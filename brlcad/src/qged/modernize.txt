qged modernization plan
=======================

Goal
----

Modernize qged's plugin and palette infrastructure into a single typed,
Qt-native, host-extensible framework.  Reusable host-neutral pieces belong in
libqtcad/include/qtcad; qged should keep only qged-specific composition choices
such as search paths, category names, menu/dock layout, and application signal
routing.

The final design should replace the legacy qged_plugin_info() C ABI,
QGED_*_TOOL_PLUGIN magic numbers, QgEdPalette's direct bu_dlopen scanning, and
QgToolPaletteElement::use_event_filter with Qt plugin metadata, typed
interfaces, deterministic plugin management, and explicit lifecycle ownership.


Current state
-------------

Completed initial libqtcad work:

* Public qtcad plugin headers exist under include/qtcad:
  QgPluginApi.h, QgPluginDescriptor.h, QgPluginContext.h,
  QgPluginInterfaces.h, QgPluginManager.h, QgPaletteController.h,
  QgPluginCommands.h, and QgToolBase.h.
* QgPluginDescriptor records plugin id, display name, host-defined category,
  icon, shortcut hint, sort key, requires-open-db/requires-view flags,
  description, vendor, and version.
* QgPluginContext is host-agnostic.  It exposes ged* and bview* accessors, an
  optional QgModel, a QgPluginNotifier for db/view/settings signals, a hostName,
  and a log sink.  It does not depend on QgEdApp.
* QgPluginInterfaces.h defines QGTCAD_PLUGIN_API_VERSION and the typed
  Q_DECLARE_INTERFACE contracts:
  IQgToolFactory, IQgPanelFactory, IQgDialogFactory, IQgCommand, and
  IQgViewEventFilter.
* QgPluginManager is implemented in libqtcad.  It scans host-supplied
  directories with QPluginLoader, reads JSON metadata before instantiation,
  supports static plugins, performs API-version checks, provides deterministic
  descriptor ordering, exposes typed factory queries, persists enable/disable
  state through QSettings, and provides diagnostics.
* QgPaletteController is implemented in libqtcad.  It connects a QgToolPalette,
  QgPluginManager, category, QgPluginContext, and active QgView; creates
  QgToolBase tools on demand; tracks the current tool; and attaches/detaches
  IQgViewEventFilter implementations.
* QgToolBase is implemented in libqtcad.  It centralizes common
  QgToolPaletteElement wiring and exposes virtual hooks such as createWidget(),
  viewEventFilter(), refresh(), onDbChanged(), onViewChanged(), and
  onSettingsChanged().
* QgPluginCommands is implemented in libqtcad for host use:
  plugins list, plugins info <id>, plugins enable <id>, plugins disable <id>,
  and plugins reload.
* The new libqtcad sources and headers are already listed in the libqtcad CMake
  build/install files.

Still using the legacy qged path:

* QgEdPalette still scans LIBEXEC/qged itself, opens each plugin with
  bu_dlopen, looks up qged_plugin_info, instantiates QgToolPaletteElement
  objects through void* function pointers, and never owns loading through
  QgPluginManager.
* src/qged/plugins/plugin.h still defines the legacy qged_plugin/qged_tool ABI
  and the QGED_CMD_PLUGIN, QGED_VC_TOOL_PLUGIN, and QGED_OC_TOOL_PLUGIN magic
  constants.
* QgEdMainWindow still constructs two QgEdPalette instances directly with
  QGED_VC_TOOL_PLUGIN and QGED_OC_TOOL_PLUGIN, and qged still treats palette
  identity as an integer interaction mode.
* QgToolPaletteElement still exposes the public use_event_filter flag.
  QgEdApp::element_selected still installs event filters by testing that flag
  and using the element controls widget as the filter object.
* All current in-tree qged plugins are still legacy shared libraries exporting
  qged_plugin_info:
  plugins/polygon, plugins/view/info, plugins/view/measure,
  plugins/view/select, plugins/view/settings, and plugins/edit/ell.
* qged does not yet create a QgPluginContext, own a QgPluginManager, wire
  qged-owned category strings such as "qged.view" and "qged.object".
* QgEdApp now owns a QgPluginNotifier, QgPluginContext, and QgPluginManager.
  The manager scans qged's libexec plugin directory for Qt plugins while the
  legacy palette loader remains active for existing qged_plugin_info plugins.
* qged now routes console `plugins ...` commands through libqtcad's
  QgPluginCommands and forwards existing db/view/settings notifications through
  QgPluginNotifier, but no in-tree qged plugins have been converted yet.
* The current qged_plugin CMake helper still creates plain shared libraries; it
  does not yet manage Qt plugin metadata JSON, plugin IIDs, AUTOMOC needs, or
  category/version metadata.
* QgEdCategories.h defines qged's two category name constants:
  QGED_CATEGORY_VIEW ("qged.view") and QGED_CATEGORY_OBJECT ("qged.object").
* QgEdMainWindow now constructs and owns QgPaletteController instances
  (vc_ctrl and oc_ctrl) for the "qged.view" and "qged.object" categories.
  Both controllers are wired to the active QgView (updated on every quad-view
  change) and populated from QgPluginManager.  Cross-palette deselection is
  now driven by working palette_element_selected and currentToolChanged
  connections rather than the previously-dead QgEdPalette::current signals.
* InteractionMode() is now derived from ActivePaletteCategory(), which returns
  the category string for the palette under the cursor.  QgModel::interaction_mode
  integers are preserved as a temporary compatibility field.
* Phase 6 retires the compatibility bridge: qged now loads tools only through
  QgPluginManager + QgPaletteController.  QgEdLegacyLoader, the qged_plugin_info
  ABI header, QGED_PLUGIN_SUFFIX scanning support, and the old QgEdApp
  element-selected event-filter hook are removed.
* QgEdPalette is now only a thin qged wrapper around QgToolPalette for
  interaction-mode bookkeeping and cross-palette visuals; all tool discovery
  and view-event-filter attachment is handled by libqtcad's typed plugin path.


Target architecture
-------------------

libqtcad owns all reusable infrastructure:

* Public API and metadata:
  QgPluginDescriptor, QgPluginContext, QgPluginNotifier,
  QGTCAD_PLUGIN_API_VERSION, and the typed IQg* interfaces.
* Plugin loading:
  QgPluginManager uses QPluginLoader/Q_PLUGIN_METADATA, supports host-supplied
  search directories, lazy instance() loading, static plugins, deterministic
  ordering, QSettings-backed enable/disable state, diagnostics, and clean
  shutdown.
* Palette-tool support:
  QgToolBase provides common tool signal wiring and QgPaletteController manages
  category-based palette population, current-tool state, and typed view event
  filter attachment.
* Diagnostics:
  QgPluginCommands provides reusable "plugins ..." subcommands for any
  libqtcad-based host with a console.

qged owns only qged-specific composition:

* QgEdApp chooses the qged plugin search path, constructs and owns a
  QgPluginContext, creates the QgPluginManager, supplies qged logging, emits
  QgPluginNotifier signals, and wires QgPluginCommands into the qged console.
* QgEdMainWindow creates qged's palettes/docks and associates them with
  qged-owned category names such as "qged.view" and "qged.object".
* qged plugins remain under src/qged/plugins but become Qt plugins implementing
  IQgToolFactory and returning QgToolBase subclasses.  Their JSON metadata
  declares qged category names, plugin ids, display labels, ordering, API
  version, and applicability flags.
* qged-specific menus, dock layout, main-window geometry, splash behavior,
  and two-palette UX stay in src/qged.  They must not move into libqtcad.


Implementation plan
-------------------

1. Harden and test the existing libqtcad base.

   * Add focused tests for QgPluginManager metadata parsing, deterministic
     ordering, enable/disable persistence, API-version rejection, diagnostic
     output, and static/shared plugin discovery where practical.
   * Add focused tests or small harness coverage for QgPaletteController and
     QgToolBase lifecycle behavior: tool creation, repeated populate(), current
     tool changes, and IQgViewEventFilter attach/detach when the active view
     changes.
   * Confirm ownership rules in code and docs: plugin-created QObject instances
     are parented to the caller/controller, plugin libraries remain loaded until
     all plugin-owned QObjects are destroyed, and global static QObjects are not
     allowed in plugin libraries.

2. Adapt qged to own the new host context and manager without changing plugin
   behavior yet.

   * Add QgEdApp-owned QgPluginNotifier, QgPluginContext, and QgPluginManager.
     Populate the context with the current ged*, current bview*, QgModel,
     qged log sink, and hostName "qged".
   * Use the qged libexec plugin directory as the manager search path, but keep
     legacy palette loading active until qged plugins are ported.
   * Wire qged's existing db/view/settings update points to QgPluginNotifier.
   * Wire QgPluginCommands into the qged console so users and tests can inspect
     discovered Qt plugins as soon as the first converted plugin exists.

3. Introduce qged category names and palette-controller composition.

   * Define qged category names centrally, initially "qged.view" and
     "qged.object".
   * Convert QgEdMainWindow to compose QgToolPalette plus QgPaletteController
     for those categories instead of constructing QgEdPalette with
     QGED_*_TOOL_PLUGIN integers.
   * Keep cross-palette deselection and current-tool behavior in controller/app
     logic rather than in plugin discovery code.
   * Replace integer palette identity assumptions in interaction-mode paths with
     explicit category/controller state.  Preserve any existing integer model
     fields only as temporary compatibility state if needed.

4. Provide a temporary legacy compatibility path.

   * While old plugins remain, either keep QgEdPalette as a legacy-only adapter
     or add a qged-side adapter that presents qged_plugin_info tools through the
     new palette/controller path.
   * The compatibility path must own dlopen handles centrally and close them at
     shutdown; it should eliminate the current repeated direct scan/load logic
     from QgEdPalette.
   * Do not put qged_plugin_info compatibility into libqtcad unless it can be
     done without exposing qged-specific ABI details in public qtcad headers.

5. Port in-tree qged plugins incrementally.

   COMPLETED: view/info, view/settings, view/select, view/measure,
   polygon/create, polygon/modify, edit/ell.

   * Updated qged_plugin CMake helper targets now add the factory header to
     qt6_wrap_cpp (moc), register the JSON metadata file in ignore_srcs, and
     record moc_*Factory.cpp_parameters in distclean.
   * All four view plugins ported to IQgToolFactory / QgToolBase:
     - QgToolBase::paletteElement() made virtual so tool subclasses can
       override it to wire extra signals (settings_changed, view_changed,
       view_updated) to element_view_changed AFTER the element is created.
     - view/info: ViewInfoFactory.h + view_info.json; CADViewModel uses
       QgPluginContext::getView() instead of casting qApp; qged_plugin_info
       export removed.
     - view/settings: ViewSettingsFactory.h + view_settings.json; paletteElement()
       override wires settings_changed → element_view_changed; qApp removed.
     - view/select: ViewSelectFactory.h + select.json; implements
       IQgViewEventFilter; attachToView/detachFromView install the CADViewSelector
       widget as the Qt event filter on the active QgView; CADViewSelector
       uses QgPluginContext::getGed() throughout instead of the gedp member.
     - view/measure: ViewMeasureFactory.h + measure.json; implements
       IQgViewEventFilter; attaches CADViewMeasure as the event filter on the
       active QgView; CADViewMeasure uses QgPluginContext::getGed().
   * Polygon subtree ported as two Qt plugins (one factory per shared library,
     matching QgPluginManager's one-id/one-instance model):
     - polygon/create: PolygonCreateFactory.h + polygon_create.json;
       QPolyCreate uses QgPluginContext::getGed()/getView(); tool wrapper
       implements IQgViewEventFilter and installs the widget as the active
       QgView event filter.
     - polygon/modify: PolygonModifyFactory.h + polygon_modify.json;
       QPolyMod uses QgPluginContext::getGed()/getView(); tool wrapper
       implements IQgViewEventFilter, refresh() also repopulates the polygon
       list, and paletteElement() preserves the legacy element_unhide ->
       mod_names_reset wiring.
   * edit/ell: EditEllFactory.h + ell.json; QEll uses
     QgPluginContext::getGed()/getView(); tool wrapper implements
     IQgViewEventFilter and installs the widget as the active QgView
     event filter.
   * Phase 5 tool ports complete; next phase is legacy ABI/palette
     retirement.

   * Update the qged_plugin CMake helper, or add a new helper, to build Qt
     plugins with the needed AUTOMOC/wrap_cpp handling, Q_PLUGIN_METADATA JSON
     files, correct IID, API version metadata, and libqtcad linkage.
   * All remaining in-tree tool subtrees for this phase are now ported to
     IQgToolFactory plus QgToolBase in their existing source subtrees.
   * Give every factory a stable id, category, displayName, sortKey, iconName,
     requiresOpenDb/requiresView flags, and description.
   * Replace ad-hoc signal wiring in each *_tool.cpp with QgToolBase hooks.
   * Replace each use_event_filter assignment with a QObject implementing
     IQgViewEventFilter returned by QgToolBase::viewEventFilter().
   * Delete each plugin's qged_plugin_info export when that plugin is converted.

6. Retire the legacy ABI and palette implementation.

   COMPLETED:
   * Removed the QgEdLegacyLoader compatibility path and QGED_PLUGIN_SUFFIX
     filename scanning from qged startup/build wiring.
   * Deleted src/qged/plugins/plugin.h and the QGED_*_TOOL_PLUGIN /
     qged_plugin / qged_tool legacy ABI definitions.
   * Removed QgToolPaletteElement::use_event_filter and the corresponding
     QgEdApp::element_selected event-filter handling.
   * Legacy palette-priority ordering is gone with the loader; tool ordering is
     now the typed-plugin path's deterministic (sortKey, id) ordering.

7. Add the non-tool extension points qged needs.

   INITIAL SLICE COMPLETED:
   * qged now owns three additional host categories: qged.panel,
     qged.dialog, and qged.command.
   * QgEdMainWindow composes IQgPanelFactory plugins into the existing
     View->Panels dock menu and IQgDialogFactory plugins into a qged-owned
     Tools->Dialogs menu.
   * QgEdApp dispatches IQgCommand plugins from the qged console before
     falling back to libged commands.
   * Added small in-tree sample non-tool plugins:
     - org.brlcad.qged.panel.host_status
     - org.brlcad.qged.dialog.host_status
     - org.brlcad.qged.command.host_status
     These exercise the non-tool interfaces with a shared host-status
     widget/summary implementation driven by QgPluginContext.
   * Future slices can now port real qged panels/dialogs/commands onto this
     host-owned composition path without adding qged-specific assumptions to
     libqtcad.

8. Validate reuse outside qged.

   INITIAL SLICE COMPLETED:
   * Added test_qtcad_plugin_reuse: a standalone test binary in
     src/libqtcad/tests/ that links only against libqtcad, libbu,
     and Qt6::Widgets — deliberately NOT libged or qged.
   * The test constructs a QgPluginManager + QgPluginContext with
     NULL ged/bview accessors (simulating a minimal, non-qged host)
     and scans the Phase 7 qged extension plugin directory at runtime.
   * Exercises verified:
     - Empty-directory manager: zero plugins, no crash.
     - Plugin discovery: all three Phase 7 host_status plugins found.
     - diagnosticSummary() contains expected plugin IDs.
     - Category-filtered descriptor queries for qged.panel,
       qged.dialog, and qged.command.
     - IQgCommand::run() invoked with NULL ged/bview → null-safe
       output ("No database open", "No active view").
     - IQgCommand alias dispatch (qged_status) works correctly.
     - --refresh flag in host_status command is handled safely even
       when viewAccessor is null.
     - IQgPanelFactory::create() returns a valid QDockWidget without
       a main window.
     - IQgDialogFactory::create() returns a valid QDialog without a
       parent window.
     - Enable/disable round-trip via QgPluginManager succeeds for
       known IDs and correctly returns false for unknown IDs.
     - diagnosticInfo() returns non-empty text for known IDs.
     - unloadAll() + rescan() cycle works without crash.
   * Future work: wire a minimal libqtcad-based tool (or archer-qt6
     when that path is ready) to a separate QgPluginManager with its
     own search directory and host categories to prove full end-to-end
     reuse with a real ged instance.


Validation expectations
-----------------------

For every implementation slice, configure and build with Qt enabled.  At
minimum, build the touched qtcad/qged targets and relevant plugin targets:
libqtcad, qged, qged_plugins, and any converted plugin library.  When touching
display-manager or view-event-filter behavior, also build dm-qtgl, dm-swrast,
qged, and the relevant libqtcad/qged tests.  Run available tests that exercise
the touched area, especially any new QgPluginManager/QgPaletteController tests
and existing qged/libqtcad headless tests.

Do not build or validate the non-Qt path for this work unless specifically
requested; this modernization is Qt-specific and should use
BRLCAD_ENABLE_QT=ON.
