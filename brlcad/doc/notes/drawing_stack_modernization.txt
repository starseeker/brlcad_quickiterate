Drawing Stack Modernization — Current Audit
===========================================

Purpose
-------
This note is the current-state summary for the BRL-CAD drawing-stack
modernization work.  It replaces the older session-by-session log with the
information future sessions actually need:

1. what the high-level plan in the repository root file `draw_migration_plan.rtf` (outside the brlcad/ subtree) was trying to do,
2. what the code in brlcad/ implements now,
3. which parts of that plan are truly done versus only approximated,
4. what work still remains, and
5. the recommended order for the remaining work.

Read this first, then read the RTF plan file `draw_migration_plan.rtf` at the
repository root (outside the brlcad/ subtree) if you need the original
end-state rationale.

--------------------------

At minimum, any code change in this area should keep the Qt drawing targets
healthy: libqtcad, dm-qtgl, dm-swrast, qged, and archer.

High-level status
-----------------
The important headline is:

- The legacy display_list implementation is no longer the canonical drawn-set
  data structure.
- The canonical drawn set is now a BSG tree rooted at
  ged_drawable::gd_draw_root.
- Phase 7's internal refactor steps (1-15) have been implemented.
- Pure tree manipulation logic has been moved into libbsg.
- However, the full end-state sketched in draw_migration_plan.rtf is NOT 100%
  realized yet.

Against the RTF plan, the project is here:

- Layer A: effectively done.
- Layer B: mostly done; B4 is still only partial.
- Layer C: internally far along, but the public libged API and some user-facing
  semantics still expose legacy ideas.
- User-facing redesign items R1/R2 from the RTF are not fully finished.
- The "backend-style vs adapter-style" end-state decision is still open.

What has been accomplished already
----------------------------------
Condensed history:

- Phases 0-4 established the supporting infrastructure:
  - dbi_state was modernized away from raw LMDB usage.
  - typed observer/state machinery was added.
  - libbsg was vendored into brlcad/.
  - libdm gained BSG traversal support.
  - views gained bsg_root plumbing.

- Phase 5 migrated the major front ends to the BSG-capable path:
  - MGED, Archer, and rtwizard were moved onto the modern draw path.
  - The renderer could already consume a BSG scene root instead of the old
    display-list walk.

- Phase 6.5 removed the standalone legacy display_list implementation:
  - src/libged/display_list.c was deleted.
  - Its helpers were folded into libged and then progressively replaced.
  - The internal linked-list-only model stopped being the renderer's source of
    truth.

- Phase 7 turned the GED draw set into a real BSG tree:
  - gd_draw_root became the canonical per-GED draw root.
  - nested per-component groups replaced top-level path-string splitting.
  - DFS snapshot navigation replaced cross-list next/prev traversal.
  - overlays moved to a dedicated _overlays tree branch using
    BSG_PAYLOAD_OVERLAY instead of RT_DIR_PHONY_ADDR in the drawing path.
  - freeing/revision helpers were pushed down into libbsg.
  - bsg_view_obj.c was renamed to bsg_ged_draw.c because it is now primarily
    GED-layer wrapper code.

Current architecture and why it looks this way
----------------------------------------------
These are the important present-day design facts future sessions should not
have to rediscover:

1. The canonical drawn set is a BSG tree.
   - Root: ged_drawable::gd_draw_root
   - Root type: BSG_NODE_GROUP
   - Real drawn geometry lives under child groups/shapes of that root.
   - The renderer consumes this tree via libdm's BSG traversal path.
   - The old gd_headDisplay chain is no longer the authoritative store.

2. gv_draw_root exists so the active bview can point directly at the GED-owned
   draw tree.
   - This is the A3 realization from the RTF.
   - The important consequence is that gv_objs is now derived/supporting state,
     not the canonical structure to mutate first.

3. libbsg now owns the pure tree logic.
   - src/libbsg/draw_set.c: draw-tree structure/free/revision helpers,
     nested-subpath erase helper, child-group utilities.
   - src/libbsg/overlay.c: overlay-group helpers.
   - include/bsg/draw_ctx.h: per-root context used by libbsg helpers to reach
     the owner's revision counter and free-object pool without needing a
     struct ged *.

4. bsg_draw_ctx in root->s_i_data is intentional.
   - It exists so libbsg code can bump gd_draw_rev and recycle nodes without
     carrying GED-private state through every helper.
   - Do not remove it unless there is a better owner/context handoff design.

5. _overlays plus BSG_PAYLOAD_OVERLAY is the replacement for the old phony-db
   overlay trick.
   - In the drawing path, overlays are now scene nodes, not fake database
     objects.
   - This was necessary to stop RT_DIR_PHONY_ADDR from being load-bearing in
     draw-tree bookkeeping.

6. gd_illum_solid is still present on purpose.
   - The current code uses it to make the common "clear current illumination"
     path O(1).
   - This is not the full sensor-driven end-state described in the RTF, but it
     is the reason the current implementation behaves acceptably.

7. s_color_rev / gd_mater_rev implement lazy material recoloring (B4, now active).
   - gd_mater_rev is initialized to 1; freshly-drawn shapes have s_color_rev=0
     and are always stale on the first sweep.
   - Callers that change the material table must call bsg_view_obj_bump_mater_rev()
     to advance gd_mater_rev.  color_from_soltab does NOT bump it.
   - color_from_soltab stamps each visited shape with the current gd_mater_rev.
     A second call without an intervening bump is a full no-op for all shapes.
   - Do not add a second cache token; the existing mechanism is complete.

Audit against the RTF plan
--------------------------
The RTF plan is still the best description of the desired end-state.  The table
below records how closely the current code matches it.

Layer A — make the drawn set a BSG tree
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
A1  DONE
    The canonical drawn set is gd_draw_root, not a list of display_list nodes.

A2  MOSTLY DONE
    The storage model is now tree-based, and nested groups represent path
    structure.  However, the public API is still path-string-oriented
    (lookup_or_add_path, erase_by_path, erase_all_paths, group_path,
    group_set_path).

A3  DONE
    gv_draw_root lets the view point at the GED-owned draw tree directly.

A4  DONE
    next/prev-style navigation is now implemented via a DFS snapshot and integer
    indexing rather than linked-list pointer chasing.

Layer B — re-express each legacy role in BSG terms
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
B1  MOSTLY DONE
    Drawn paths are realized as BSG groups/shapes and append_solid_to_group now
    builds nested groups correctly.  The public API is still legacy-shaped, so
    the internal model is ahead of the surface API.

B2  DONE
    Nested erase is tree-based.  The old split-heavy implementation has been
    retired.  All public compatibility knobs have been removed:
      - `allow_split` removed from `bsg_view_obj_erase_by_path`.
      - `skip_first` removed from `bsg_view_obj_erase_all_paths`.
      - `skip_first` removed from `bsg_view_obj_erase_by_name`; killrefs now
        explicitly iterates path components via bsg_view_obj_foreach_group to
        identify paths where the target name is a non-root component.

B3  DONE (Phase 9.1)
    Overlay filtering uses BSG_PAYLOAD_OVERLAY rather than phony directory
    addresses, AND aggregate bbox is now cached at every interior group node:
      - bv_scene_obj gains an s_bbox_cached flag; for GROUP/ROOT nodes,
        bmin/bmax holds the cached aggregate bbox of the subtree's
        non-overlay descendants when s_bbox_cached==1.
      - libbsg/draw_set.c implements bsg_subtree_bbox() (recursive,
        cache-respecting) and bsg_node_bbox_invalidate() (walk-up that
        clears all ancestors' caches, stopping at the first already-dirty
        node so the amortised cost is O(depth-of-clean-prefix)).
      - All structural mutation chokepoints invalidate the parent chain:
        bsg_group_ensure_child, bsg_free_children_recursive, bsg_free_group,
        bsg_erase_nested_subpath cases (a) and (b), bsg_view_obj_append_solid_to_group
        and the _sg_invent overlay-attach path.
      - _sg_bounding_sph in libged is now a one-line delegate to
        bsg_subtree_bbox; the per-frame full-tree _sph_solid_cb walk is gone.
      - pflag (include-overlays) bypasses the cache and does a full walk;
        this is the rare path used only by `view bounds -p` style queries.
      - Test [12] in src/libged/tests/draw/bsg_view_obj.cpp verifies cold/warm
        cache, cache-vs-walk parity, and erase-invalidates-cache.

B4  DONE
    The lazy-color mechanism is now fully active:
      - gd_mater_rev initializes to 1; freshly-drawn shapes have s_color_rev=0,
        so they are always stale on the first color_from_soltab call.
      - bsg_view_obj_bump_mater_rev() is the only caller that advances
        gd_mater_rev; it must be called before any material-change event.
      - bsg_view_obj_color_from_soltab() stamps s_color_rev on each shape it
        colors but does NOT advance gd_mater_rev itself.
      - bump is wired at: color.c (ged_color_core + edcolor import path),
        mater.cpp (mater_shader), edmater.c (post-rmater flow).
      - Tests verify: skip fires on repeated calls without a material change;
        a bump followed by a sweep recolors stale shapes; counter stays stable.

B5  MOSTLY DONE
    The common clear-illumination path is O(1) through gd_illum_solid, which
    captures most of the practical win the RTF wanted.  The exact sensor-driven
    design described in the RTF is not what is currently implemented.

B6  DONE
    Overlays now live under _overlays and no longer require fake db entries in
    the drawing path.  User-facing reporting is now also cleaned up: who.c
    uses bsg_view_obj_group_is_phony() instead of db_lookup()+phony-addr
    comparison (R1 cleanup).

B7  DONE
    Structural revision tracking is now a cheap counter (gd_draw_rev) rather
    than a content hash walk.

B8  DONE
    MGED's "advance illuminated solid" logic uses DFS snapshot order and integer
    indexing rather than cross-list traversal.

B9  DONE
    Visitor-style traversal is in place and callers were migrated off the old
    nested group/solid iteration pattern.

Layer C — cleanly lift the redesign into libbsg / delete the old shape
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
C1  MOSTLY DONE
    Pure tree mechanics have been moved into libbsg.  The remaining gap is that
    the libged public API still exposes legacy drawing-stack vocabulary and
    compatibility shims.

C2  BY DESIGN STAYS ABOVE LIBBSG
    The plan explicitly says policy belongs in libged/mged.  This is still the
    right split.

C3  PARTIAL
    A large amount of legacy machinery is gone, and bsg_view_obj.c has already
    been renamed to bsg_ged_draw.c.  However, the end-state sketched in the RTF
    is stricter than the current tree:
      - bsg_view_obj_invent still exists as a public GED entry point.
      - include/ged/bsg_view_obj.h still presents a legacy compatibility API.
      - several callers still reason in terms of "phony" groups rather than a
        first-class overlay policy.

RTF user-facing redesign items
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
R1  DONE
    The internal draw tree no longer masquerades overlays as database objects.
    who.c routes the real/overlay decision through bsg_view_obj_group_is_phony()
    rather than db_lookup() + RT_DIR_PHONY_ADDR.  The helpers in
    src/libged/ged_util.cpp (who_argv_cb and rt_write_draw_cb) likewise use
    bsg_view_obj_group_is_phony() instead of direct dp->d_addr comparisons.

R2  DONE
    All public erase compatibility knobs have been removed:
      - `allow_split` removed from `bsg_view_obj_erase_by_path`.
      - `skip_first` removed from `bsg_view_obj_erase_all_paths`.
      - `skip_first` removed from `bsg_view_obj_erase_by_name`; the one caller
        (killrefs.c) that needed "match interior components only" now expresses
        that logic explicitly via bsg_view_obj_foreach_group + path component
        iteration, without requiring any API-level flag.

What remains to do
------------------
The structural modernization is complete.  The items below are the genuine open
questions that could still be addressed, but none are blocking normal use.

1. Larger end-state architecture questions (optional, low urgency).
   - bbox/sensor invalidation improvements: DONE in Phase 9.1 (cached
     aggregate bbox + invalidation-on-mutation, see B3 above),
   - fuller sensorization of highlight state (B5 residual),
   - backend-style vs adapter-style libbsg/Obol integration.

2. Path-string-centric entry points.
   bsg_view_obj_lookup_or_add_path, bsg_view_obj_group_path,
   bsg_view_obj_group_set_path still accept/return raw path strings.  If a
   future caller wants to drive the draw tree directly in BSG terms rather
   than path strings, those entry points would need counterparts that accept
   a struct db_full_path * or a tree-node handle.  This is not currently
   blocking anything.

Phase 8: BSG render contract
----------------------------
This phase corrected a set of regressions caused by the BSG render path not
re-creating behaviour that the legacy dm_draw_head_dl() / dm_drawSolid() had
encoded implicitly.  The fixes restore parity without reintroducing
display_list, dm_draw_head_dl, or the gv_objs ptbls.

Status: DONE for items 1-6 below (the user-visible regressions); items 7-8
are verification / documentation polish.

The "BSG render contract" — what dm_draw_objs / bsg_view_traverse /
dm_draw_scene_obj must do per frame, contractually:

  C1. Two-pass transparency render.
      When dm_get_transparency(dmp) is true, dm_draw_objs() walks the BSG
      tree TWICE:
        - Pass 1 — opaque (s_os->transparency >= 1.0), depth writes on.
        - dm_set_depth_mask(dmp, 0).
        - Pass 2 — transparent (s_os->transparency != 1.0), depth writes off.
        - dm_set_depth_mask(dmp, 1).
      Implemented in libdm/view.c via _dm_draw_scene_obj_internal's
      transparency_pass argument; dm_draw_objs supplies pass=1 then pass=2.

  C2. Per-frame s_flag = DOWN reset.
      At the very top of every frame dm_draw_objs() runs
        bsg_visit(root, BSG_NODE_SHAPE, _reset_drawn_cb, NULL)
      so that dm_draw_scene_obj's "set s_flag = UP on successful draw" then
      gives an accurate "what was drawn this frame" set for downstream
      consumers (dozoom dm_ndrawn count, usepen.c illumination).

  C3. Geometry default colour.
      When sp->s_old.s_cflag is set (i.e. "use the dm's default wireframe
      colour"), _dm_draw_scene_obj_internal calls
      dm_get_geometry_default_color(dmp) instead of using s->s_color.
      MGED pushes its current geometry_default_color[] into the dm via
      dm_set_geometry_default_color() at the top of refresh.

  C4. Line-width fallback.
      _dm_draw_scene_obj_internal honours s->s_os->s_line_width when nonzero,
      otherwise falls back to dm_get_linewidth(dmp).  This makes
      `set linewidth` propagate through to shaded-triangle edges.

  C5. mv_dlist (compiled GL display list) replay.
      gl_draw_obj() in dm-gl_lod.cpp falls through to
      dm_draw_dlist(dmp, sp->s_dlist) when dm_get_displaylist(dmp) is true
      and sp->s_dlist is nonzero (and s_dmode != 4 so hidden-line still uses
      the explicit vlist path).  This restores the legacy fast path.

  C6. Bound-flag size-based culling.
      _dm_draw_scene_obj_internal skips BSG_NODE_SHAPE objects when
        dm_get_bound_flag(dmp) && !s->s_displayobj
        && (s->s_size * v->gv_isize) < 0.001
      restoring `dm set bound` and pan-time small-geometry skipping.

  C7. Transform-stack matrix restore.
      _bsg_view_traverse_impl carries an accumulated cur_mat through
      recursion.  When entering a BSG_NODE_TRANSFORM child, it pushes
      cur_mat * s->s_mat as the new cur_mat; on return it restores the
      outer cur_mat.  When _dm_draw_scene_obj_internal swaps in
      v->gv_edit_mat for an s_iflag == UP child, it restores cur_mat
      afterwards (rather than always falling back to gv_model2view).
      This is latent today (libged emits no BSG_NODE_TRANSFORM children)
      but is the contract any future transform-emitting consumer relies on.

Note on libtclcad/view/draw.c:
The Archer-style go_draw / go_draw_dlist still use their own inline two-pass
walk via go_draw_solid because go_draw_solid implements the per-path
edited_paths matrix swap (an Archer-specific feature that dm_draw_scene_obj
does not currently replicate).  The contract above applies to dm_draw_objs;
the libtclcad path independently implements C1 and inherits C2 once the
draw tree is reset by dm_draw_objs.  A future cleanup may migrate Archer's
edited_paths to per-scene-obj attribution and let go_draw delegate to
dm_draw_objs(gdvp, NULL, NULL).

Recommended execution order
---------------------------
The core API cleanup is complete (R2 done).  If continuing this work in code,
address the optional items above as needed.

What not to redo
----------------
Future sessions should NOT spend time rediscovering or re-arguing these points:

- Do not reintroduce display_list/gd_headDisplay as the canonical drawn-set
  structure.
- Do not reintroduce RT_DIR_PHONY_ADDR into the drawing path for overlays.
- Do not replace s_color_rev with a different lazy-color token; the existing
  mechanism is done and working.
- Do not make color_from_soltab bump gd_mater_rev itself; the bump must come
  from material-change event callers only.
- Do not move GED/MGED policy decisions down into libbsg just to make the lower
  layer "look complete".
- Do not treat the rename to bsg_ged_draw.c as cosmetic; it marks the real split
  between pure tree logic (libbsg) and GED policy/wrappers (libged).

Bottom line
-----------
The modernization effort is complete.  The draw tree is BSG-native, all public
legacy compatibility knobs have been removed, and the codebase is clean.

- B1/B2/B4/B5/B6/B7/B8/B9, R1, R2 are all done.
- All three erase-by-name/path/all-paths API knobs (allow_split, skip_first×2)
  have been removed.  killrefs now expresses its "interior component" erase
  semantics explicitly via bsg_view_obj_foreach_group + path walking.
- ged_util.cpp uses bsg_view_obj_group_is_phony() for overlay filtering.
- No boolean compatibility flags remain in the public bsg_view_obj_* API.

Phase 9: lazy bbox + sensorized highlight (in progress)
-------------------------------------------------------
Phase 9 addresses the two residuals (B3, B5) and lays the substrate that
Phase 11 (renderer-backend contract) will reuse.

Step 9.1 -- DONE -- cached aggregate bbox with dirty propagation.
  See the B3 entry above for full details.  This step alone makes the per-
  query cost of `view bounds` / `autoview` / `zoom-extents` O(touched-since-
  last-query) instead of O(all-shapes-ever-drawn), and provides the first
  concrete demonstration of "dirty propagated up the parent chain on every
  structural mutation chokepoint" -- the same pattern the highlight sensor
  in Step 9.3 and the backend hooks in Phase 11 will reuse.

Step 9.2 -- DONE -- replace per-frame `s_flag = DOWN` reset with a
  `gv_frame_rev` generation counter.
    - bview gains `uint64_t gv_frame_rev`, bumped at the top of
      dm_draw_objs() (libdm/view.c).
    - bv_scene_obj gains `uint64_t s_drawn_rev`; the renderer stamps
      `s->s_drawn_rev = v->gv_frame_rev` after a successful paint
      (replacing the old `s->s_flag = UP`).
    - "drawn this frame" is now `sp->s_drawn_rev == v->gv_frame_rev`;
      MGED's _mged_count_drawn_cb walks once per frame and tests
      against the stamp instead of relying on a global s_flag reset.
    - s_flag retains its original "persistent visibility" semantics
      (DOWN means the object is hidden); the renderer no longer writes
      to s_flag at all.  This finally separates the two roles that
      were conflated on s_flag.
    - Test [13] in src/libged/tests/draw/bsg_view_obj.cpp verifies
      that stamping shapes at frame rev N then bumping to N+1 produces
      a "drawn this frame" count of zero on N+1 with no full-tree
      reset.

Step 9.3 -- DONE -- re-express gd_illum_solid as a NodeSensor.
    - ged_drawable gains `bsg_node *gd_illum_sensor` (live NodeSensor
      handle while a solid is illuminated; NULL otherwise) and
      `uint64_t gd_illum_rev` (highlight-state revision counter).
    - _sg_set_illum() now manages sensor lifecycle: tear down the
      previous sensor on every transition, register a fresh one on
      the new target via bsg_node_sensor_create(), and bump
      gd_illum_rev.
    - The sensor's callback bumps gd_illum_rev on every
      bsg_node_field_touch() targeting the illuminated solid, so that
      external observers can detect highlight-state changes purely by
      polling bsg_view_obj_illum_rev() — no need to subscribe to the
      sensor or poll gd_illum_solid identity.
    - bsg_view_obj_set_iflag(DOWN) and bsg_view_obj_zap() also tear
      down the sensor and bump gd_illum_rev.
    - ged_bv_illum_free_cb() now also tears down the sensor when the
      illuminated solid itself is freed (avoiding a dangling target
      pointer in the registry).
    - Public API: bsg_view_obj_illum_rev() returns the current value
      of the counter.
    - The manually-maintained gd_illum_solid cache stays as the O(1)
      identity-lookup path used by set_iflag(DOWN); the NodeSensor is
      strictly the lazy-notification side.
    - Test [14] in src/libged/tests/draw/bsg_view_obj.cpp covers
      transitions, field-touch on the illum solid, field-touch on a
      different solid (no bump), and clean teardown after set_illum
      (NULL).

Phases 10-13: deferred follow-ons
---------------------------------
Phase 10 -- DONE (full migration) -- public libged API cleanup.
  - Header rename: include/ged/bsg_view_obj.h -> include/ged/bsg_ged_draw.h
    (canonical), with a thin compatibility shim left at the old name
    that simply forwards via #include "ged/bsg_ged_draw.h" so out-of-
    tree callers do not break.
  - New db_full_path-keyed entry points added in libged/bsg_ged_draw.c
    parallel to the path-string variants:
      bsg_view_obj_lookup_or_add_dbpath(gedp, dfp)
      bsg_view_obj_erase_by_dbpath(gedp, dfp)
      bsg_view_obj_erase_all_dbpaths(gedp, dfp)
      bsg_view_obj_group_dbpath(gedp, group, out)
      bsg_view_obj_group_set_dbpath(group, dfp)
    The dbpath wrappers call the file-private _sg_* helpers directly
    (not the deprecated public path-string wrappers) so libged itself
    stays warning-clean.
  - In-tree caller migration complete.  Every call to the four
    mutation/lookup APIs that take a path-string now constructs a
    db_full_path at the call site (parse via db_string_to_path against
    gedp->dbip, free via db_free_full_path) and calls the dbpath
    variant.  Migrated files: draw/draw.c, draw/bigE.c, erase/erase.c,
    gdiff/gdiff.c, killrefs/killrefs.c, nirt/nirt.cpp, remove/remove.c,
    rtcheck/rtcheck.c, move/move.c, move_all/move_all.c.  The
    move/move_all rename callbacks gained a `struct ged *gedp`
    back-pointer in their userdata structs so the rename callback can
    parse the new path.
  - __attribute__((deprecated("use the db_full_path-keyed variant")))
    is now applied to the four migrated path-string declarations
    (bsg_view_obj_lookup_or_add_path, bsg_view_obj_erase_by_path,
    bsg_view_obj_erase_all_paths, bsg_view_obj_group_set_path) via a
    BSG_DEPRECATED_PATH_STR macro guarded for GCC/Clang.  Out-of-tree
    callers will see a compile-time warning at every remaining call
    site.  bsg_view_obj_group_path and bsg_view_obj_erase_by_name are
    intentionally NOT deprecated: the former is the natural string
    accessor for the (still-string) internal s_name storage, and the
    latter is component-name-keyed rather than path-keyed.
  - The bsg_view_obj.cpp test still exercises the path-string
    variants in section [1] (NULL-arg safety) and section [15]
    (dbpath-keyed entries).  Section [1] wraps the deprecated calls
    in `#pragma GCC diagnostic push/ignored "-Wdeprecated-declarations"
    /pop` so the regression test for the deprecated contract still
    compiles under -Werror.
  - Phase 11 (renderer-backend contract) and Phase 12/13 will land
    in separate PRs.

Phase 11 -- renderer-backend contract.  Replace ad-hoc fields (s_dlist,
  s_obol_node, ...) on bv_scene_obj with one (slot, dtor) pair plus a
  proper `struct bsg_backend` functab in include/dm/backend.h.  dm-gl,
  dm-swrast, and the qgedobol experiment all become proper backends; the
  Phase 8 render contract moves into a shared "default GL frame loop"
  helper that backends opt into.  This is the architectural answer to
  "adapter vs direct adoption of Obol" -- adapter, but with a real
  interface, not the current "widen bv_scene_obj" pattern.

Phase 12 -- decide the long-term default backend by benchmark.  Concrete
  rule: dm-obol becomes default if it wins on >=2 of {redraw latency,
  peak RSS, code volume saved} and is no worse than 10% on the others;
  otherwise dm-gl stays default and Obol ships as opt-in.

Phase 13 -- retire the deprecated-during-Phase-10 path-string APIs,
  remove s_dlist/s_obol_node/etc. from bv_scene_obj, remove gd_illum_solid
  (subsumed by the Phase 9.3 sensor), remove the Phase-8 frame-reset pass
  (subsumed by the Phase 9.2 generation counter).

Explicit non-goals (recorded so future sessions don't re-litigate):
  * Do not put SoNode* directly on bv_scene_obj.
  * Do not vendor Obol underneath libbsg; libbsg stays the canonical,
    C-friendly tree.
  * Do not move highlight/illum policy down into libbsg; the sensor is
    the data primitive but "what counts as illuminated" stays in libged.
  * Do not reintroduce a per-frame full-tree reset pass once gv_frame_rev
    lands.
  * Do not let backend-specific fields creep back onto bv_scene_obj once
    the generic backend slot exists.
