Drawing Stack Modernization — Current State and Next Work
=========================================================

Purpose
-------
This note is the handoff document for continuing BRL-CAD drawing-stack
modernization work.  It replaces older session-by-session notes with a concise
summary of:

1. the current architecture,
2. the phases that are already complete,
3. the remaining follow-on work, and
4. the constraints future sessions should preserve.

The original long-form end-state rationale lives in the repository-root
`draw_migration_plan.rtf` file (outside the `brlcad/` subtree).  Read that file
only when the rationale behind a design choice is needed; this file should be
sufficient for implementation sessions.

Build and validation reminders
------------------------------
Drawing-stack work is Qt-sensitive.  Always configure BRL-CAD with Qt enabled
unless intentionally testing a non-Qt path.

Recommended configure shape from the repository root:

  cmake -S brlcad -B brlcad_build \
    -DBRLCAD_EXT_DIR=bext_output \
    -DCMAKE_PREFIX_PATH=bext_output/install \
    -DBRLCAD_EXTRADOCS=OFF \
    -DBRLCAD_ENABLE_STEP=OFF \
    -DBRLCAD_ENABLE_GDAL=OFF \
    -DBRLCAD_ENABLE_OPENGL=ON \
    -DBRLCAD_ENABLE_QT=ON

For code changes in this area, at minimum keep the Qt drawing targets healthy:
`libqtcad`, `dm-qtgl`, `dm-swrast`, `qged`, and `archer`.  For focused BSG/GED
changes, also run the draw tests in `src/libged/tests/draw`, especially
`bsg_view_obj.cpp`.

Current headline
----------------
The structural modernization is complete.  The canonical drawn set is now a BSG
tree rooted at `ged_drawable::gd_draw_root`; the old `display_list` model is no
longer the authoritative draw-store.  The active view points at that tree through
`bview::gv_draw_root`, and libdm renders it via BSG traversal.

Completed work includes:

- Phases 0-7: BSG infrastructure, front-end migration, removal of the standalone
  legacy display-list implementation, and conversion of the GED draw set into a
  real tree.
- Phase 8: render-contract parity with the old display-list path.
- Phase 9: cached aggregate bounding boxes, per-frame draw generation stamps,
  and sensorized illumination revision tracking.
- Phase 10: public API cleanup through db_full_path-keyed entry points and
  deprecation of the remaining path-string mutation/lookup APIs.
- Phase 11: renderer-backend contract; backends attach per-shape state via a
  single generic slot on `bv_scene_obj` (`s_backend`) and a libdm-side ops
  table (`struct dm_backend_ops`).  The GL family stores its compiled display
  list, list-compile mode, and stale flag on a private
  `gl_backend_handle` (libdm/dm-gl_lod.cpp) attached through that slot.
- Phase 13 (partial): the Phase 10 deprecated path-string mutation/lookup
  entry points (`bsg_view_obj_lookup_or_add_path`, `bsg_view_obj_erase_by_path`,
  `bsg_view_obj_erase_all_paths`, `bsg_view_obj_group_set_path`) and the
  `BSG_DEPRECATED_PATH_STR` machinery have been removed.  The
  `include/ged/bsg_view_obj.h` compatibility shim has been retired and all
  in-tree includes now use the canonical `include/ged/bsg_ged_draw.h`
  directly.  Phase 13 C is also complete: the BV_DEPRECATED `s_dlist`,
  `s_dlist_mode`, `s_dlist_stale`, and `s_dlist_free_callback` fields on
  `bv_scene_obj` have been removed (storage migrated to
  `gl_backend_handle` on `s_backend->handle`), all libbv/libbsg legacy
  compat firing has been dropped, and the libged
  `ged_create_vlist_scene_obj_callback` / `ged_destroy_vlist_callback` /
  `vlist_ctx` fields plus their `ged_create_vlist_solid_cb` /
  `ged_destroy_vlist_cb` wrappers have been retired.  `gd_illum_solid`
  has been collapsed (Phase 13 cleanup): the registered NodeSensor on
  `gd_illum_sensor` is now the single source of truth for the illuminated
  -solid identity, read back via `bsg_sensor_target()`.

The remaining work is not to make the current tree viable; it is follow-on
architecture cleanup and backend selection:

- Phase 12: benchmark-based default backend decision.
- Phase 13 (remaining): retirement of the BV_DEPRECATED `s_dlist*` fields
  and the legacy display-list pre-generation paths in MGED + tclcad.

Current architecture
--------------------
Future sessions should start from these present-day facts.

1. The BSG tree is the canonical drawn set.
   - Owner/root: `ged_drawable::gd_draw_root`.
   - View pointer: `bview::gv_draw_root`.
   - Real drawn geometry is represented by nested BSG group/shape nodes.
   - `gd_headDisplay` and old display-list concepts are compatibility/supporting
     state only; do not make them authoritative again.

2. Tree mechanics belong in libbsg.
   - `src/libbsg/draw_set.c` owns pure tree operations: child-group utilities,
     recursive free, revision/cache invalidation, nested-subpath erase, and
     aggregate bbox calculation.
   - `src/libbsg/overlay.c` owns overlay-group helpers.
   - `include/bsg/draw_ctx.h` defines the per-root context that lets libbsg bump
     owner revisions and recycle nodes without taking a `struct ged *`.

3. GED policy remains above libbsg.
   - `src/libged/bsg_ged_draw.c` is the GED-facing wrapper/policy layer.
   - Keep user-facing policy decisions (draw command semantics, overlay policy,
     illumination policy, material-table policy) out of libbsg unless they become
     pure tree primitives.

4. Overlays are scene nodes, not fake database objects.
   - The `_overlays` branch and `BSG_PAYLOAD_OVERLAY` replaced drawing-path use
     of `RT_DIR_PHONY_ADDR`.
   - Public reporting helpers should ask the BSG/GED helpers whether a group is
     an overlay/phony group; they should not infer this from database addresses.

5. Material recoloring is lazy and revision based.
   - `ged_drawable::gd_mater_rev` starts at 1.
   - `bv_scene_obj::s_color_rev` starts at 0 for freshly drawn shapes.
   - Material-changing commands call `bsg_view_obj_bump_mater_rev()`.
   - `bsg_view_obj_color_from_soltab()` stamps shapes with the current material
     revision but does not bump the revision itself.

6. Frame-drawn status is generation based.
   - `bview::gv_frame_rev` is bumped at the start of `dm_draw_objs()`.
   - Successfully drawn shapes are stamped with `bv_scene_obj::s_drawn_rev`.
   - "Drawn this frame" means `s_drawn_rev == gv_frame_rev`.
   - Do not restore a per-frame full-tree `s_flag = DOWN` reset.

7. Illumination identity lives on the NodeSensor; revisions notify lazily.
   - `ged_drawable::gd_illum_sensor` carries the libbsg NodeSensor watching
     the currently illuminated node; `bsg_sensor_target()` reads back the
     identity.  When no solid is illuminated, the field is NULL.
   - `ged_drawable::gd_illum_rev` is bumped on every transition (set/clear/
     replace) and on every `bsg_node_field_touch` against the illuminated
     node (delivered through the sensor callback).
   - `bsg_view_obj_illum_rev()` exposes the revision counter; observers
     cache a snapshot and compare to detect "highlight may have changed".

8. Aggregate bounding boxes are cached on group nodes.
   - `bv_scene_obj::s_bbox_cached` marks valid aggregate bbox data for group/root
     nodes.
   - Structural mutation chokepoints invalidate caches up the parent chain.
   - `bsg_subtree_bbox()` is the cache-aware tree query.

Completed phase summary
-----------------------

Phase 0-4: supporting infrastructure — DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
These phases established the pieces needed to move the drawing stack to BSG:
modernized state handling, observer/state machinery, vendored libbsg, libdm BSG
traversal support, and `bview` draw-root plumbing.

Phase 5: front-end migration — DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
MGED, Archer, and related front ends were moved onto the BSG-capable drawing
path.  Renderers could consume a BSG scene root rather than walking the old
display-list chain.

Phase 6.5: legacy display-list removal — DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
The standalone `src/libged/display_list.c` implementation was removed.  Its
remaining helpers were folded into the newer layers and then progressively
replaced or narrowed to compatibility roles.

Phase 7: GED draw set as a real BSG tree — DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
The GED draw tree became the canonical data structure:

- `gd_draw_root` is the per-GED root.
- Nested component groups represent drawn paths.
- DFS snapshots replaced linked-list next/previous traversal.
- Overlay nodes moved under `_overlays` with `BSG_PAYLOAD_OVERLAY`.
- Pure tree free/revision helpers moved to libbsg.
- `bsg_view_obj.c` was renamed to `bsg_ged_draw.c` to reflect the split between
  libbsg tree mechanics and libged policy/wrappers.

Phase 8: BSG render contract — DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
The BSG render path now preserves behaviour formerly encoded by
`dm_draw_head_dl()` / `dm_drawSolid()`:

- transparent drawing uses an opaque pass and a transparent pass;
- geometry default color is obtained from the display manager;
- line-width fallback uses the display manager linewidth when the object line
  width is unset;
- OpenGL display-list replay still happens when enabled and valid;
- bound-flag small-object culling is preserved;
- transform traversal carries and restores the accumulated matrix correctly.

The per-frame `s_flag = DOWN` reset that originally belonged to this contract was
superseded by Phase 9.2's generation counter.

Phase 9: lazy bbox and sensorized highlight — DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Phase 9 closed the main residual performance/state gaps.

Step 9.1: cached aggregate bbox
  - Group/root nodes cache aggregate bbox data with `s_bbox_cached`.
  - `bsg_subtree_bbox()` performs cache-aware bbox queries.
  - `bsg_node_bbox_invalidate()` clears ancestor caches when tree structure
    changes.
  - Structural mutation chokepoints invalidate caches.
  - `_sg_bounding_sph()` delegates to libbsg instead of doing a full-tree walk.

Step 9.2: drawn-this-frame generation counter
  - `bview::gv_frame_rev` is advanced per frame.
  - `bv_scene_obj::s_drawn_rev` records successful drawing in that frame.
  - MGED's drawn-count logic tests the generation stamp rather than relying on a
    destructive reset pass.

Step 9.3: illumination NodeSensor
  - `gd_illum_sensor` tracks the currently illuminated node and is the
    single source of truth for the highlight identity (Phase 13:
    `gd_illum_solid` cache field collapsed; `bsg_sensor_target()` reads
    the identity off the sensor handle).
  - Sensor callbacks bump `gd_illum_rev` when the illuminated node changes.
  - `set_iflag(DOWN)`, `zap`, free callbacks, and illumination transitions tear
    the sensor down cleanly.
  - `bsg_view_obj_illum_rev()` exposes the revision to observers.

Phase 10: public libged API cleanup — DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
The canonical GED drawing header is `include/ged/bsg_ged_draw.h`.  The
former compatibility shim `include/ged/bsg_view_obj.h` was retired in
Phase 13; all in-tree includes now reference `bsg_ged_draw.h` directly.

The db_full_path-keyed APIs are:

- `bsg_view_obj_lookup_or_add_dbpath()`
- `bsg_view_obj_erase_by_dbpath()`
- `bsg_view_obj_erase_all_dbpaths()`
- `bsg_view_obj_group_dbpath()`
- `bsg_view_obj_group_set_dbpath()`

All in-tree callers of the path-keyed mutation/lookup APIs construct a
`db_full_path` at the call site and use the dbpath variants.  The Phase 10
deprecated path-string variants
(`bsg_view_obj_lookup_or_add_path`, `_erase_by_path`, `_erase_all_paths`,
`_group_set_path`) and the `BSG_DEPRECATED_PATH_STR` macro were removed in
Phase 13.

`bsg_view_obj_group_path()` and `bsg_view_obj_erase_by_name()` are intentionally
not deprecated: the former is the natural string accessor for current internal
name storage, and the latter is component-name-keyed rather than path-keyed.

Audit against the original RTF layers
-------------------------------------

Layer A — make the drawn set a BSG tree: DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
A1 canonical BSG drawn set, A2 tree-based storage, A3 view draw-root plumbing,
and A4 DFS snapshot navigation are complete.  The remaining path-string APIs are
compatibility surfaces, not evidence that storage is still list-based.

Layer B — re-express legacy roles in BSG terms: DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
B1/B2/B3/B4/B5/B6/B7/B8/B9 are complete.  B5 keeps illumination identity on the
libbsg NodeSensor (`gd_illum_sensor`, read back via `bsg_sensor_target()`)
together with `gd_illum_rev` for lazy change notification — no separate cache
field.

Layer C — lift tree mechanics into libbsg/delete old shape: MOSTLY DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Pure tree mechanics are in libbsg and GED policy is above it.  The remaining
cleanup belongs to Phase 13: backend-specific per-shape fields and deprecated
path-string entry points.

User-facing redesign items R1/R2: DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
R1 overlay reporting no longer depends on fake database addresses.  R2 erase
compatibility knobs have been removed; callers now express any special matching
semantics explicitly.

Remaining work
--------------

Phase 11: renderer-backend contract: DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Goal: replace ad-hoc backend fields on `bv_scene_obj` with a real backend
contract.  Per-shape backend state now attaches via one generic slot on the
scene object plus a libdm-side ops table; new backends can hook in without
widening `bv_scene_obj`.

What landed:

- `struct bv_obj_backend` (include/bv/defines.h) holds a per-shape
  `{type_tag, handle, free, invalidate}` descriptor; `bv_scene_obj::s_backend`
  is the single backend-owned slot.  `BV_BACKEND_*` tags identify the owning
  backend so cross-backend handle confusion can be caught.
- `bv_scene_obj_release_backend()` and `bv_scene_obj_invalidate_backend()`
  (include/bv/util.h, src/libbv/util.cpp) are the canonical entry points for
  releasing/invalidating per-shape backend resources.  They fire the new
  contract callbacks and, for compatibility, also fire the legacy
  `s_dlist_free_callback` and set `s_dlist_stale=1`.
- `struct dm_backend_ops` and the `dm_backend_draw_obj` /
  `dm_backend_invalidate_obj` / `dm_backend_release_obj` dispatch wrappers
  (include/dm.h, src/libdm/dm-generic.c) are the display-manager-side
  counterpart.  Each `dm_impl` carries a `dm_backend_ops` pointer.
- `gl_backend_ops` (src/libdm/dm-gl_lod.cpp) provides the GL implementation
  (`gl_draw_obj` and the `gl_backend_handle` lifecycle).  Every GL plugin
  (dm-gl, dm-qtgl, dm-glx, dm-wgl, dm-swrast) wires it into its `dm_impl`
  template.
- All in-tree fire points for per-shape backend release/invalidate
  (libbv/util.cpp, libbv/view_sets.cpp, libbv/lod.cpp, libbsg/draw_set.c,
  libbsg/overlay.c) route through the helpers, so ops registered on
  `s_backend` fire automatically.
- Per-shape GL state (compiled display list, list-compile mode, stale flag)
  now lives on `struct gl_backend_handle` attached via `s_backend->handle`
  in libdm-private code.  The Phase 11 transitional BV_DEPRECATED fields
  (`s_dlist`, `s_dlist_mode`, `s_dlist_stale`, `s_dlist_free_callback`)
  have been removed in Phase 13 C; see the Phase 13 section below.
- Section [16] in `src/libged/tests/draw/bsg_view_obj.cpp` exercises the
  contract with a stub backend and verifies the new ops fire on
  release/invalidate.

Phase 12: default backend decision
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Goal: choose the long-term default renderer backend by measurement rather than
preference.

Use dm-obol as the default only if it wins on at least two of these dimensions
and is no worse than 10% on the others:

- redraw latency,
- peak RSS,
- code volume/maintenance burden saved.

Otherwise keep dm-gl as the default and ship Obol as opt-in.

Phase B short-term hot-fix: BViewState writes through BSG — DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Background: `bsg_scene_root_sync` (libbsg/scene_graph.cpp) preferred
`v->gv_draw_root` whenever it was non-NULL, but `ged_open` eagerly
initialised that pointer via `bsg_view_obj_ensure_root`.  The
`ged_draw2_core` / `BViewState::redraw` path placed every freshly
allocated scene object into `bv_view_objs(v, BV_DB_OBJS)` rather than
under `gd_draw_root`, so `dm_draw_objs` could not see them and
`ged_test_drawing_*` produced nearly-blank images.

Fix landed in two parts (both committed together):

1. `bsg_scene_root_sync` now also folds the view-only ptbls
   (`BV_VIEW_OBJS` and `BV_VIEW_OBJS|BV_LOCAL_OBJS`) into the render
   root when `gv_draw_root` is set.  `BV_DB_OBJS` is intentionally NOT
   folded in — that ptbl is a derived/compat index for db-objects, and
   `gd_draw_root` remains the single source of truth for db-objects
   rendering.  This fixes the 2-D view-only / faceplate / polygon
   tests.

2. `BViewState::scene_obj()` and the redraw "swap"/invalidation paths
   now route freshly-allocated leaves through
   `bsg_view_obj_lookup_or_add_dbpath` +
   `bsg_view_obj_append_solid_to_group` so each leaf becomes a
   `BSG_NODE_SHAPE` under `gd_draw_root` with intermediate sub-group
   nodes for combs.  `BViewState`'s `s_map[phash][mode] → bv_scene_obj`
   semantics are preserved (only the *storage location* of the leaf
   moved from the flat ptbl to a tree leaf); per-mode multiplicity is
   naturally supported because each (path, mode) leaf is a distinct
   shape child under the same comb group.

   `BViewState::erase_hpath()` and `BViewState::clear()` (and the
   redraw replacement path) detach the leaf from its BSG parent before
   `bv_obj_put`.  `clear()` deliberately does NOT call
   `bsg_view_obj_zap()` — `gd_draw_root` is shared across views, and
   zapping it would tear down leaves owned by other views, leading to
   a double-free at the subsequent `bv_clear()`.

The new helpers `_bview_state_attach_leaf` and `_bview_state_detach_leaf`
in `dbi_state.cpp` are static; they are the only seam where draw2's
BViewState path interacts with the BSG tree.

Validation: `ged_test_drawing_basic` passes its wireframe (mode 0),
polygon, label, axes, and faceplate cases (previously all blank);
`ged_test_drawing_faceplate` passes; the existing `ged_test_bsg_view_obj`,
`ged_test_bsg_parity`, and `ged_test_mged_shaded_mode_bsg` still pass.
Remaining open issues (not addressed by this short-term fix): shaded
mode 1 with LoD disabled, hidden lines (mode 4), and the LoD test
suite still produce blank/incorrect images for some scenarios; these
likely require additional work in the adaptive-plot / view-object
(`bv_obj_for_view`) integration with the BSG render contract and are
candidates for the long-term Phase B/C/D follow-on described in the
parent plan.

Long-term unification plan (Phases A–E)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
End state: a single drawing stack that retains qged's sophistication.
Phasing builds incrementally on the Phase B short-term fix above
without re-architecting either side.

Phase A — DbiState becomes the optional path/state front-end.

  Keep `DbiState` exactly as it is, owned via `gedp->dbi_state`.
  MGED/Archer continue to leave `dbi_state == NULL` and call
  `bsg_view_obj_*` mutation helpers directly, exactly as today.

  qged keeps using `DbiState` for its tree-of-paths model,
  change-driven invalidation, color/matrix/region-id caches, and
  selection sets, all of which MGED does not need and which BSG cannot
  host without losing its tree-mechanics-only role.

  Eliminate `gedp->new_cmd_forms` as a global "old vs new" toggle.
  Replace its callers with a presence test on `gedp->dbi_state`:
  commands that need state (`draw`, `erase`, `who`, `redraw`,
  `tops`, …) call into `BViewState` when `dbi_state` is non-NULL,
  otherwise fall through to direct BSG mutations.  This removes the
  second-generation/first-generation user-visible split.

  Status: DONE.  All 36 runtime `if (gedp->new_cmd_forms)` checks
  across `libged/{who,erase,zap,view,select,lod,overlay,brep,gdiff,
  rt,rtcheck,gqa,lint,bot,check,draw,nirt,joint,garbage_collect,
  ged_util}` have been rewritten as `if (gedp->dbi_state)` presence
  tests.  The `new_cmd_forms` field is retained narrowly in
  `open/open.cpp` and `ged.cpp` purely as the opendb-time hint that
  controls allocation of `gedp->dbi_state` / `gedp->ged_lod`; it is
  no longer a runtime mode toggle.  The gsh `--new-cmds` CLI flag
  still flips this opendb-time hint; tests that allocate `dbi_state`
  directly already get the new code paths automatically.  All 105
  drawing-stack regression tests that passed before Phase A still
  pass after; no new failures.

Phase B — BViewState writes through BSG.

  Land step 2 of the short-term fix as the canonical implementation
  of `BViewState`: it computes paths, owns hash maps, drives
  change/refresh policy, but every scene object it touches is a node
  under `gd_draw_root` accessed through `bsg_ged_draw.h`.  The flat
  ptbl in `BV_DB_OBJS` stops being a draw store for any code path.
  A few sites that read it (`bv_view_objs(v, BV_DB_OBJS)`) are
  migrated to BSG traversals (`bsg_visit(BSG_NODE_SHAPE, ...)`),
  matching the migration already done in MGED's
  `_mged_count_drawn_cb` (Phase 9.2).

  Status: short-term hot-fix landed (above section).  Full migration
  of `bv_view_objs(v, BV_DB_OBJS)` readers to BSG traversal still
  pending.

Phase C — push the stack-1 helpers needed by qged into the shared API.

  The handful of behaviours that exist on stack 1 but not in
  `BViewState` today (overlay groups, illumination NodeSensor, lazy
  material rev, frame generation counter) are already implemented in
  `libbsg`/`bsg_ged_draw.c`.  After Phase B these are immediately
  available to qged because everything is in the BSG tree.  Wire
  qged's selection/illumination paths to read them via
  `bsg_sensor_target` / `bsg_view_obj_illum_rev` / `gv_frame_rev`
  rather than the old gv_objs-based paths it still has in places.

Phase D — extract a thin `dbi_state` interface.

  Move `DbiState`/`BViewState` either fully into `libged` (it is
  already there) or split the parts qged-only code touches into a
  public header so MGED/Archer can opt-in to specific facilities
  (e.g. fast `is_drawn(path)` checks driven from cached path
  hashes).  This is the only step where MGED/Archer would gain
  anything from `dbi_state`; until then they ignore it.

Phase E — finish retiring the BSG legacy fallback.

  With Phase B in place, the gv_objs branches of
  `bsg_scene_root_sync` and `dm_draw_objs` are unused for all GED
  consumers.  Step 1 of the short-term fix (folding view-only ptbls
  in) becomes the only fallback responsibility.  At this point,
  investigate whether the scene graph can also handle the objects
  currently being held by gv_objs — if the tree can handle
  everything without needing a sync step, `bsg_scene_root_sync`
  either simplifies or can be eliminated completely.

Constraints to respect during the work
......................................

- `dbi_state` machinery in qged is sophisticated and has no MGED
  equivalent.  Do not push it down into `libbsg`.  It remains a
  `libged`-side path/state layer that *targets* the BSG tree.
- The Phase 8 render contract (two-pass transparency, geometry
  default color, line-width fallback, dlist replay,
  `gv_frame_rev`/`s_drawn_rev`) is correct and already paid for;
  the unified path must keep using it.  No new render contract.
- The dbpath-keyed APIs (`bsg_view_obj_lookup_or_add_dbpath` and
  friends, Phase 10) are the only mutation surface the merged stack
  should call.  Do not reintroduce path-string variants.
- Preserve `BViewState::s_map[phash][mode] → bv_scene_obj`
  semantics: a path can be drawn in multiple modes simultaneously.
  The BSG tree already supports this naturally because mode is per
  shape leaf.

Phase 13: retire transitional APIs and fields — IN PROGRESS
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Goal: remove compatibility surfaces once Phase 11 provides the replacement
architecture and downstream callers have had a migration window.

Done:

- The Phase 10 deprecated path-string mutation/lookup APIs
  (`bsg_view_obj_lookup_or_add_path`, `bsg_view_obj_erase_by_path`,
  `bsg_view_obj_erase_all_paths`, `bsg_view_obj_group_set_path`) and the
  `BSG_DEPRECATED_PATH_STR` deprecation macro have been deleted from
  `include/ged/bsg_ged_draw.h` and `src/libged/bsg_ged_draw.c`.  The
  db_full_path-keyed wrappers continue to forward to the file-private
  path-string helpers (`_sg_add_path`, `_sg_erase_path`, `_sg_erase_all_paths`)
  inside `bsg_ged_draw.c`.
- The `include/ged/bsg_view_obj.h` compatibility shim has been removed;
  `include/ged/bsg_ged_draw.h` is the only canonical header.  All in-tree
  includes (libged, libtclcad, mged, and the bsg_view_obj test) now
  reference the canonical header directly.

- Phase 13 C — bv_scene_obj field migration: the BV_DEPRECATED `s_dlist`,
  `s_dlist_mode`, `s_dlist_stale`, and `s_dlist_free_callback` fields on
  `bv_scene_obj` have been removed.  GL-backend per-shape state now lives
  on `struct gl_backend_handle` (libdm/dm-gl_lod.cpp) attached via
  `s_backend->handle`; the handle is allocated lazily the first time the
  backend caches a list and torn down through the dm_backend_ops
  release/invalidate callbacks.  All in-tree callers that touched the
  legacy fields (libged `draw/draw.c`, `bsg_ged_draw.c`,
  `set_transparency`, mged `dodraw.c`) have been migrated, the legacy
  `s_dlist_free_callback` compat firing in `src/libbv/{util.cpp,
  view_sets.cpp,lod.cpp}` and `src/libbsg/{draw_set.c,overlay.c}` has been
  removed, and the libged `ged_create_vlist_scene_obj_callback` /
  `ged_destroy_vlist_callback` / `vlist_ctx` fields on `struct ged` plus
  the `ged_create_vlist_solid_cb` / `ged_destroy_vlist_cb` wrappers (and
  associated callback typedefs and counter fields) have been retired.
  Test [16] in `src/libged/tests/draw/bsg_view_obj.cpp` was updated to
  exercise only the Phase 11 contract.

Remaining candidates:

- (none — `gd_illum_solid` was collapsed in Phase 13.  The libbsg
  NodeSensor on `gd_illum_sensor` is the single source of truth: identity
  is read via `bsg_sensor_target((bsg_node *)gdp->gd_illum_sensor)`.  The
  public `bsg_view_obj_set_illum()` setter (used by MGED's selection
  path), `bsg_view_obj_get_illum()` accessor (used by libged callers),
  and `bsg_view_obj_illum_rev()` revision counter all derive from the
  same handle and need no separate cache field.)

Do not remove these prematurely: each remaining item has at least one
in-tree caller that must be migrated first.

What not to redo
----------------
Do not spend future sessions rediscovering or re-litigating these settled points:

- Do not reintroduce `display_list`/`gd_headDisplay` as the canonical drawn-set
  structure.
- Do not use `RT_DIR_PHONY_ADDR` as drawing-path overlay state.
- Do not move GED/MGED policy down into libbsg just to make libbsg look more
  complete.
- Do not replace the existing lazy-color revision token with a second mechanism.
- Do not make `bsg_view_obj_color_from_soltab()` bump `gd_mater_rev`; material
  change callers must bump it.
- Do not restore per-frame full-tree `s_flag` resets; use `gv_frame_rev` and
  `s_drawn_rev`.
- Do not add backend-specific fields to `bv_scene_obj`; attach state via the
  `s_backend` slot and a `dm_backend_ops` table (Phase 11 contract).  In
  particular, do not add new direct callers of the `BV_DEPRECATED`
  `s_dlist_*` fields — they will be removed in Phase 13.
- Do not remove the deprecated path-string APIs before the planned Phase 13
  compatibility cleanup.

Quick checklist for future sessions
-----------------------------------
Before making a drawing-stack change:

1. Identify whether the change is GED policy, pure tree mechanics, display-manager
   rendering, or backend-resource management.
2. Put GED policy in libged, pure tree mechanics in libbsg, and rendering/backend
   concerns in libdm.
3. Preserve the revision/caching contracts: `gd_draw_rev`, `gd_mater_rev`,
   `gv_frame_rev`, `s_drawn_rev`, `s_bbox_cached`, and `gd_illum_rev`.
4. Add or update focused draw tests when behaviour changes.
5. Keep Qt-enabled drawing targets buildable.
