BRL-CAD Drawing Stack Modernization Guide
==========================================

Purpose
-------
This is the single active guide for BRL-CAD's drawing modernization effort.  It
replaces the older planning/work-log files `bsg_modernize.txt`, `bview2bsg.txt`,
`draw_migration_plan.rtf`, `drawing_modernization.txt`, and the previous version
of this note.

The goal is to make BRL-CAD drawing an OpenInventor/Obol-style scene graph: GED,
MGED, Archer, qged, libqtcad, Tcl, and display managers should describe drawing
state as typed BSG scene data, while renderers consume prepared render requests
through a backend contract.  Existing native GL/swrast behavior must remain
compatible while laying the foundation for an Obol backend.

Vision and non-negotiables
--------------------------
1. `libbsg` is the canonical drawing/scene-graph library.  The old `libbv` layer
   is gone; do not reintroduce `bv_*`, `BV_*`, display-list, or raw solid-list
   concepts in new code.
2. Producers create typed payloads and draw intents.  Commands should not encode
   draw state by mutating child tables, names, or former `bsg_node` fields.
3. Consumers use BSG actions and accessors.  Picking, selection, snapping,
   measuring, exporting, reporting, HUD drawing, overlays, LoD, and rendering
   must flow through the BSG APIs rather than ad hoc node traversal.
4. `libdm` owns display-manager operations and backend primitive drawing only;
   BSG owns traversal policy, render phases, payload dispatch, appearance
   resolution, HUD/overlay ordering, and backend cache invalidation rules.
5. Obol is an adapter/backend, not a bypass.  Do not add Obol-specific shortcuts
   that skip BSG payloads, draw intents, render items, camera/light state, or
   selection/pick/snap records.
6. Preserve current capabilities while modernizing internals: native GL,
   swrast, qtgl, MGED/Tcl, qged, offscreen tests, plot/export/report commands,
   edit previews, HUD/faceplate features, and legacy-visible command behavior
   must continue to work.

Current state summary
---------------------
The foundational modernization is substantially complete:

* `libbv` has been folded into `libbsg` and removed as an independent source-tree
  dependency.  Public callers use `bsg/` headers and `bsg_*` APIs.
* BSG now has first-class APIs for nodes, identity/revisions, typed payloads,
  materials, appearance, draw intents, actions, selection, pick/snap/measure,
  HUD, overlays, camera, lights, render settings, render items, and backend
  adapters.
* `bsg_node` is opaque in public headers; the layout lives in
  `include/bsg/node_private.h` for internal in-tree users that have not yet been
  fully converted to accessor-only code.
* Render traversal is centered in `bsg_render_request_execute()`.  `libdm/view.c`
  drives BSG render requests and backend callbacks instead of owning the scene
  traversal model.
* qged/libqtcad and editor work have moved away from custom draw callbacks
  toward BSG scene nodes and live payloads.
* Legacy `BV_*` aliases are isolated in `include/bsg/legacy_compat.h` behind
  `BSG_ENABLE_LEGACY_BV_ALIASES`; new code should not include or depend on them.

Modernized architecture
-----------------------

### Node and identity model
A BSG scene is a tree of typed nodes: roots, groups, transforms, shapes, LoD
nodes, view scopes, HUD nodes, and overlays.  Identity, source path, source
directory, instance path, revision, parent/child structure, visibility,
transform, bounds, and user/internal payload references are accessed through BSG
APIs.  Public headers forward-declare `struct bsg_node`; direct layout access is
an implementation detail and should continue to shrink.

### Typed payload model
Geometry and annotations live in typed payloads rather than raw `s_vlist` or
`draw_data` fields.  Current payload vocabulary includes VLIST, HUD text,
line-set, polygon, mesh, CSG, BRep, image, framebuffer, grid, axes, live-source
editor payloads, and annotation/measurement-style payloads.  Payloads provide
revision, bounds, export, pick, snap, measure, realization, and backend-prepare
hooks as applicable.  Unsupported operations must return documented sentinel
results, not NULL surprises or implicit fallbacks.

### Draw intents
GED-style draw commands attach semantic draw intents to scene nodes.  Reporting,
export, erase, revalidate, simplify, and visible-target collection should query
intent actions instead of reconstructing state from node names or child tables.
Database changes should flow through draw-intent revalidation, and overlays with
source-change lifecycles should auto-remove through the same event path.

### Selection, picking, snapping, and measurement
Selection is represented by `bsg_selection`, and highlighting is derived
appearance.  Pick/snap/measurement APIs return typed records with semantic paths,
primitive/subelement identifiers, hit distance, and view information.  UI code
should not use raw `bsg_node *` tables as the primary selection currency except
inside explicitly documented compatibility helpers.

### HUD and overlays
Faceplate/HUD output is represented as BSG view-scope/HUD nodes and rendered via
render requests.  Overlays carry role, lifecycle, owner, ordering, and optional
source-path metadata.  Tools should refresh their visuals by owner/role APIs,
not by name conventions or renderer-specific custom callbacks.

### Render pipeline
`bsg_render_request_execute()` owns traversal, filtering, render phases,
transparent ordering, HUD/overlay ordering, payload dispatch, appearance
resolution, LoD participation, render settings, and backend-adapter calls.
Backends receive `bsg_render_item` objects with resolved appearance and payload
information.  Backend caches must invalidate from typed reason masks: payload,
appearance, transform, render-mode, or all.

### Camera, lights, and render settings
Camera snapshots, camera-node binding, lights, and render settings are BSG state.
Saved views, multi-view qged layouts, native GL/swrast drawing, and the future
Obol adapter should all consume the same camera/light/settings APIs.

Completed work
--------------

### 1. libbv to libbsg migration
Completed.  Former `libbv` functionality was merged into `libbsg`; callers were
renamed from `bv_*`/`BV_*`/`bview`/`bv_scene_obj` vocabulary to BSG vocabulary;
`bsg.h` and `bsg/` headers are canonical.

### 2. BSG API foundation
Completed.  Generic node APIs, identity/revision helpers, material/appearance
split, typed payloads, action framework, selection, camera, lights, render
request, and backend-adapter APIs are present and wired into the libbsg build.

### 3. Consumer modernization
Substantially complete.  libged, libdm, libqtcad, qged, MGED, and Tcl paths have
been migrated through many BSG accessors/actions.  Recent work removed direct
custom draw callbacks, routed qged/MGED selection through `bsg_selection`, moved
HUD rendering through BSG render requests, and introduced live payloads for edit
previews.

### 4. Public API cleanup
Completed for the public boundary.  `bsg_node` is opaque to public headers,
legacy aliases are isolated in `bsg/legacy_compat.h`, and surviving internal
layout users must include `bsg/node_private.h` explicitly.

### 5. Documentation support
`brlcad/doc/bsg_vocabulary.md` and `brlcad/doc/bsg_drawing_api.md` describe the
vocabulary and API.  This file is now the active roadmap/status document.

Remaining work
--------------
The next sessions should focus on finishing the foundations cleanly before
starting or merging an Obol backend.

### R1. Run and fix the full validation matrix
This is the highest-priority remaining task.  Several planning notes recorded
successful targeted builds/tests in earlier sessions, but the full Qt-enabled
matrix still needs to be run on the current tree and any regressions fixed.

Required build targets:

* `libbsg`, `libdm`, `dm-qtgl`, `dm-swrast`, `dm-glx`, `libged`, `libqtcad`,
  `qged`, `mged`, `archer`

Required core tests:

* `libbsg_node`, `libbsg_identity`, `libbsg_material_appearance`,
  `libbsg_action`, `libbsg_selection`, `libbsg_camera`, `libbsg_light`,
  `libbsg_render`, `libbsg_lod_node`, `libbsg_scene_graph`, `libbsg_pick`,
  `libbsg_hud`, `libbsg_render_item`, `libbsg_payload_typed`,
  `libbsg_payload_typed_live_source`, `libbsg_snap_action`, `libbsg_measure`,
  `libbsg_appearance_resolve`, `libbsg_backend_adapter`

Required drawing/application tests:

* `ged_test_bsg_view_obj`, `ged_test_drawing_basic`,
  `ged_test_drawing_faceplate`, `ged_test_drawing_lod`,
  `ged_test_lod_crossrun`, `ged_test_bsg_parity`, `ged_test_bsg_quad_parity`,
  `ged_test_tcl_adornment_bsg`, `ged_test_view_independent`,
  `ged_test_view_command`, `ged_test_qged_swrast`, `ged_test_mged_bsg`,
  `ged_test_mged_shaded_mode_bsg`, `ged_test_rtwizard_bsg`,
  `ged_test_selection_parity`, `ged_test_snap_parity`,
  `ged_test_measure_parity`

If Qt configure fails due to xcb support, install the missing `libxcb-*` dev
packages, clear the Qt/CMake configure cache, reconfigure, and rerun the matrix.

### R2. Finish payload hook coverage and consumer breadth
Do a payload-by-payload audit and make sure every payload type has the complete
builder/accessor/hook contract expected by render, export, pick, snap, measure,
and backend preparation.  In particular, verify labels, axes, grid, polygons,
measurement annotations, selection rectangles/rubber bands, framebuffer,
LoD/mesh, CSG, BRep, and database draw producers.

Acceptance checks:

* `BSG_ADD_VLIST`/`BSG_FREE_VLIST` direct node writes appear only in payload
  builder or primitive-plotter internals.
* No libged/libqtcad/qged/libtclcad consumer reads former node fields such as
  `s_vlist`, `s_i_data`, or `draw_data` directly.
* `libbsg_payload_typed` has per-type tests for create/mutate/revision/bounds/
  pick/snap/export/backend-prepare behavior.

### R3. Complete draw-intent command migration
Continue migrating every command that needs drawn object sets to draw-intent
actions: `gqa`, `loadview`, `plot`, `ps`, `png`, `bot_dump`, `rt`, `rtcheck`,
`rtarea`, `nirt`, `rtwizard`, MGED report/export helpers, erase/zap/draw refresh,
and any remaining `who`/`how` variants.

Acceptance checks:

* Commands obtain targets with `bsg_draw_intent_collect_visible`,
  `bsg_draw_intent_collect_for_export`, `bsg_draw_intent_match`, or erase/
  revalidate helpers.
* No command infers intent from child-table traversal or node naming.
* Database object changes trigger draw-intent revalidation for all active draw
  roots.

### R4. Finish overlay role/lifecycle adoption
The overlay API exists; continue using it everywhere instead of names or custom
renderer callbacks.  Confirm all expected roles are present and used:

* model, screen, xray, edit handle, measure, selection rubber band, snap guide,
  command result, diagnostic, Tcl adornment, polygon edit, sketch edit, user
  annotation

Acceptance checks:

* qged/libqtcad measurement, selection, polygon, edit, and live-preview overlays
  all carry typed role/lifecycle metadata.
* libtclcad and MGED adornments use overlay nodes with owner/lifecycle metadata.
* `bsg_overlay_query_by_role()` can enumerate each role without string matching.

### R5. Audit backend parity and cache invalidation
Now that render items and resolved appearance are in place, audit native backends
for remaining policy decisions that should live in BSG.  Focus on `dm-glx`,
`dm-swrast`, `dm-qtgl`, plot/ps/txt paths, framebuffer paths, LoD update timing,
transparency sorting, default geometry color, highlight appearance, HUD ordering,
and cache invalidation.

Acceptance checks:

* Backends draw prepared render items and do not recompute material, selection,
  transparency, overlay ordering, or traversal policy.
* Cache invalidation reacts to payload, appearance, transform, and render-mode
  revision changes through `bsg_backend_adapter` reason masks.
* Native backend output remains parity-compatible before Obol is introduced.

### R6. Convert remaining internal layout users to accessor APIs
Public API opacity is done, but many in-tree sources still include
`bsg/node_private.h` for direct layout access.  Continue reducing those users
where doing so improves API clarity.  Do not add accessors just to keep legacy
patterns alive; add semantic helpers only when they express stable scene-graph
concepts.

Priorities:

* libged draw/report/export code
* libdm render consumption
* qged/libqtcad plugin and filter code
* MGED/Tcl edit, illuminate, and adornment paths
* libbsg internals where direct field access hides a reusable semantic operation

### R7. Remove scheduled compatibility bridges when safe
`include/bsg/legacy_compat.h` is a temporary bridge for remaining compatibility
aliases.  Keep it isolated and documented until the native backend parity and
Obol adapter work demonstrate that no caller requires the legacy names.

Acceptance checks before removal:

* No production code includes `bsg/legacy_compat.h` for new behavior.
* `BSG_ENABLE_LEGACY_BV_ALIASES=0` builds the drawing stack.
* `brlcad/doc/bsg_vocabulary.md` and `brlcad/doc/bsg_drawing_api.md` list any
  remaining scheduled removals with clear owner/status.

### R8. Implement Obol as a backend adapter
Only start this after R1-R7 are either complete or explicitly triaged.  The Obol
backend should implement the documented backend-adapter callbacks, payload
prepare hooks, camera/light/settings consumption, pick mapping, and cache
lifecycle.  It must not introduce a separate scene traversal path or its own
parallel draw-state model.

Acceptance checks:

* Obol consumes `bsg_render_item` plus payload/backend-prepare data.
* Obol camera, pick, instance-path, material/appearance, overlay, HUD, and LoD
  behavior match native BSG rendering.
* Native GL/swrast/qtgl tests continue to pass.
* Adding Obol requires no changes to GED command intent, payload builder,
  selection, snap, measure, HUD, or traversal policy APIs.

Definition of done
------------------
The drawing modernization is complete when:

1. The full validation matrix passes on a Qt-enabled build.
2. All drawing producers use typed BSG payloads and draw intents.
3. All drawing consumers use payload/action/accessor APIs rather than raw node
   layout or display-list assumptions.
4. Selection, pick, snap, measurement, HUD, overlays, camera, lights, render
   settings, appearance resolution, and backend cache lifecycle are all first-
   class BSG concepts with tests.
5. Native backends and Obol all consume the same `bsg_render_request` /
   `bsg_backend_adapter` contract.
6. Compatibility shims are either removed or explicitly isolated with documented
   removal criteria.
7. Existing BRL-CAD drawing behavior remains compatible for users while the
   internal architecture is scene-graph based.

Guidance for future agents
--------------------------
* Start by checking this file, `brlcad/doc/bsg_drawing_api.md`, and
  `brlcad/doc/bsg_vocabulary.md`.
* For implementation work, make one small migration slice at a time and run the
  narrow relevant build/tests immediately, then the full validation matrix before
  claiming a phase complete.
* Do not solve short-term UI or backend needs by adding new raw node fields,
  custom draw callbacks, display-list traversal, or Obol-only bypasses.
* Prefer semantic BSG APIs: payload builders, draw-intent actions,
  selection/pick/snap/measure records, overlay owner/role/lifecycle operations,
  render requests, render settings, resolved appearance, and backend-adapter
  callbacks.
