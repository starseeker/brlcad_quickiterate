needed.  This file should stay focused on current status and the remaining

Executive summary
-----------------
The major architectural merge is done:
- DB-backed drawing now uses the BSG tree as the canonical scene model.
- LoD is a first-class BSG concept, not a per-view duplicate-subtree hack.
- View-only objects also now live on the BSG side, and the `view obj`
  command surface has been consolidated around the unified grammar.
- Public typed view-object APIs exist for creation, lookup, iteration, and
  simple mutations.

Why that matters:
- qged, libged, and libdm now mostly agree on one scene representation.
- Most rendering invariants now live in one traversal path instead of split
  across BSG and ad hoc ptbl walks.
- New work should build on typed view-object APIs and BSG view-scope nodes,
  not on legacy `BV_VIEW_OBJS` storage assumptions.

What still blocks a fully finished stack:
- Tcl/Archer/mged refresh still has a legacy render path outside
  `dm_draw_objs`.
- Some producers/readers still rely on compatibility paths instead of the
  typed API.
- Final deprecation removal and backend-default policy are intentionally
  deferred until the migration work is complete.


Completed baseline (do not reopen without a new design reason)
--------------------------------------------------------------
1. Canonical drawn scene ownership is unified on the BSG tree.
   - `ged_drawable::gd_draw_root` is authoritative.
   - `bview::gv_draw_root` / `bview::bsg_root` are handles to that tree.
   - qged `dbi_state` is front-end state, not a parallel scene store.

2. LoD redesign is complete.
   - `BSG_NODE_LOD` is the adaptive representation.
   - Per-view LoD state is cursor-based, not duplicate-subtree based.
   - `dm_draw_objs` owns the single LoD update site.

3. View-only object unification Phases V1-V8 are complete.
   - `BSG_NODE_VIEW_SCOPE` exists and drives shared vs per-view visibility.
   - libdm renders from the BSG tree only.
   - `view independent` is structural via a private view scope.
   - `view obj` uses the unified `create/remove/list/info/set` grammar.
   - Public APIs exist: `bv_view_obj_create`, typed wrappers,
     `bv_view_obj_find`, `bv_view_obj_visit`, and typed setters.

4. Typed setter groundwork is complete.
   - `bv_view_obj_set_color`
   - `bv_view_obj_set_line_width`
   - `bv_view_obj_set_visible`

5. Early typed-API adoption work is already in place.
   - libbv readers in `hash.c` and `snap.c` use typed iteration.
   - libged readers in `view.c`, `draw2.cpp`, `rtcheck2.cpp`, and
     `polygons.c` use typed iteration / lookup where the change was
     mechanical.

6. Per-view-variant / highlight model (Phase H) is complete.
   - Design decision: LOCAL VIEW_SCOPE overlays (no new node type).
   - `bsg_view_obj_illum_by_name` public API added.
   - `QEll` migrated onto `bv_view_obj_overlay_create` and the new
     illumination API.


Still-open work, in priority order
==================================

Priority 1 — retire the Tcl/legacy render path (Phase T)
--------------------------------------------------------
This is the highest-value remaining work.  Until it lands, the project still
has two drawing systems: the BSG pipeline and the Tcl-only legacy path.

Phase T0 is done:
- The remaining legacy callers and adornment producers were audited.
- Deprecation notes were added to `dm_draw_viewobjs` and `bv_data_tclcad`.

### T1 — migrate Tcl faceplate adornments onto BSG view-scope objects
Status: DONE (partial — lines, arrows, labels migrated; axes and polygons deferred).

What was done:
- `src/libtclcad/view/arrows.c`: Added `_sync_tcl_arrows_to_bsg()`; every
  setter (draw/color/line_width/points/tip_length/tip_width) now calls the
  helper to create or replace a `_tcl_data_arrows` / `_tcl_sdata_arrows`
  BSG VIEW_SCOPE object via `bv_view_obj_arrow_create`.
- `src/libtclcad/view/labels.c`: Added `_sync_tcl_labels_to_bsg()`; every
  setter (draw/color/labels/size) now creates a container BSG object with
  per-label `BV_LABELS` children via `bv_obj_get_child`.
- `src/libged/view/data_lines.c`: Added `_sync_dlines_to_bsg()` and a
  `bsg_name` field to `view_dlines_state`; every setter now maintains a
  `_tcl_data_lines` / `_tcl_sdata_lines` BSG VIEW_SCOPE vlist object.
- `src/libbv/util.cpp` (`bv_obj_reset`): Fixed a latent null-dereference that
  would crash when a `BV_LABELS` scene object was reused from the free list;
  added an `&& s->s_i_data` guard.

Deferred (not migrated — require view-size-dependent geometry or BSG polygon
support that does not exist yet):
- `src/libtclcad/view/axes.c` (data_axes): tip/size geometry depends on the
  run-time view scale factor `sf = v->gv_size / width`; deferred to T1-axes.
- `src/libtclcad/view/polygons.c` (data_polygons): complex contour mode;
  deferred to T1-polygons.

### T2 — switch refresh to `dm_draw_objs`
Status: PARTIAL (gv_tcl rendering removed from dm_draw_viewobjs; duplicate
call in refresh.c fixed; full switch to dm_draw_objs deferred to T2-final).

What was done:
- `src/libdm/view.c` (`dm_draw_viewobjs`): Removed the eight gv_tcl rendering
  blocks (data/sdata arrows, axes, lines, polygons in 3D; data/sdata labels
  and prim_labels in HUD).  Fixed the pre-existing `if (view_objs)` bug that
  guarded `local_view_objs` with the wrong pointer.  Removed the now-unused
  `sf` / `width` locals and the `#if 0` selection-highlight stub.
- `src/libtclcad/view/refresh.c` (`go_refresh_draw`): Removed the duplicate
  `dm_draw_viewobjs` call that was double-rendering the default path; confirmed
  that the OVERLAY path retains its single correct call.

Still to do (T2-final):
- Replace `dm_draw_viewobjs(...)` in `src/libtclcad/view/refresh.c` with
  `dm_draw_objs(...)` once the deferred T1 adornment kinds (axes, polygons)
  are migrated so the BSG path renders the full faceplate.

### T3 — delete the legacy renderer
Status: PARTIAL (dm_draw_arrows, dm_draw_lines, dm_draw_polys, dm_draw_labels
deprecated; full removal blocked on T2-final and T1 axes/polygons).

What was done:

  `dm_draw_lines`, `dm_draw_polys`, `dm_draw_labels`; these functions are now

Still to do (T3-final):

Priority 3 — define the per-view-variant / highlight model (Phase H)
--------------------------------------------------------------------
Status: DONE.

Design decision — overlay scope, no new node type:
- Edit overlays are LOCAL (per-view) BSG view-scope objects created via
  `bv_view_obj_overlay_create(v, name, 1/*local*/)`.  A fixed name
  (`"_ell_edit"` for the ellipsoid tool) is used at creation time so the
  BSG scope owns the object's lifetime without extra bookkeeping.
  No new BSG node concept is needed: the existing LOCAL VIEW_SCOPE
  already provides per-view containment, automatic cleanup, and
  proper integration with `bv_obj_put`.
- This is the "overlay scope" option from the design question; the
  dedicated-node-concept option was rejected because it would require a
  new BSG payload type and offer no additional capability over what the
  existing LOCAL VIEW_SCOPE already provides.

Highlight API (`bsg_view_obj_illum_by_name`):
- Added to `include/ged/bsg_ged_draw.h` and `src/libged/bsg_ged_draw.c`.
- Walks drawn display-list groups via `bsg_view_obj_foreach_group`.
- Basename-matches the last slash-separated component of each group path
  against `name`; illuminates the first solid in the first matching group
  via `bsg_view_obj_set_illum`.
- Returns the illuminated solid, or NULL (and clears any highlight) when
  no matching drawn solid is found.
- Builds on the pre-existing `bsg_view_obj_set_illum` /
  `bsg_view_obj_get_illum` infrastructure; does not touch `gd_illum_sensor`
  directly.

`QEll` migration:
- `src/qged/plugins/edit/ell/QEll.cpp`:
  - Added `#include "ged/bsg_ged_draw.h"`.
  - Both `bv_obj_get(v, BV_VIEW_OBJS)` calls replaced with
    `bv_view_obj_overlay_create(v, "_ell_edit", 1/*local*/)`.  The BSG
    scope sets the object name at creation; the old manual
    `bu_vls_sprintf(&p->s_name, ...)` line was removed.
  - `update_viewobj_name`: when the typed name resolves to a known DB
    object, calls `bsg_view_obj_illum_by_name(gedp, name)` to highlight
    the drawn representation.  When the name becomes invalid, calls
    `bsg_view_obj_set_illum(gedp, NULL)` to clear the highlight.
  - Destructor: `bv_obj_put(p)` retained unchanged — it correctly removes
    BSG-native overlay objects from their parent scope (Phase V4 path in
    `bv_obj_put`).
