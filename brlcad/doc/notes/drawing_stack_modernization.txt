Drawing Stack Modernization — Phase Cross-Walk
===============================================

This document is the single source of truth for the incremental modernization
of BRL-CAD's 3D drawing stack.  It maps changes that have already been proven
in the experimental brlcad_qgedobol/ tree to their equivalent work items in
the canonical brlcad/ tree, records which changes block which, and tracks the
status of each.

The high-level goal is to progress from two drawing stacks with an opaque
dbi_state toward a single, Inventor-shaped scene-graph stack that can be
directly backed by Obol (or an equivalent portable scene-management library).
The full plan is in seven phases; this document covers the first four in detail
and describes the remaining ones at a higher level.

See also: doc/notes/struct_resource_removal.txt (precedent for phased
structural refactoring across many sessions).

== Build prerequisites ==

Guiding principles
------------------
1. Never break MGED/Archer/rtwizard during the transition.
2. Land every change as a small, independently mergeable commit.
3. Move responsibilities UP the stack (deep libbv should not make view
   decisions; that belongs in libged or higher).
4. Make state inspectable: replace opaque unordered_map<unsigned long long,…>
   with named, typed value types and an explicit observer protocol.
5. Target an OpenInventor-shaped API as the final destination, not the next
   step; each phase leaves the code closer without requiring a flag-day.

== Phase 1 — Fix the dbi_state opacity problem ==

Status: DONE

Prerequisite: Phase 0 complete.

The core problem: dbi_state.cpp and dbi.h expose their internal state as
seventeen separate unordered_map<unsigned long long, …> fields, making it
impossible to understand at a glance which map is keyed by what kind of hash
(object name hash vs. instance hash vs. full-path hash), and impossible to
add/remove a debugger watch on "all data for object X".

Reference design: brlcad_qgedobol/include/ged/dbi.h (the fully redesigned API)

Sub-items (each an independent commit):

  1-A: Typed hash wrappers (GHash / InstHash / PathHash / DbiPath)   [DONE]
    Three unit structs (GHash, InstHash, PathHash) each wrapping
    unsigned long long, with operator== / operator!= / explicit bool and
    std::hash specializations.  DbiPath (typed path vector) has an implicit
    conversion to const vector<ull>& for backward compatibility.
    All defined in src/libged/dbi.h.

  1-B: DbiChangeEvent and SceneChangeEvent use typed hash fields       [DONE]
    New event structs use GHash / PathHash.  Existing flat maps in DbiState
    remain as unsigned long long for now (full retype deferred to Phase 2 to
    keep the diff minimal); DbiChangeEvent exposes a GHash object field and
    a bool batch flag.

  1-C: Observer protocol (IDbiObserver / DbiChangeEvent)               [DONE]
    IDbiObserver and ISceneObserver pure virtual interfaces.  DbiState gains
    add_observer() / remove_observer() / add_scene_observer() /
    remove_scene_observer() and fires on_dbi_changed(events) after each
    DbiState::update() call.  notify_dbi_observers() / notify_scene_observers()
    are private dispatchers.
    Regression: test_dbi_cpp.cpp Test 8 — observer add/fire/remove verified.

  1-D: GObj / CombInst object model                                    [DONE]
    GObj (one per .g object) and CombInst (one per child instance) value types
    added to dbi.h.  DbiState gains gobjs map (ull → GObj*) and get_gobj()
    accessor.  update_dp() creates/recreates the GObj after populating flat
    maps; GenCombInstances() walks the comb tree to populate CombInst children.
    Removed objects also remove their GObj; destructor clears all.
    Old flat-map fields (p_c, p_v, bboxes, etc.) remain as the canonical store;
    GObj reads from them on construction.
    Regression: test_dbi_cpp.cpp Test 8 — GObj for all.g has 6 CombInst entries.

  1-E: DrawList as a first-class type                                  [DONE]
    DrawList class with add(path, mode), remove(path_hash, mode),
    clear(), query(path_hash) → DrawState enum {NOT_DRAWN, FULLY_DRAWN,
    PARTIALLY_DRAWN}, drawn_path_hashes(mode), count(mode), empty().
    BViewState gains draw_list() / const draw_list() accessors backed by a
    private DrawList draw_list_ member.
    Regression: test_dbi_cpp.cpp Test 8 — add/query/clear verified.

  1-F: SelectionSet replacing BSelectState                             [DONE]
    BSelectState renamed SelectionSet throughout dbi.h and dbi_state.cpp.
    typedef SelectionSet BSelectState preserves all existing callers unchanged.
    New API methods: select(path_hash, path_vec), select(DbiPath),
    select(const char*), deselect() overloads, is_parent(), is_ancestor(),
    is_obj_immediate_parent(), is_obj_ancestor(), recompute_hierarchy(),
    selected_paths(), selected_hashes(), state_hash_val(), selected_map().
    Regression: test_dbi_cpp.cpp Test 8 — select/deselect/state_hash_val.

  1-G: Keep the C++ surface stable                                     [DONE]
    DbiState gains get_selection_set(name) / get_selection_sets(pattern) /
    add_selection_set(name) / remove_selection_set(name) as clean wrappers
    alongside the legacy find_selected_state() / get_selected_states().
    qged CMakeLists.txt updated to explicitly link Qt6::OpenGL +
    Qt6::OpenGLWidgets (pre-existing Qt6 build gap, fixed as part of this
    phase's Qt validation step).

Exit criteria: observer-based notification works and is covered by a
regression test (test_dbi_cpp.cpp Test 8).  DrawList and SelectionSet are
typed first-class objects.  GObj / CombInst populate the gobjs map.
All 8 tests in ged_test_dbi_cpp pass; qged builds cleanly with Qt6.

== Phase 2 — Drain view-dependent behavior out of libbv ==

Status: DONE

Prerequisite: Phase 1 in progress (libbv shape must be stable before libbsg
can be vendored in Phase 4).

The core problem: bv_scene_obj carries s_update_callback, s_dlist_stale,
s_dlist_free_callback, adaptive_wireframe, view_scale, bot_threshold,
curve_scale, point_scale, plus the s_v back-pointer to a bview.  These fields
push view-policy decisions into the data model.  Nothing in the scene data
record should know about adaptive rendering or display-list staleness; those
are concerns of the renderer (libdm) and the draw manager (libged).

== Phase 3 — Generalize the draw cache ==

Status: DONE

Prerequisite: Phase 0 (bu_cache migration).

Today there are two on-disk LMDB users:
  - src/libbv/lod.cpp  — stores BoT LoD geometry and mesh-name→key mappings
  - src/libged/dbi_state.cpp — stores bbox, region_id, region_flag,
                               color_inherit, color per .g solid

After Phase 0, dbi_state.cpp uses bu_cache.  libbv/lod.cpp still uses raw
LMDB.  Phase 3 migrates lod.cpp to bu_cache, restores the on-disk format-version
sentinel that guards lod.cpp's cache, introduces a version-prefixed key scheme
for dbi_state.cpp's cache, and adds a background OBB worker.

Sub-items:

  3-A: Migrate libbv/lod.cpp LMDB → bu_cache                      [DONE]
    Replace the two MDB_env instances (lod_env / name_env) with two
    struct bu_cache* instances (lod_cache / name_cache).  All MDB_* calls
    become bu_cache_* calls.  Remove LMDB_LIBRARIES from libbv CMakeLists.txt.
    Reference: qgedobol src/libbsg/lod.cpp (already migrated).

  3-B: Cache invalidation / versioning                             [DONE]
    Two different mechanisms are used, one per cache owner:

    lod.cpp (POPLoD cache):
      The pre-existing CACHE_CURRENT_FORMAT / format-file mechanism is
      retained and works independently of LMDB vs. bu_cache.  On every
      call to bv_mesh_lod_context_create() the file
        BU_DIR_CACHE/.POPLoD/format
      is read; if the integer stored there does not match CACHE_CURRENT_FORMAT
      the entire .POPLoD tree is cleared via bu_dirclear() before new caches
      are opened.  CACHE_CURRENT_FORMAT was bumped from 1 → 2 to force a
      clean slate after the LMDB→bu_cache migration.  LOD cache keys use
      the plain "hash:component" scheme with no embedded version prefix;
      the format file is the sole invalidation mechanism.

    dbi_state.cpp (DBI cache, dcache):
      All five existing payload keys (bb, rid, rf, if, c) and the new OBB
      key are constructed via dbi_cache_key(hash, component), which prepends
      a "v1:" prefix: "v1:hash:component".  When the schema changes in a
      future phase the prefix is bumped ("v2:…"); stale entries under the old
      prefix are orphaned (harmless; the data is recomputed on next access).
      There is no separate format file for dcache because the prefix scheme
      provides per-namespace discrimination without a whole-directory nuke.

    Design rationale for the divergence:
      The .POPLoD format file predates LMDB and has always been the designed
      whole-cache invalidation mechanism for lod.cpp.  A key-prefix scheme
      was considered as a replacement but would leave orphaned disk entries
      accumulating indefinitely without a corresponding cleanup path.
      The dbi_state.cpp cache is new (Phase 0) and has no prior format file;
      the key-prefix scheme was chosen from the start and is sufficient there
      because the five DBI payloads are small and quickly recomputed.

  3-C: Background OBB computation via GeomLoader                   [DONE]
    Introduce a GeomLoader worker (based on the qgedobol DrawPipeline concept)
    that computes OBBs for each solid in the background.  Results are stored in
    dcache (key "v1:hash:obb") and made available to BViewState via a
    drain_geom_results() pump.  Current OBB computation is a trivial
    axis-aligned placeholder; a PCA-based OBB can replace it later.
    GeomLoader declared in dbi.h, implemented in dbi_state.cpp.
    DbiState::geom_loader created after dcache is opened; destroyed (joining
    the worker thread) before dcache is closed in ~DbiState().

  3-D: Placeholder rendering ladder                                [DONE]
    BViewState::redraw() queues OBB computations for all newly drawn solids
    immediately after draw_scene().  BViewState::drain_geom_results() is
    exposed as a public method; callers that poll it and get count > 0 should
    trigger a view refresh to consume the updated OBBs.
    Reference: qgedobol doc/TODO.qged-stack.md §7.4 (fully validated there).

Exit criteria: a new cached payload (OBB) can be added in one place and is
consumed by the draw path without changes to bv_* headers.  The lod.cpp cache
is versioned via the format-file mechanism; the dbi cache is versioned via
key prefixes.
Qt build requirement: libbv, dm-swrast, and the LoD caching tests must all
pass; qt6-base-dev / qt6-svg-dev must be installed and -DBRLCAD_ENABLE_QT=ON.

== Phase 7 — Swap or graft Obol underneath libbsg ==

Status: PLANNED (open-ended; strategy chosen when Phase 6 is complete)

Two strategies:
  Backend-style: libbsg keeps its public API; implementations delegate to Obol.
    Prefer this when API stability is paramount (many out-of-tree consumers
    depend on the libbsg surface) or when Obol's public API is not yet stable
    enough to expose directly.
  Adapter-style: Obol becomes the public scene API; libbsg shrinks to a shim.
    Prefer this when Obol's API has stabilized, performance measurements show
    the extra indirection through libbsg is material, and the remaining
    out-of-tree consumers are few enough to migrate in one pass.

Key decision factors when the time comes:
  - Obol API stability: is the obol/ public surface frozen or still evolving?
  - Callsite count: how many files outside of libbsg still call libbsg symbols?
    (A large number favors the backend-style to avoid a flag-day migration.)
  - Performance: does the backend-style double-dispatch introduce measurable
    overhead on the draw-test benchmark set?
  - Maintenance cost: adapter-style allows deleting libbsg entirely once
    migration is complete, reducing long-term maintenance burden.
