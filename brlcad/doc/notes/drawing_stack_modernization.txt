Drawing Stack Modernization — Current State and Next Work
=========================================================

Purpose
-------
This note is the handoff document for continuing BRL-CAD drawing-stack
modernization work.  It replaces older session-by-session notes with a concise
summary of:

1. the current architecture,
2. the phases that are already complete,
3. the remaining follow-on work, and
4. the constraints future sessions should preserve.

The original long-form end-state rationale lives in the repository-root
`draw_migration_plan.rtf` file (outside the `brlcad/` subtree).  Read that file
only when the rationale behind a design choice is needed; this file should be
sufficient for implementation sessions.

Build and validation reminders
------------------------------
Drawing-stack work is Qt-sensitive.  Always configure BRL-CAD with Qt enabled
unless intentionally testing a non-Qt path.

Recommended configure shape from the repository root:

  cmake -S brlcad -B brlcad_build \
    -DBRLCAD_EXT_DIR=bext_output \
    -DCMAKE_PREFIX_PATH=bext_output/install \
    -DBRLCAD_EXTRADOCS=OFF \
    -DBRLCAD_ENABLE_STEP=OFF \
    -DBRLCAD_ENABLE_GDAL=OFF \
    -DBRLCAD_ENABLE_OPENGL=ON \
    -DBRLCAD_ENABLE_QT=ON

For code changes in this area, at minimum keep the Qt drawing targets healthy:
`libqtcad`, `dm-qtgl`, `dm-swrast`, `qged`, and `archer`.  For focused BSG/GED
changes, also run the draw tests in `src/libged/tests/draw`, especially
`bsg_view_obj.cpp`.

Current headline
----------------
The structural modernization is complete.  The canonical drawn set is now a BSG
tree rooted at `ged_drawable::gd_draw_root`; the old `display_list` model is no
longer the authoritative draw-store.  The active view points at that tree through
`bview::gv_draw_root`, and libdm renders it via BSG traversal.

Completed work includes:

- Phases 0-7: BSG infrastructure, front-end migration, removal of the standalone
  legacy display-list implementation, and conversion of the GED draw set into a
  real tree.
- Phase 8: render-contract parity with the old display-list path.
- Phase 9: cached aggregate bounding boxes, per-frame draw generation stamps,
  and sensorized illumination revision tracking.
- Phase 10: public API cleanup through db_full_path-keyed entry points and
  deprecation of the remaining path-string mutation/lookup APIs.

The remaining work is not to make the current tree viable; it is follow-on
architecture cleanup and backend selection:

- Phase 11: renderer-backend contract.
- Phase 12: benchmark-based default backend decision.
- Phase 13: retirement of deprecated/transitional fields and APIs after the new
  backend contract lands.

Current architecture
--------------------
Future sessions should start from these present-day facts.

1. The BSG tree is the canonical drawn set.
   - Owner/root: `ged_drawable::gd_draw_root`.
   - View pointer: `bview::gv_draw_root`.
   - Real drawn geometry is represented by nested BSG group/shape nodes.
   - `gd_headDisplay` and old display-list concepts are compatibility/supporting
     state only; do not make them authoritative again.

2. Tree mechanics belong in libbsg.
   - `src/libbsg/draw_set.c` owns pure tree operations: child-group utilities,
     recursive free, revision/cache invalidation, nested-subpath erase, and
     aggregate bbox calculation.
   - `src/libbsg/overlay.c` owns overlay-group helpers.
   - `include/bsg/draw_ctx.h` defines the per-root context that lets libbsg bump
     owner revisions and recycle nodes without taking a `struct ged *`.

3. GED policy remains above libbsg.
   - `src/libged/bsg_ged_draw.c` is the GED-facing wrapper/policy layer.
   - Keep user-facing policy decisions (draw command semantics, overlay policy,
     illumination policy, material-table policy) out of libbsg unless they become
     pure tree primitives.

4. Overlays are scene nodes, not fake database objects.
   - The `_overlays` branch and `BSG_PAYLOAD_OVERLAY` replaced drawing-path use
     of `RT_DIR_PHONY_ADDR`.
   - Public reporting helpers should ask the BSG/GED helpers whether a group is
     an overlay/phony group; they should not infer this from database addresses.

5. Material recoloring is lazy and revision based.
   - `ged_drawable::gd_mater_rev` starts at 1.
   - `bv_scene_obj::s_color_rev` starts at 0 for freshly drawn shapes.
   - Material-changing commands call `bsg_view_obj_bump_mater_rev()`.
   - `bsg_view_obj_color_from_soltab()` stamps shapes with the current material
     revision but does not bump the revision itself.

6. Frame-drawn status is generation based.
   - `bview::gv_frame_rev` is bumped at the start of `dm_draw_objs()`.
   - Successfully drawn shapes are stamped with `bv_scene_obj::s_drawn_rev`.
   - "Drawn this frame" means `s_drawn_rev == gv_frame_rev`.
   - Do not restore a per-frame full-tree `s_flag = DOWN` reset.

7. Illumination has both an O(1) identity cache and a sensor revision.
   - `ged_drawable::gd_illum_solid` remains as the fast identity path used by
     current GED logic.
   - `ged_drawable::gd_illum_sensor` and `gd_illum_rev` provide lazy change
     notification for the illuminated node.
   - `bsg_view_obj_illum_rev()` exposes the revision counter.

8. Aggregate bounding boxes are cached on group nodes.
   - `bv_scene_obj::s_bbox_cached` marks valid aggregate bbox data for group/root
     nodes.
   - Structural mutation chokepoints invalidate caches up the parent chain.
   - `bsg_subtree_bbox()` is the cache-aware tree query.

Completed phase summary
-----------------------

Phase 0-4: supporting infrastructure — DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
These phases established the pieces needed to move the drawing stack to BSG:
modernized state handling, observer/state machinery, vendored libbsg, libdm BSG
traversal support, and `bview` draw-root plumbing.

Phase 5: front-end migration — DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
MGED, Archer, and related front ends were moved onto the BSG-capable drawing
path.  Renderers could consume a BSG scene root rather than walking the old
display-list chain.

Phase 6.5: legacy display-list removal — DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
The standalone `src/libged/display_list.c` implementation was removed.  Its
remaining helpers were folded into the newer layers and then progressively
replaced or narrowed to compatibility roles.

Phase 7: GED draw set as a real BSG tree — DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
The GED draw tree became the canonical data structure:

- `gd_draw_root` is the per-GED root.
- Nested component groups represent drawn paths.
- DFS snapshots replaced linked-list next/previous traversal.
- Overlay nodes moved under `_overlays` with `BSG_PAYLOAD_OVERLAY`.
- Pure tree free/revision helpers moved to libbsg.
- `bsg_view_obj.c` was renamed to `bsg_ged_draw.c` to reflect the split between
  libbsg tree mechanics and libged policy/wrappers.

Phase 8: BSG render contract — DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
The BSG render path now preserves behaviour formerly encoded by
`dm_draw_head_dl()` / `dm_drawSolid()`:

- transparent drawing uses an opaque pass and a transparent pass;
- geometry default color is obtained from the display manager;
- line-width fallback uses the display manager linewidth when the object line
  width is unset;
- OpenGL display-list replay still happens when enabled and valid;
- bound-flag small-object culling is preserved;
- transform traversal carries and restores the accumulated matrix correctly.

The per-frame `s_flag = DOWN` reset that originally belonged to this contract was
superseded by Phase 9.2's generation counter.

Phase 9: lazy bbox and sensorized highlight — DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Phase 9 closed the main residual performance/state gaps.

Step 9.1: cached aggregate bbox
  - Group/root nodes cache aggregate bbox data with `s_bbox_cached`.
  - `bsg_subtree_bbox()` performs cache-aware bbox queries.
  - `bsg_node_bbox_invalidate()` clears ancestor caches when tree structure
    changes.
  - Structural mutation chokepoints invalidate caches.
  - `_sg_bounding_sph()` delegates to libbsg instead of doing a full-tree walk.

Step 9.2: drawn-this-frame generation counter
  - `bview::gv_frame_rev` is advanced per frame.
  - `bv_scene_obj::s_drawn_rev` records successful drawing in that frame.
  - MGED's drawn-count logic tests the generation stamp rather than relying on a
    destructive reset pass.

Step 9.3: illumination NodeSensor
  - `gd_illum_sensor` tracks the currently illuminated node.
  - Sensor callbacks bump `gd_illum_rev` when the illuminated node changes.
  - `set_iflag(DOWN)`, `zap`, free callbacks, and illumination transitions tear
    the sensor down cleanly.
  - `bsg_view_obj_illum_rev()` exposes the revision to observers.

Phase 10: public libged API cleanup — DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
The canonical GED drawing header is now `include/ged/bsg_ged_draw.h`.
`include/ged/bsg_view_obj.h` remains as a compatibility shim that includes the
canonical header.

New db_full_path-keyed APIs are available:

- `bsg_view_obj_lookup_or_add_dbpath()`
- `bsg_view_obj_erase_by_dbpath()`
- `bsg_view_obj_erase_all_dbpaths()`
- `bsg_view_obj_group_dbpath()`
- `bsg_view_obj_group_set_dbpath()`

All in-tree callers of the path-keyed mutation/lookup APIs have been migrated to
construct a `db_full_path` at the call site and use the dbpath variants.  The old
path-string variants remain for compatibility but are deprecated with
`BSG_DEPRECATED_PATH_STR`:

- `bsg_view_obj_lookup_or_add_path()`
- `bsg_view_obj_erase_by_path()`
- `bsg_view_obj_erase_all_paths()`
- `bsg_view_obj_group_set_path()`

`bsg_view_obj_group_path()` and `bsg_view_obj_erase_by_name()` are intentionally
not deprecated: the former is the natural string accessor for current internal
name storage, and the latter is component-name-keyed rather than path-keyed.

Audit against the original RTF layers
-------------------------------------

Layer A — make the drawn set a BSG tree: DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
A1 canonical BSG drawn set, A2 tree-based storage, A3 view draw-root plumbing,
and A4 DFS snapshot navigation are complete.  The remaining path-string APIs are
compatibility surfaces, not evidence that storage is still list-based.

Layer B — re-express legacy roles in BSG terms: DONE with one transitional cache
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
B1/B2/B3/B4/B6/B7/B8/B9 are complete.  B5's lazy notification side is implemented
with a NodeSensor and `gd_illum_rev`; `gd_illum_solid` intentionally remains as a
transitional O(1) identity cache until Phase 13.

Layer C — lift tree mechanics into libbsg/delete old shape: MOSTLY DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Pure tree mechanics are in libbsg and GED policy is above it.  The remaining
cleanup belongs to Phases 11 and 13: backend-specific per-shape fields,
deprecated path-string entry points, and transitional illumination identity state.

User-facing redesign items R1/R2: DONE
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
R1 overlay reporting no longer depends on fake database addresses.  R2 erase
compatibility knobs have been removed; callers now express any special matching
semantics explicitly.

Remaining work
--------------

Phase 11: renderer-backend contract
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Goal: replace ad-hoc backend fields on `bv_scene_obj` with a real backend
contract.  Today fields such as GL display-list state are still stored directly
on scene objects.  A cleaner design should provide one backend-owned slot plus a
destructor/cleanup path and a display-manager backend function table.

Expected outcome:

- dm-gl and dm-swrast use the same backend contract;
- experimental Obol/qged backend work can attach without widening
  `bv_scene_obj` again;
- the Phase 8 render contract is captured in shared helper logic that backends
  can opt into or faithfully replace;
- backend-specific resources are invalidated/freed through the generic contract,
  not by adding more fields to `bv_scene_obj`.

Suggested starting points:

- `include/bv/defines.h` for current per-scene-object backend/display-list
  fields;
- `include/dm.h` and `src/libdm/include/calltable.h` for current display-manager
  hooks;
- `src/libdm/view.c` for the default BSG traversal/render loop;
- `src/libdm/dm-gl_lod.cpp` for GL display-list replay and invalidation
  expectations;
- `include/bsg/draw_set.h` and `src/libbsg/draw_set.c` for cleanup callbacks
  currently fired when shapes are removed.

Phase 12: default backend decision
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Goal: choose the long-term default renderer backend by measurement rather than
preference.

Use dm-obol as the default only if it wins on at least two of these dimensions
and is no worse than 10% on the others:

- redraw latency,
- peak RSS,
- code volume/maintenance burden saved.

Otherwise keep dm-gl as the default and ship Obol as opt-in.

Phase 13: retire transitional APIs and fields
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Goal: remove compatibility surfaces once Phase 11 provides the replacement
architecture and downstream callers have had a migration window.

Candidates to remove or collapse:

- path-string mutation/lookup APIs deprecated during Phase 10;
- backend-specific scene-object fields that Phase 11 replaces;
- `gd_illum_solid`, once all users can rely on sensor/revision-backed
  illumination state;
- any remaining compatibility path that reintroduces display-list-era semantics
  into public drawing APIs.

Do not remove these prematurely: Phase 13 should happen after Phase 11 lands and
after in-tree/out-of-tree compatibility expectations are reviewed.

What not to redo
----------------
Do not spend future sessions rediscovering or re-litigating these settled points:

- Do not reintroduce `display_list`/`gd_headDisplay` as the canonical drawn-set
  structure.
- Do not use `RT_DIR_PHONY_ADDR` as drawing-path overlay state.
- Do not move GED/MGED policy down into libbsg just to make libbsg look more
  complete.
- Do not replace the existing lazy-color revision token with a second mechanism.
- Do not make `bsg_view_obj_color_from_soltab()` bump `gd_mater_rev`; material
  change callers must bump it.
- Do not restore per-frame full-tree `s_flag` resets; use `gv_frame_rev` and
  `s_drawn_rev`.
- Do not add backend-specific fields to `bv_scene_obj` as a long-term solution;
  implement Phase 11's backend-owned slot/contract first.
- Do not remove the deprecated path-string APIs before the planned Phase 13
  compatibility cleanup.

Quick checklist for future sessions
-----------------------------------
Before making a drawing-stack change:

1. Identify whether the change is GED policy, pure tree mechanics, display-manager
   rendering, or backend-resource management.
2. Put GED policy in libged, pure tree mechanics in libbsg, and rendering/backend
   concerns in libdm.
3. Preserve the revision/caching contracts: `gd_draw_rev`, `gd_mater_rev`,
   `gv_frame_rev`, `s_drawn_rev`, `s_bbox_cached`, and `gd_illum_rev`.
4. Add or update focused draw tests when behaviour changes.
5. Keep Qt-enabled drawing targets buildable.
