Drawing Stack Modernization — Phase Cross-Walk
===============================================

This document is the single source of truth for the incremental modernization
of BRL-CAD's 3D drawing stack.  It maps changes that have already been proven
in the experimental brlcad_qgedobol/ tree to their equivalent work items in
the canonical brlcad/ tree, records which changes block which, and tracks the
status of each.

The high-level goal is to progress from two drawing stacks with an opaque
dbi_state toward a single, Inventor-shaped scene-graph stack that can be
directly backed by Obol (or an equivalent portable scene-management library).
The full plan is in seven phases; this document covers the first four in detail
and describes the remaining ones at a higher level.

See also: doc/notes/struct_resource_removal.txt (precedent for phased
structural refactoring across many sessions).

== Build prerequisites ==

The Qt stack (libqtcad, dm-qtgl, dm-swrast, qged) is central to this
work.  Every phase MUST be built and validated with Qt enabled.  Never use
-DBRLCAD_ENABLE_QT=OFF for work in this area.

Guiding principles
------------------
1. Never break MGED/Archer/rtwizard during the transition.
2. Land every change as a small, independently mergeable commit.
3. Move responsibilities UP the stack (deep libbv should not make view
   decisions; that belongs in libged or higher).
4. Make state inspectable: replace opaque unordered_map<unsigned long long,…>
   with named, typed value types and an explicit observer protocol.
5. Target an OpenInventor-shaped API as the final destination, not the next
   step; each phase leaves the code closer without requiring a flag-day.

== Phase 1 — Fix the dbi_state opacity problem ==

Status: DONE

Prerequisite: Phase 0 complete.

The core problem: dbi_state.cpp and dbi.h expose their internal state as
seventeen separate unordered_map<unsigned long long, …> fields, making it
impossible to understand at a glance which map is keyed by what kind of hash
(object name hash vs. instance hash vs. full-path hash), and impossible to
add/remove a debugger watch on "all data for object X".

Reference design: brlcad_qgedobol/include/ged/dbi.h (the fully redesigned API)

Sub-items (each an independent commit):

  1-A: Typed hash wrappers (GHash / InstHash / PathHash / DbiPath)   [DONE]
    Three unit structs (GHash, InstHash, PathHash) each wrapping
    unsigned long long, with operator== / operator!= / explicit bool and
    std::hash specializations.  DbiPath (typed path vector) has an implicit
    conversion to const vector<ull>& for backward compatibility.
    All defined in src/libged/dbi.h.

  1-B: DbiChangeEvent and SceneChangeEvent use typed hash fields       [DONE]
    New event structs use GHash / PathHash.  Existing flat maps in DbiState
    remain as unsigned long long for now (full retype deferred to Phase 2 to
    keep the diff minimal); DbiChangeEvent exposes a GHash object field and
    a bool batch flag.

  1-C: Observer protocol (IDbiObserver / DbiChangeEvent)               [DONE]
    IDbiObserver and ISceneObserver pure virtual interfaces.  DbiState gains
    add_observer() / remove_observer() / add_scene_observer() /
    remove_scene_observer() and fires on_dbi_changed(events) after each
    DbiState::update() call.  notify_dbi_observers() / notify_scene_observers()
    are private dispatchers.
    Regression: test_dbi_cpp.cpp Test 8 — observer add/fire/remove verified.

  1-D: GObj / CombInst object model                                    [DONE]
    GObj (one per .g object) and CombInst (one per child instance) value types
    added to dbi.h.  DbiState gains gobjs map (ull → GObj*) and get_gobj()
    accessor.  update_dp() creates/recreates the GObj after populating flat
    maps; GenCombInstances() walks the comb tree to populate CombInst children.
    Removed objects also remove their GObj; destructor clears all.
    Old flat-map fields (p_c, p_v, bboxes, etc.) remain as the canonical store;
    GObj reads from them on construction.
    Regression: test_dbi_cpp.cpp Test 8 — GObj for all.g has 6 CombInst entries.

  1-E: DrawList as a first-class type                                  [DONE]
    DrawList class with add(path, mode), remove(path_hash, mode),
    clear(), query(path_hash) → DrawState enum {NOT_DRAWN, FULLY_DRAWN,
    PARTIALLY_DRAWN}, drawn_path_hashes(mode), count(mode), empty().
    BViewState gains draw_list() / const draw_list() accessors backed by a
    private DrawList draw_list_ member.
    Regression: test_dbi_cpp.cpp Test 8 — add/query/clear verified.

  1-F: SelectionSet replacing BSelectState                             [DONE]
    BSelectState renamed SelectionSet throughout dbi.h and dbi_state.cpp.
    typedef SelectionSet BSelectState preserves all existing callers unchanged.
    New API methods: select(path_hash, path_vec), select(DbiPath),
    select(const char*), deselect() overloads, is_parent(), is_ancestor(),
    is_obj_immediate_parent(), is_obj_ancestor(), recompute_hierarchy(),
    selected_paths(), selected_hashes(), state_hash_val(), selected_map().
    Regression: test_dbi_cpp.cpp Test 8 — select/deselect/state_hash_val.

  1-G: Keep the C++ surface stable                                     [DONE]
    DbiState gains get_selection_set(name) / get_selection_sets(pattern) /
    add_selection_set(name) / remove_selection_set(name) as clean wrappers
    alongside the legacy find_selected_state() / get_selected_states().
    qged CMakeLists.txt updated to explicitly link Qt6::OpenGL +
    Qt6::OpenGLWidgets (pre-existing Qt6 build gap, fixed as part of this
    phase's Qt validation step).

Exit criteria: observer-based notification works and is covered by a
regression test (test_dbi_cpp.cpp Test 8).  DrawList and SelectionSet are
typed first-class objects.  GObj / CombInst populate the gobjs map.
All 8 tests in ged_test_dbi_cpp pass; qged builds cleanly with Qt6.

== Phase 2 — Drain view-dependent behavior out of libbv ==

Status: DONE

Prerequisite: Phase 1 in progress (libbv shape must be stable before libbsg
can be vendored in Phase 4).

The core problem: bv_scene_obj carries s_update_callback, s_dlist_stale,
s_dlist_free_callback, adaptive_wireframe, view_scale, bot_threshold,
curve_scale, point_scale, plus the s_v back-pointer to a bview.  These fields
push view-policy decisions into the data model.  Nothing in the scene data
record should know about adaptive rendering or display-list staleness; those
are concerns of the renderer (libdm) and the draw manager (libged).

Reference design: brlcad_qgedobol/src/libbsg/ (scene_graph.cpp, lod.cpp)

Sub-items:

  2-A: Annotate & audit callers                                       [DONE]
    BV_DEPRECATED (Phase 2) comments added in include/bv/defines.h for:
      s_v (used for control flow), s_update_callback (LoD/CSG path removed),
      s_dlist_stale, s_dlist_free_callback, adaptive_wireframe, view_scale,
      bot_threshold, curve_scale, point_scale.

    Write-site audit (all direct writes to the deprecated fields):
      s_update_callback:
        src/libged/draw.cpp: bot_adaptive_plot(), brep_adaptive_plot(),
          wireframe_plot() — RETAINED for per-frame rendering via libdm/view.c.
          BViewState::redraw() adds an explicit supplementary pass (2-B).
        src/libdm/view.c: draw_scene_obj() calls s_update_callback for
          non-LoD polygon-edit objects — this call remains valid.
      s_dlist_stale:
        src/libbv/util.cpp bv_obj_stale() sets s_dlist_stale=1 — remains.
        src/libdm/dm-gl_lod.cpp: polled on entry; cleared after dlist gen — remains
          for backward compat; sensor fires on dlist regeneration (2-C).
      s_dlist_free_callback:
        src/libdm/dm-gl_lod.cpp: set during dlist creation — remains; will
          be removed in 2-E after libdm owns teardown via sensor pattern.
      adaptive_wireframe, view_scale, bot_threshold, curve_scale, point_scale:
        Written in csg_wireframe_update() and bv_mesh_lod_view() — these

  2-B: Move adaptive-plot / LoD trigger to BViewState                 [DONE]
    s_update_callback = &bv_mesh_lod_view RETAINED for BV_MESH_LOD objects
      (bot_adaptive_plot, brep_adaptive_plot) — it is still called per-frame

      in wireframe_plot() for the same reason.
    csg_wireframe_update() made extern "C" (non-static) so dbi_state.cpp

    Forward declarations added at top of dbi_state.cpp for draw_scene() and

      This ensures view-scale changes from redraw_on_zoom also propagate LoD.
    Dead #if 0 block in libbv/util.cpp::bv_update_selected() replaced with

    lod.cpp: enabling adaptive_plot now also sets redraw_on_zoom = 1 so

    Blocker: Phase 1-E (DrawList), 2-A.

    struct dm_dlist_sensor added to calltable.h (singly-linked list node

== Phase 3 — Generalize the draw cache ==

Status: DONE

Prerequisite: Phase 0 (bu_cache migration).

Today there are two on-disk LMDB users:
  - src/libbv/lod.cpp  — stores BoT LoD geometry and mesh-name→key mappings
  - src/libged/dbi_state.cpp — stores bbox, region_id, region_flag,
                               color_inherit, color per .g solid

After Phase 0, dbi_state.cpp uses bu_cache.  libbv/lod.cpp still uses raw
LMDB.  Phase 3 migrates lod.cpp to bu_cache, gives both caches a consistent
format-file invalidation mechanism, and adds a background OBB worker.

Sub-items:

  3-A: Migrate libbv/lod.cpp LMDB → bu_cache                      [DONE]
    Replace the two MDB_env instances (lod_env / name_env) with two
    struct bu_cache* instances (lod_cache / name_cache).  All MDB_* calls
    become bu_cache_* calls.  Remove LMDB_LIBRARIES from libbv CMakeLists.txt.
    Reference: qgedobol src/libbsg/lod.cpp (already migrated).

  3-B: Cache invalidation via format files                         [DONE]
    Both cache owners use the same mechanism: a plain-text integer version
    file in the cache root directory.  On startup, if the integer in the file
    doesn't match the compile-time constant the entire cache directory is
    cleared via bu_dirclear() before new caches are opened.  Cache keys use
    plain "hash:component" strings with no embedded version prefix.

    lod.cpp (POPLoD cache):
      File: BU_DIR_CACHE/.POPLoD/format
      Constant: CACHE_CURRENT_FORMAT (bumped 1 → 2 to force a clean slate
      after the LMDB→bu_cache migration in 3-A).
      Checked in: bv_mesh_lod_context_create().

    dbi_state.cpp (DBI cache, dcache):
      File: BU_DIR_CACHE/.Dbi/format
      Constant: DBI_CACHE_FORMAT_VERSION (starts at 1).
      Checked in: DbiState::DbiState() before bu_cache_open().
      Covers all six payload keys: bb, rid, rf, if, c, obb.

    When a payload's binary layout changes, or a payload type is added or
    removed, only the relevant format-version constant needs to be bumped;
    the next startup automatically wipes and rebuilds the entire cache
    directory for that cache owner.  No orphaned entries accumulate.

  3-C: Background OBB computation via GeomLoader                   [DONE]
    Introduce a GeomLoader worker (based on the qgedobol DrawPipeline concept)
    that computes OBBs for each solid in the background.  Results are stored in
    dcache (key "hash:obb") and made available to BViewState via a
    drain_geom_results() pump.  Current OBB computation is a trivial
    axis-aligned placeholder; a PCA-based OBB can replace it later.
    GeomLoader declared in dbi.h, implemented in dbi_state.cpp.
    DbiState::geom_loader created after dcache is opened; destroyed (joining
    the worker thread) before dcache is closed in ~DbiState().

  3-D: Placeholder rendering ladder                                [DONE]
    BViewState::redraw() queues OBB computations for all newly drawn solids
    immediately after draw_scene().  BViewState::drain_geom_results() is
    exposed as a public method; callers that poll it and get count > 0 should
    trigger a view refresh to consume the updated OBBs.
    Reference: qgedobol doc/TODO.qged-stack.md §7.4 (fully validated there).

Exit criteria: a new cached payload (OBB) can be added in one place and is
consumed by the draw path without changes to bv_* headers.  Both caches use
the format-file mechanism for invalidation; keys are plain "hash:component".
Qt build requirement: libbv, dm-swrast, and the LoD caching tests must all
pass; qt6-base-dev / qt6-svg-dev must be installed and -DBRLCAD_ENABLE_QT=ON.

== Phase 3.5 — Migrate concurrentqueue.h based drawing data cache in qgedobol

Status: DONE

    Replaced the Phase 3-C single-threaded GeomLoader (which computed trivial
    axis-aligned OBBs as a placeholder) with a 5-stage concurrent pipeline
    (DrawPipeline) that closely mirrors qgedobol's cache_drawing.cpp design:

    Stage 1 — attr_worker:   reads region flag/id, inherit, color from AVS and
                             enqueues them for cache writing; cracks geometry and
                             forwards rt_db_internal to q_aabb.
    Stage 2 — aabb_worker:  calls ft_bbox to compute a real AABB; posts a
                             DrawPipeline::Result::AABB to results_q and forwards
                             the internal to q_obb.
    Stage 3 — obb_worker:   calls ft_oriented_bbox to compute a tight oriented
                             bounding box (8 corner points, 24 fastf_t); posts
                             DrawPipeline::Result::OBB; forwards to q_lod.
    Stage 4 — lod_worker:   for BoT primitives, calls bv_mesh_lod_cache /
                             bv_mesh_lod_key_put if not already cached; posts
                             DrawPipeline::Result::LOD.
    Stage 5 — write_worker: serialises all bu_cache writes, preventing LMDB
                             transaction conflicts from concurrent workers.

    All 5 stages use moodycamel::ConcurrentQueue (concurrentqueue.h) for lock-
    free inter-stage handoff.  A shared DrawPipelineState (held as a
    shared_ptr) owns the queues and result_q; the pipeline shuts down cleanly
    when ~DrawPipeline() signals shutdown and waits up to 2 s for all threads.

    New public surface in dbi.h / DbiState:
      DbiState::obbs       — map from hash to std::array<fastf_t,24> (8 corner pts)
      DbiState::start_geom_load(items) — push WorkItems to pipeline
      DbiState::drain_geom_results()   — drain results, update bboxes/obbs
      DbiState::wait_for_pipeline(ms)  — blocking drain loop (useful for tests)
      BViewState::drain_geom_results() — delegates to DbiState (return type now size_t)

    DBI_CACHE_FORMAT_VERSION bumped to 2 (OBB format changed from center+extents
    4×3 doubles to 8 corner points 24 fastf_t).

    DbiState constructor also pushes all solid directory pointers at init time so
    AABB, OBB and LoD data are pre-populated in the background for the full model.

    BViewState::redraw() Phase 3-D block updated: instead of calling
    geom_loader->queue_item(hash, bmin, bmax) it builds a DrawPipeline::WorkItem
    list from the drawn s_map and calls DbiState::start_geom_load().

    Most OBB data will not yet be used in current drawing implementations (Phase 4+
    will wire OBBs into view-frustum culling and bsg scene nodes), but all the
    required data is now being computed and stored, positioning us for future work.

    Test 9 added to ged_test_dbi_cpp: opens moss.g, waits for pipeline to settle,
    verifies at least one AABB result is produced.  9/9 PASS.

Exit criteria: We successfully cache and are able to retrieve all information
qgedobol's cache stores, and do so without breaking our current LoD features.
Qt build requirement: libbv, dm-swrast, and the LoD caching tests must all
pass; qt6-base-dev / qt6-svg-dev must be installed and -DBRLCAD_ENABLE_QT=ON.


== Phase 4 — Stand up libbsg in brlcad/ alongside libbv ==

Status: DONE

Prerequisite: Phase 2 (libbv shape stable), Phase 3 (cache unified).

This phase is additive: libbv still ships and works.  libbsg is vendored in
alongside it, providing the scene-graph API that will eventually replace the
dl_* walk.

  - bsg_view_traverse(root) is the single render loop

== Phase 7 — Swap or graft Obol underneath libbsg ==

Status: PLANNED (open-ended; strategy chosen when Phase 6 is complete)

Two strategies:
  Backend-style: libbsg keeps its public API; implementations delegate to Obol.
    Prefer this when API stability is paramount (many out-of-tree consumers
    depend on the libbsg surface) or when Obol's public API is not yet stable
    enough to expose directly.
  Adapter-style: Obol becomes the public scene API; libbsg shrinks to a shim.
    Prefer this when Obol's API has stabilized, performance measurements show
    the extra indirection through libbsg is material, and the remaining
    out-of-tree consumers are few enough to migrate in one pass.

Key decision factors when the time comes:
  - Obol API stability: is the obol/ public surface frozen or still evolving?
  - Callsite count: how many files outside of libbsg still call libbsg symbols?
    (A large number favors the backend-style to avoid a flag-day migration.)
  - Performance: does the backend-style double-dispatch introduce measurable
    overhead on the draw-test benchmark set?
  - Maintenance cost: adapter-style allows deleting libbsg entirely once
    migration is complete, reducing long-term maintenance burden.

           ── Phase 7 Step 9: illum-clear via s_free_callback (option 4) ──

           2026-05-04

              Investigation: Why does gd_illum_solid exist, and can the
              per-object s_free_callback mechanism replace _sg_clear_illum_if_match?

              Background: s_iflag (char on bv_scene_obj) is the per-object
              illumination state (UP = highlighted, DOWN = normal). gd_illum_solid
              is a GED-level pointer to the single currently-illuminated shape,
              added in Phase 7 Step 6 as an O(1) optimization: clearing illumination
              across the entire tree (bsg_view_obj_set_iflag DOWN) only needs to
              touch the one tracked pointer instead of sweeping N shapes.

              The dangling-pointer hazard: if a shape is freed while it is the
              illuminated solid, gd_illum_solid becomes a dangling pointer.
              _sg_clear_illum_if_match(gedp, sp) was called explicitly in every
              freeing path to prevent this.  This required passing gedp into
              _sg_free_children_recursive and _sg_erase_nested_subpath (case b),
              blocking those helpers from moving to libbsg.

              Fix (option 4):
                1.  Added struct ged *gedp back-pointer to struct ged_bv_data
                    (include/ged/view.h) — one pointer per pool slot, set once
                    per shape creation, reused across pool recycles.

                2.  Added ged_bv_illum_free_cb() (non-static, declared in
                    include/ged/bsg_view_obj.h) — reads bdata->gedp, clears
                    gd_illum_solid if it matches sp. No-op on second call
                    (e.g. during bv_free pool teardown).

                3.  Registered ged_bv_illum_free_cb as sp->s_free_callback at
                    every BSG_NODE_SHAPE creation site:
                      bsg_view_obj.c _sg_invent (overlay shapes)
                      draw.c dl_add_path (main draw path)
                      draw.c append_solid_to_display_list (bigE path)

                4.  In _sg_free_children_recursive and _sg_erase_nested_subpath
                    (case b): added explicit `if (sp->s_free_callback)
                    (*sp->s_free_callback)(sp)` call before FREE_BV_SCENE_OBJ
                    (same pattern already used for s_dlist_free_callback).
                    Removed _sg_clear_illum_if_match(gedp, ...) calls.
                    Deleted the _sg_clear_illum_if_match helper entirely.

              gd_illum_solid and the O(1) fast path are retained — they are
              correct and the fast path is genuinely useful for interactive
              editing. The change removes only the GED-dependency concern from
              the freeing path for this specific bookkeeping operation.
