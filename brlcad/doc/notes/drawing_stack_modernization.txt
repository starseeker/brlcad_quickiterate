Drawing Stack Modernization — Concise Status and Next-Session Plan
=================================================================

Purpose
-------
This note is the short handoff for future drawing-stack work.  It records
what is already settled, why that work matters, and what still needs to be
done to finish the migration to one clean rendering model.

Use `draw_migration_plan.rtf` only when deeper historical design rationale is
needed.  This file should stay focused on current status and the remaining
implementation plan.

Historical record
-----------------
Previous copilot sessions (before the upstream sync that reset this branch)
implemented the following work.  All of it was lost when main was re-synced
from upstream brlcad/brlcad.  This section records what was done so that it
can be re-implemented methodically.

1. BSG (Bounded Scene Graph) tree infrastructure (Phases V4–V8):
   - Added `libbsg` library with `BSG_NODE_*` type flags and BSG tree traversal.
   - Added `BSG_NODE_VIEW_SCOPE` concept for shared vs per-view object containment.
   - Added `BSG_NODE_LOD` for adaptive Level-of-Detail.
   - Added typed public APIs to libbv:
       bv_view_obj_create, bv_view_obj_arrow_create,
       bv_view_obj_lines_create, bv_view_obj_overlay_create,
       bv_view_obj_find, bv_view_obj_visit, bv_view_obj_remove,
       bv_view_obj_set_color, bv_view_obj_set_line_width, bv_view_obj_set_visible.
   - Retired `bview::independent` boolean in favour of structural BSG independence.
   - Unified the `view obj` command surface around create/remove/list/info/set.

2. Phase T — retire the Tcl/legacy render path (partial):
   - T0: audited legacy callers; added deprecation notes.
   - T1 (partial): added `_sync_tcl_arrows_to_bsg`, `_sync_tcl_labels_to_bsg`,
     `_sync_dlines_to_bsg` in libtclcad/libged; each keeps a BSG VIEW_SCOPE
     object in sync with the gv_tcl adornment state so dm_draw_objs picks it up.
     Axes and polygons were deferred (view-size-dependent geometry / BSG polygon
     support not yet ready).
   - T2 (partial): removed gv_tcl rendering blocks from dm_draw_viewobjs; fixed
     duplicate dm_draw_viewobjs call in refresh.c.
   - T3 (partial): deprecated dm_draw_arrows/lines/polys/labels.
   - T2-final / T3-final blocked on T1-axes and T1-polygons.

3. Phase A — typed-API adoption (complete):
   - A0: bv_vlblock_obj → bv_view_obj_find + bv_view_obj_overlay_create;
     bv_view_select_polygon typed wrapper added.
   - A1: polygon creation paths fixed (spurious bu_vls_init removed).
   - A2: QgMeasureFilter, QgPolyFilter, QPolyCreate, QPolyMod migrated from
     bv_view_objs ptbl loops to bv_view_obj_visit callbacks.

4. Phase H — per-view-variant / highlight model (complete):
   - Design: LOCAL VIEW_SCOPE overlays, no new node type.
   - Added bsg_view_obj_illum_by_name to libged.
   - QEll migrated to bv_view_obj_overlay_create + bsg_view_obj_illum_by_name.

5. Phase D — final cleanup (complete except bview::independent):
   - Removed BV_MESH_LOD and BV_CSG_LOD flag bits.
   - Removed BV_VIEW_OBJS auto-routing from bv_obj_get.
   - Removed BV_VIEW_OBJS branch from bv_view_objs (replaced by bv_view_obj_visit).
   - Removed view_obj_cache from bview_objs and shared_view_obj_cache from
     bview_set_internal.
   - Migrated bv_autoview and bv_clear to bv_view_obj_visit.
   - Migrated dm_draw_viewobjs view-only rendering to bv_view_obj_visit.
   - bview::independent deferred: still read/written in libbv, libqtcad, mged.

6. Phase B — backend default decision (done in previous session;
   re-implemented in this session; see "Completed this session" below).

Completed this session
----------------------

Phase B — backend default decision  DONE (2026-05-08)

Policy:
- qged default backend: dm-qtgl (hardware OpenGL via QgGL widget) when
  BRL-CAD is built with OpenGL support.  Falls back to dm-swrast when the
  user passes -s / --swrast or when BRL-CAD is built without OpenGL support.
- mged / legacy applications: dm-bestXType selects from {wgl, ogl, X} via
  the priority_list in src/libdm/dm_plugins.cpp.  dm-qtgl is intentionally
  absent because it requires a Qt widget context only qged provides.

What was done:

### B1 — codify qged default backend
- src/qged/QgEdApp.cpp: replaced the implicit `swrast_mode` pass-through
  with an explicit canvas_type selection:
    #ifdef BRLCAD_OPENGL
        canvas_type = swrast_mode ? QgView_SW : QgView_GL;
    #else
        canvas_type = QgView_SW;
    #endif
  Documented rationale in a comment block above the selection.

### B2 — codify mged / libdm default path
- src/libdm/dm_plugins.cpp: added a block comment above priority_list
  explaining why dm-qtgl and dm-swrast are absent, and documenting the
  --dm-type swrast flag for headless mged use.

### B3 — dm backend benchmark test
- src/libqtcad/tests/ged_test_dm_backend_bench.cpp: new file.
  Times dm_draw_objs throughput via the QgSW (dm-swrast) widget path.
  The dm-qtgl section requires hardware OpenGL; it is skipped gracefully on
  headless / CI machines.  Exit status is always 0 (benchmark, not pass/fail).
- src/libqtcad/tests/CMakeLists.txt: added build/registration for the test.
