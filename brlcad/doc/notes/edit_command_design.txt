libged `edit` Command — Design Notes
======================================

Status:  Phase 3 complete.
Date:    2026-04-30


Overview
--------

This note captures the design contract for the new libged `edit` command that
replaces (via `gedp->new_cmd_forms == 1`) the legacy edit.c implementation.
The goal is MGED-class command-line editing driven exclusively by the librt
editing APIs and the `ft_edit_desc()` descriptor tables, with no primitive-
specific knowledge hard-coded in libged.


Architecture
------------

Two-layer command surface
~~~~~~~~~~~~~~~~~~~~~~~~~

  1. Generic layer (hand-written in libged):
       edit <geom> rotate   [-k] [-a|-r] [-c] [-O] [-n] [-o] [-d] [-R] ...
       edit <geom> translate [-k] [-a|-r] [-x|-y|-z] ...
       edit <geom> tra      (alias: translate -r)
       edit <geom> scale    [-k] [-a|-r] [-c] [-x|-y|-z] ...
       edit <geom> perturb  <factor>
       edit <geom> mat      <4x4 matrix>
       edit <geom> checkpoint
       edit <geom> revert
       edit <geom> reset

     These are valid for ALL geometry types (primitives and combs).
     They use only `RT_PARAMS_EDIT_*` and `RT_MATRIX_EDIT_*` ops.

  2. Per-primitive layer (descriptor-driven, built at runtime):
       edit <geom> <op>     [param ...]
       edit <type>          (prints per-type help, grouped by category)
       edit <type> --list-ops  (emits rt_edit_type_to_json() output)

     The subcommand tree is built entirely from `ft_edit_desc()` returns —
     NO primitive-specific code exists anywhere in libged.


Single source of truth
~~~~~~~~~~~~~~~~~~~~~~

  librt is the canonical source for:
    - Which operations a primitive supports  (EDOBJ / ft_edit_desc)
    - What parameters each operation requires  (rt_edit_cmd_desc / params[])
    - How to execute an operation  (rt_edit_process + functab callbacks)
    - How to serialise the descriptor  (rt_edit_prim_desc_to_json)

  libged responsibilities:
    - Parse the command line once into ged_edit_ctx
    - Resolve geometry specifiers (URI, path, selection fallback)
    - Arbiter of selection conflicts (see below)
    - Maintain the temp edit buffer
    - Translate ged_edit_ctx into rt_edit calls and write results to disk


Execution engine
~~~~~~~~~~~~~~~~

  For each operation, libged:
    1. Resolves geometry to a db_full_path.
    2. Looks up or creates an rt_edit * for the path (from temp buffer or new).
    3. Sets edit_flag via rt_edit_set_edflag().
    4. Fills e_para[] and/or e_str[] with parsed argument values.
    5. Calls rt_edit_process().
    6. Unless -i (intermediate), calls rt_db_put_internal() and DbiState::update().

  For matrix editing (rotate / translate / scale on combs or as matrix ops):
    - Uses RT_MATRIX_EDIT_ROT / RT_MATRIX_EDIT_TRANS_MODEL_XYZ /
      RT_MATRIX_EDIT_SCALE{,_X,_Y,_Z}.

  For solid parameter editing (descriptor-driven):
    - Sets edit_flag = cmd_desc->cmd_id and fills params per param_desc specs.


Geometry specifier grammar
~~~~~~~~~~~~~~~~~~~~~~~~~~

  Specifiers are resolved left-to-right before dispatch.  Each specifier
  can be:

    a) bare name:         sph.s
    b) path:              all.g/platform.r/sph.s
    c) quoted name:       "my-obj"    (allows names containing dashes)
    d) URI with fragment: sph.s#V1   (feature key: vertex/edge/face)
    e) URI with query:    sph.s?V*   (wildcard multi-feature)
    f) dot:               .          (batch marker — each listed object)

  If no specifier is given on the command line, the active selection set
  ("default") is used.  If both an explicit specifier and an active
  non-empty selection exist for the same object, the command aborts with
  an actionable message unless one of these flags is set:

    -S   operate on the selection, ignoring command-line specifier
    -f   force: apply the operation, write to disk, clear conflict
    -F   abandon: discard intermediate state, start from on-disk state
    -i   intermediate: apply to temp buffer only, do not write to disk

  The -f/-F/-i trio maps onto MGED's apply/reset/in-progress semantics.


Temp edit buffer
~~~~~~~~~~~~~~~~

  A per-gedp map (path_hash → rt_edit *) survives across command
  invocations within a session.  The buffer API is in ged_private.h:

    ged_edit_buf_get(gedp, &dfp)       -> rt_edit * (or NULL)
    ged_edit_buf_set(gedp, &dfp, s)    -> store/replace entry
    ged_edit_buf_promote(gedp, &dfp)   -> write to disk, remove entry
    ged_edit_buf_abandon(gedp, &dfp)   -> rt_edit_destroy, remove entry
    ged_edit_buf_flush(gedp)           -> promote all entries

  This allows multi-step CLI edits (multiple relative rotates, etc.)
  without a disk write per step, which is important for large BoT objects.

  Lifecycle rules:
    - rt_edit_reset()  when reinitialising for a new object (reuses struct)
    - rt_edit_destroy() on db close or explicit -F abandon
    - rt_edit_reinit()  when reloading after external disk change


edit.c feature spec (implemented in Phase 2)
--------------------------------------------

  The following is the complete grammar inherited from edit.c.  Every
  feature listed here MUST be covered by a test in src/libged/tests/edit/.

  Coordinate flags (per-axis modifiers)
  ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

    -x val     Use only the X component of the following argument
    -y val     Use only the Y component
    -z val     Use only the Z component
    (no flag)  Use all three components (X, Y, Z) from the next tokens

  edit_arg types
  ~~~~~~~~~~~~~~

    *_FROM     keypoint: source of reference vector / axis
    *_TO       target:   where we want to end up
    *_POS      coordinate literal {x [y [z]]} or per-component -x/-y/-z
    *_OBJECT   an existing object in the database

    Modifier flags on *_TO:
      -a    interpret as absolute position (default for *_TO_OBJECT)
      -r    interpret as relative distance from FROM (default if no FROM)
      -d    interpret as relative degrees (ANGLE_TO only, default)
      -R    interpret angles in radians (rotate only)

    Object flags:
      -n    use natural origin of the object instead of bbox centre
      .     each operation uses the object itself as its own reference

  rotate subcommand grammar
  ~~~~~~~~~~~~~~~~~~~~~~~~~

    rotate [-R] [AXIS] [CENTER] ANGLE OBJECT ...
    rotate [-R] [[AXIS_FROM] AXIS_TO] [CENTER] [ANGLE_ORIGIN]
               [ANGLE_FROM] ANGLE_TO OBJECT ...

    Options:
      -R                  interpret ANGLE_TO as radians
      -c CENTER           centre of rotation (default: bbox centre of 1st OBJECT)
      -O ANGLE_ORIGIN     origin of ANGLE (default: CENTER)
      -k AXIS_FROM        keypoint for axis (default: origin 0,0,0)
      -a AXIS_TO          AXIS_TO as absolute position (required with *_OBJECT)
      -r AXIS_TO          AXIS_TO as relative distance from AXIS_FROM
      -d ANGLE_TO         ANGLE_TO as relative degrees (default)
      -o                  override AXIS constraint (deg/rad rotate)
      -n *_FROM|*_TO      use natural origin of the given object
      -k ANGLE_FROM       keypoint for angle reference
      -a ANGLE_TO         ANGLE_TO as absolute position
      -r ANGLE_TO         ANGLE_TO as relative distance

    Test coverage required:
      rotate -z 45 cube                       (z-axis, 45 deg from bbox centre)
      rotate 0 0 45 cube                      (same, positional syntax)
      rotate -c 0 0 0 -d 0 0 45 cube         (explicit centre, explicit deg)
      rotate -c cube 0 0 45 cube             (centre from bbox)
      rotate -c . 0 0 45 cube                (each object its own centre)
      rotate -k sphere1 -a sphere2 cube      (axis from obj to obj)
      rotate -c . -x 25 -d 180 cube          (180 deg about offset axis)
      rotate -a 180 cube -x 25              (preferred form)
      rotate 90 cube                          (unconstrained single-angle)
      rotate -45 45 cube                      (two-angle)
      rotate -R ...                           (radian form)
      rotate 180 cube  (ambiguous, should fail)

  translate subcommand grammar
  ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

    translate [[FROM] TO] OBJECT ...
    translate [[-n] -k {FROM_OBJECT | FROM_POS}]
              [-n] [-a | -r] {TO_OBJECT | TO_POS}
              OBJECT ...

    Options:
      -k FROM     keypoint for translation (default: bbox centre of 1st OBJECT)
      -a TO       TO as absolute position
      -r TO       TO as relative distance from FROM (default if no FROM)
      -n          use natural origin

    tra OBJECT X Y Z  is an alias for:  translate -r OBJECT X Y Z

    Test coverage required:
      translate -a 10 0 0 sph.s     (abs move to (10,0,0))
      translate -r  5 0 0 sph.s     (rel move +5 in X)
      tra 5 0 0 sph.s               (same as translate -r)
      translate -k sph.s -a other.s sph.s   (from-to object form)

  scale subcommand grammar
  ~~~~~~~~~~~~~~~~~~~~~~~~

    scale [SCALE] [CENTER] FACTOR OBJECT ...
    scale [[SCALE_FROM] SCALE_TO] [CENTER] [FACTOR_FROM] FACTOR_TO OBJECT ...

    Options:
      -k SCALE_FROM   reference scale from-point (default 0,0,0)
      -a SCALE_TO     reference scale to-point as absolute
      -r SCALE_TO     reference scale to-point as relative
      -c CENTER       centre of scaling (default: bbox centre of 1st OBJECT)
      -n              natural origin

    Test coverage required:
      scale 2 cube              (uniform 2x from bbox centre)
      scale 2 2 2 cube          (same, explicit xyz factor)
      scale -k 0 0 0 -a 2 2 2 cube
      scale -k 0 0 0 -a 1 1 1 -c . -r 2 cube
      scale -k 5 10 15 -a 7 11 -2 -r 4 2 34 cube

Implementation Phases
---------------------

Phase 0 (DONE): Survey, freeze, harness
  - This document
  - Descriptor audit (above)
  - Test directory src/libged/tests/edit/ with fixture and runner
  - 46/46 assertions pass (ctest -R ged_test_edit_phase0)

Phase 1 (DONE): Parser foundation
  - ged_edit_ctx struct replacing struct edit_info
  - Three-pass parser: global opts → geometry specifiers → subcommand+args
  - URI fragment/query parsing, . batch marker, selection fallback
  - Selection conflict arbiter
  - Temp edit buffer API (ged_edit_buf_*)
  - 21/21 assertions pass (ctest -R ged_test_edit_phase1)

Phase 2 (DONE): Generic transform commands
  - translate / tra / rotate / scale / perturb / mat / checkpoint / revert / reset
  - Full option grammar: -a/-r/-x/-y/-z/-k/-d/-c/-R/-O
  - _edit_xform_apply() helper managing temp buffer + disk promotion
  - 48/48 assertions pass (test_edit.cpp section 2)

Phase 3 (DONE): Descriptor-driven per-primitive editing
  - CLI slug derivation: "Set Radius 1" → "set_radius_1" (_prim_cmd_slug)
  - Param-name alias for single-param commands: "r1" → ECMD_TOR_R1
  - _exec_desc_cmd_on_edit(): per-param-type bu_opt converters fill e_para[]/e_str[]
  - _exec_desc_cmd(): wraps via _edit_xform_apply (buffer + disk promotion)
  - _find_desc_cmd(): slug, param-name, and case-insensitive label matching
  - 'edit <type>' → category-grouped help (_print_prim_help)
  - 'edit <type> --list-ops' → rt_edit_type_to_json() JSON output
  - 'edit <geom> <unknown_op>' → per-primitive error + type help
  - All supported param types: SCALAR, INTEGER, BOOLEAN, ENUM, POINT, VECTOR,
    COLOR, MATRIX, STRING
  - 22 new Section 3 assertions in test_edit.cpp (217/217 total pass)

Phase 4: Descriptor completeness backlog
  - Extend rt_ecmd_scanner.cpp to detect undescribed ECMDs
  - Fill missing descriptors per the priority list above

Phase 5: Auto-generated mann pages
  - rt_edit_doc_gen.cpp linked against librt
  - Generates edit_<type>.adoc per primitive from descriptors
  - Hooked into docs/asciidoc CMakeLists

Phase 6: Flip default and retire edit.c
  - gedp->new_cmd_forms defaults to 1
  - Legacy path kept behind env var for one release
  - Remove old C helper files once parity confirmed


Key risks
---------

  1. edit.c semantics are subtle (axis/angle constraints, 180 ambiguity,
     -k/-a/-r/-d/-o interactions).  Phase 2 MUST start from a golden
     transcript of the edit.c EXAMPLES block verified against the legacy
     binary BEFORE implementing the new path.

  2. Descriptor quality varies.  Phase 4 is a backlog, not a blocker for
     Phase 3.  Primitives without descriptors still get generic transform
     operations.

  3. Temp edit buffer ownership.  rt_edit_destroy() must be called on
     session close; rt_edit_reset()+rt_edit_reinit() for reload scenarios.
     Tests must cover db-close and ged_open reuse.

  4. ABI instability.  rt_edit_prim_desc is explicitly marked experimental
     in rt/edit.h.  Any struct additions for Phase 5 (e.g., example field)
     must append-only.
