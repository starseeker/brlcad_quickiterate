CHANGES Cleanup Plan (pre-7.40 entries)
=======================================

Scope decisions
---------------
- Do now: low + medium disruption items.
- Defer for later: high-disruption items and struct hit.hit_point / hit_normal.
- Defer explicitly: ~/.density handling.


Low disruption

    include/vmath.h: remove VCOMB3, VCOMB3N, VJOIN4; no source uses found outside definitions.
    nmg_model_break_e_on_v: replacement nmg_break_e_on_v exists and old function is a wrapper.
    src/tclscripts/mged/bots.tcl: likely standalone Tcl removal plus install list/docs cleanup.

Medium disruption

    MGED E command: replacement drawing mode exists, but command registration, docs, tests, and aliases must be cleaned carefully.
    Distillation-era MGED/libged commands still present, including db_glob, debugbu, debugdir, debuglib, debugnmg, match, preview, regdef, rrt, savekey, shaded_mode, sync, etc.
    Image/signal tools: at least alias-pix, asc2pix, bw-a, and double-asc still build; verify icv/cv replacement coverage before removing binaries/docs/tests.
    BU_PTBL_* macros: many internal uses remain; replace internal usage first, then remove public macros.
    XDR byte-order API and db4 matrix conversion functions: replacements exist, but internal uses remain.
    rt_prep_timer / rt_get_timer: many internal uses remain; migrate to bu_timer / bu_elapsed.

High disruption

    Legacy MGED commands replaced by rm, search, comb, debug, edit, nirt, push: replacements exist, but aliases are broadly registered and may be used by Tcl scripts/tests.
    Tcl classes Mged, Database, Db, Dm, Drawable, Display, QuadDisplay, View: still present; replacing with Ged is likely broad GUI/Tcl work.
    bspline, poly, hf, and FASTGEN4 CLINE: still wired into librt primitive tables, headers, tests, and conversion paths.
    RT_DBHASH / RT_DBNHASH: still used in public headers and librt internals; requires privatization strategy.
    rt_comb_internal fields and reserved attribute migrations: behavior-sensitive database compatibility work.

IMPORTANT - update CHANGES file per standard policy whenever a deprecated feature is retired.

Validation approach
-------------------
- Build touched targets after each batch.
- Run focused tests for modified areas (libged/mged tests for command-surface changes).
- Keep behavior-preserving changes small and reviewable.

Deferred list
--------------------------
- struct hit.hit_point / struct hit.hit_normal removal.
- High-disruption primitive/database compatibility removals.
- ~/.density deprecation follow-up.
