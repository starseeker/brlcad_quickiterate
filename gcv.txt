Key findings


libged/facetize contains the robust logic:

CLI option handling in brlcad/src/libged/facetize/facetize.cpp

state/options in ged_facetize.h

Manifold boolean evaluation and fallback orchestration in tri.cpp

NMG path in nmg.cpp

region replacement logic in regions.cpp

fault-tolerant subprocess primitive tessellation in facetize/subprocess/main.cpp



libgcv currently has only a simpler gcv_facetize() in brlcad/src/libgcv/facetize.c, using NMG boolean evaluation and nmg_bot.

libgcv writers such as STL, OBJ, PLY, VRML, and assetimport still mostly walk trees with rt_booltree_leaf_tess and gcv_region_end, so they do not benefit from facetize’s Manifold, method fallback, perturb, fixup, timeout, or subprocess recovery behavior.

gcv CLI currently has only input/output/both option buckets (-I, -O, -B) and does not model conversion as a scoped pipeline.


Proposed rework

1. Move facetize’s functional core into libgcv

Create a new public API family, for example:



include/gcv/facetize.h

src/libgcv/facetize/


Move the non-GED-specific implementation from libged/facetize into libgcv:



primitive tessellation method handling

method option parsing/description

working-copy setup

subprocess supervision and timeout recovery

primitive fallback sequence: NMG → CM → SPSR

plate BoT handling

BRep CSG fallback

Manifold boolean evaluation

optional NMG boolean evaluation

perturb variant planning

BoT fixup

region-by-region output mode

empty-output handling

logging/progress summaries


Exclude the legacy old_facetize path.


2. Define a real libgcv facetization API

Introduce a durable options struct, not a GED command state struct:



output mode:

single BoT

per-region BoTs

NMG output where needed

in-place database replacement

write-to-target database



primitive conversion methods:

ordered method list

per-method option map

default/fallback policy



boolean evaluation:

Manifold default

optional NMG boolean evaluation

future boolean engines via registry



fault tolerance:

subprocess enabled/disabled

max time

per-method max time

resume/cache directory/log file



quality controls:

no-empty

disable-fixup

perturb/no-perturb

perturb volume/surface-area thresholds

max sampled points



callbacks:

logging

progress

cancellation

method-result reporting




Expose APIs along these lines:



gcv_facetize_opts_default

gcv_facetize_methods

gcv_facetize_method_options

gcv_facetize_objects

gcv_facetize_regions

gcv_facetize_to_bot

gcv_facetize_to_db

gcv_facetize_describe_options


3. Add extensible method registries

Avoid hard-coding NMG/CM/SPSR permanently.


Define registries for:



primitive conversion methods

boolean evaluators

post-process/fixup steps


Each method should publish:



stable name

description

option descriptors

supported primitive/data classes

cost/quality/fallback ranking

whether subprocess isolation is recommended

whether it can consume point samples

whether it can repair/convert existing BoTs

whether it is deterministic/resumable


This prepares libgcv for future primitive conversion and boolean evaluation methods.


4. Keep subprocess isolation, but move ownership to libgcv

The current ged_exec facetize_process pattern is important for robustness.


Refactor it into a libgcv-owned worker, e.g.:



gcv_facetize_process

or a libgcv subprocess plugin executable


The parent libgcv API should own:



command construction

timeout enforcement

backup/restore of working .g

stdout/stderr forwarding

failure bisection

per-method fallback retry


libged should no longer know about this machinery.


5. Make libged facetize a thin wrapper

After the libgcv API exists, keep the current GED command behavior by mapping existing options into gcv_facetize_opts.


libged/facetize/facetize.cpp should retain:



user-facing command name

current option names and semantics

GED help output

result-string reporting

database read-only checks

object-name validation

compatibility with current workflows


But it should call libgcv for actual work.


6. Update libgcv plugins to use the shared facetizer

Replace direct NMG tree-walk tessellation in mesh writers with a common libgcv mesh-production stage.


Affected writers include:



STL

OBJ

PLY

VRML

assetimport

fastgen4 where applicable


Instead of each plugin doing its own db_walk_tree + rt_booltree_leaf_tess + gcv_region_end, they should request meshable geometry from libgcv:



default: auto facetize CSG to BoT/triangles

advanced: honor caller-selected facetize options

fallback: try next method/plugin if facetization or writing fails


This gives all mesh outputs the same robust tessellation path as GED facetize.


7. Model gcv as a scoped pipeline

Extend gcv_context to represent:


read → [process stages] → write


Default behavior:



gcv in.ext out.ext still works

if writing a mesh format from CSG, automatically insert facetize


Add stage scopes:



in

out

facetize

future scopes such as decimate, repair, validate


Command-line examples conceptually become:



gcv model.g model.stl

gcv --facetize.methods=NMG,CM,SPSR model.g model.obj

gcv --facetize.max-time=60 model.g model.stl

gcv --out.binary model.g model.stl

gcv --in.format=stl --out.format=g input output


8. Improve plugin/stage self-description

Extend struct gcv_filter or introduce struct gcv_stage metadata so every stage can report:



plugin name

stage type

formats supported

readable/writable capabilities

option descriptors

option scope

aliases

fallback priority

support score for a given file/data type


This enables:



gcv --list-formats

gcv --list-plugins

gcv --describe facetize

gcv --describe out:stl

gcv --find-option max-time


9. Migration order


Add libgcv facetize public option structs and metadata APIs.

Move method-option parsing and method descriptions from libged into libgcv.

Move subprocess primitive tessellation into libgcv.

Move Manifold boolean evaluation into libgcv.

Move region/single-object orchestration into libgcv.

Convert GED facetize to a compatibility wrapper.

Add a libgcv pipeline/process-stage API.

Teach mesh writers to consume the new facetize stage.

Update gcv CLI to use scoped pipeline options.

Add regression tests comparing GED facetize output behavior before/after.

Add failure-mode tests for subprocess timeout and fallback.

Add CLI tests confirming:
