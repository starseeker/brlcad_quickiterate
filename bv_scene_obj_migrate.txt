BV_SCENE_OBJ TO BSG COMPLETION PLAN
===================================

Purpose
-------
This document tracks the remaining work to remove `struct bv_scene_obj` as the
scene-graph backing store and complete the cutover to first-class libbsg data
structures and APIs.  It intentionally focuses on remaining work only; previous
phase execution logs have been collapsed into the current-state summary below.

Backwards compatibility is not a constraint for this effort.  Compatibility
helpers may be used as short-lived migration tools, but the target is deletion of
`bv_scene_obj`, not long-term preservation of a wrapper.  Removing or shrinking
libbv scene-object functionality in favor of libbsg ownership is approved when it
produces a cleaner result.

Target End State
----------------
- `bsg_node` is allocated, owned, traversed, mutated, and destroyed by libbsg.
- Scene-graph semantics live in BSG-owned concepts:
  - node identity and source metadata
  - parent/child structure
  - transform and bounds
  - material and appearance
  - payload/vlist data
  - selection/highlight state
  - view/edit context
  - renderer/backend attachments
  - lifecycle callbacks
- libdm, libged, qged, mged, libqtcad, libtclcad, librt, and libanalyze consume
  BSG APIs instead of `bv_scene_obj` storage.
- `bsg/defines.h` no longer includes `bv/defines.h`.
- `include/bv/defines.h` no longer defines scene-graph node storage.
- `struct bsg_settings` is either deleted as a public structure or reduced to an
  internal import/export snapshot synthesized from material, appearance, and draw
  policy state.

Current State Summary
---------------------
Completed groundwork:
- `struct bsg_settings` was moved out of `include/bv/defines.h` into
  `include/bsg/settings_types.h`.
- BSG settings sidecars (`settings_local`, `settings_effective`) now live on
  `struct bsg_node` and are the authoritative compatibility storage for settings
  flows.
- Appearance, material, draw policy, payload, view, backend, callback,
  parent/child, bounds, transform, visibility, force-draw, and legacy highlight
  accessors exist for most formerly raw `bv_scene_obj` fields.
- BSG lifecycle entry points exist:
  - `bsg_node_create()`
  - `bsg_node_create_child()`
  - `bsg_node_clear_children()`
  - `bsg_node_destroy()`
- Major libbsg draw-tree allocation and teardown paths already route through the
  BSG lifecycle boundary.
- Phase A is complete: `struct bsg_node` and BSG node constants now live in
  BSG-owned headers, and `include/bsg/defines.h` no longer includes
  `include/bv/defines.h`.
- Phase B is complete: non-compat libbsg headers now expose `bsg_node *`
  rather than `struct bv_scene_obj *`, and the remaining legacy conversions are
  isolated in `include/bsg/compat.h` / `src/libbsg/compat.c`.
- `struct bv_scene_obj` still embeds `struct bsg_node` as its first member;
  that first-member compatibility layout is now the central structural blocker.

Current Structural Blockers
---------------------------
1. `struct bv_scene_obj` still embeds `struct bsg_node` and many legacy fields.
2. Legacy libbv/libged/mged boundary APIs still name `struct bv_scene_obj *`
   outside the non-compat libbsg surface.
3. Some subsystems still use direct `bv_scene_obj` field access for data that has
   not yet been physically moved to BSG-owned sidecars.

Implementation Plan
-------------------

Phase A - Move the Core BSG Type Out of libbv
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Objective: make BSG headers able to define and consume `bsg_node` without
including `bv/defines.h`.

Work:
- Create a BSG-owned core type header for `struct bsg_node` and node constants.
- Move the current `struct bsg_node` definition and BSG node constants from
  `include/bv/defines.h` / `include/bsg/defines.h` into BSG-owned headers.
- Update `include/bsg/defines.h` to stop including `bv/defines.h`.
- Change `include/bv/defines.h` to include the BSG core type only for the
  temporary `bv_scene_obj` embedding.
- Keep `struct bv_scene_obj { struct bsg_node bsg; ... }` temporarily so the
  first-member compatibility cast still works during following phases.

Exit criteria:
- libbsg public headers no longer depend on `bv/defines.h`.
- libbsg builds when only BSG headers are included by BSG users.

Phase B - Stop Exporting `bv_scene_obj` from BSG APIs
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Objective: make BSG APIs type-clean before changing storage layout.

Work:
- Convert public libbsg signatures from `struct bv_scene_obj *` to `bsg_node *`.
- Move unavoidable legacy conversion helpers into an explicitly named temporary
  compatibility header/source pair.
- Update libged/libdm/libqtcad/libtclcad callers that are already semantically
  using BSG nodes to hold `bsg_node *` locally.
- Keep casts only at old libbv/libged/mged API boundaries that still expose
  `struct bv_scene_obj *`.

Exit criteria:
- Non-compat libbsg headers do not mention `struct bv_scene_obj`.
- New code can include BSG headers and use BSG nodes without pulling in libbv
  scene-object definitions.

Status (2026-05-21):
- Complete.
- Non-compat public libbsg headers use `bsg_node *` only.
- Temporary legacy handle conversions live in `include/bsg/compat.h` and
  `src/libbsg/compat.c`.
- Remaining `struct bv_scene_obj *` API exposure is confined to compatibility
  and older non-BSG boundaries scheduled for later phases.

Phase C - Move Remaining Storage Semantics to BSG Sidecars
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Objective: leave `bv_scene_obj` with no unique semantic ownership.

Work by storage cluster:
1. Settings and appearance mirrors
   - Delete authoritative use of `s_os`, `s_local_os`, and `s_inherit_settings`.
   - Make compatibility snapshot APIs synthesize from BSG sidecars only.
   - Move remaining `s_soldash`, `s_arrow`, and `s_old` draw-style users to
     `bsg_appearance`, `bsg_material`, selection/highlight, or deletion.
2. Payload and vlist storage
   - Move `s_vlist` and `s_vlen` ownership into BSG payload storage.
   - Convert mged, libtclcad, librt, libanalyze, and residual libged callers to
     `bsg_node_vlist_*` or typed payload APIs.
   - Delete direct reuse-list assumptions from callers; keep allocation policy in
     payload/lifecycle code.
3. Source/app metadata
   - Replace direct `dp` and `s_path` usage with a typed BSG source/context API.
   - Separate database object identity (`struct directory *`, path) from arbitrary
     caller app data.
   - Convert bot/brep/nmg/edit paths, QgModel, mged ray/display paths, and draw
     update code one cluster at a time.
4. Material and revision mirrors
   - Move residual `s_color` and `s_color_rev` users to `bsg_material` and BSG
     node revision APIs.
   - Remove legacy color mirrors after render/export/report paths no longer read
     them.
5. Bounds and display state
   - Move `s_size`, `s_center`, `bmin`, `bmax`, `have_bbox`, `s_bbox_cached`,
     `s_drawn_rev`, and `s_displayobj` scene-node uses to BSG bounds/render
     state.
   - Audit same-named non-scene fields separately before broad replacement.
6. View/backend/callback state
   - Move remaining `s_v`, `s_backend`, `s_update_callback`, and
     `s_free_callback` storage into BSG view context, renderer attachment, and
     payload lifecycle state.

Exit criteria:
- Direct field access in ordinary libdm/libged/qged/mged/libqtcad/libtclcad/
  librt/libanalyze code is gone.
- Any remaining direct access is isolated to a temporary compatibility source file
  with deletion notes.

Phase D - Make BSG Allocation Independent of libbv Free Lists
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Objective: make BSG lifecycle own memory, not just wrap `bv_obj_*`.

Work:
- Implement real BSG allocation/free internals for `bsg_node` and BSG sidecars.
- Move child tables, payload teardown, backend cleanup, callback cleanup, and
  bounds/material/appearance release fully under `bsg_node_destroy()`.
- Change `bv_obj_create()`, `bv_obj_reset()`, and `bv_obj_put()` into temporary
  wrappers around BSG allocation/lifecycle or delete them where callers have
  moved to BSG.
- Remove libbsg calls into libbv allocation/reset utilities.

Exit criteria:
- BSG nodes can be created and destroyed without allocating a `bv_scene_obj`.
- libbsg no longer depends on libbv lifecycle implementation.

Phase E - Collapse or Delete libbv Scene-Object APIs
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Objective: remove libbv as a scene-graph storage layer.

Work:
- For each libbv scene-object API, choose one outcome:
  - move implementation to libbsg and update callers;
  - keep a non-scene libbv utility if it is genuinely view/math related;
  - delete it.
- Replace `bv_scene_obj` object tables and view-object helpers with BSG scene/set
  and traversal APIs.
- Move reusable vlist/free-list mechanics into BSG payload code or BU-level
  utilities if still needed.
- Remove `include/bv/defines.h` scene-object storage from public use.

Exit criteria:
- libbv no longer defines the scene-object storage type.
- libbv no longer owns allocation, reset, traversal, or payload storage for scene
  nodes.

Phase F - Remove the First-Member Compatibility Cast
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Objective: end the `bsg_node *` / `bv_scene_obj *` equivalence.

Work:
- Remove `struct bsg_node bsg;` embedding from the retired compatibility storage.
- Delete conversion macros/helpers that depend on first-member layout.
- Replace old public signatures that still name `struct bv_scene_obj *` with
  `bsg_node *` or higher-level BSG/scene-set types.
- Delete temporary compatibility source/header files.

Exit criteria:
- The tree builds with no `struct bv_scene_obj` definition.
- `rg "bv_scene_obj" brlcad/include brlcad/src` finds only historical comments,
  removed-migration notes, or no matches.

Phase G - Retire Transitional Settings and Compatibility APIs
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Objective: remove migration scaffolding after storage cutover.

Work:
- Delete public `struct bsg_settings` if all callers use appearance/material/draw
  policy APIs.
- If import/export compatibility still needs settings snapshots, make the type
  private to libbsg or a command adapter.
- Delete redundant sync/reset/hash helpers that existed only to keep old storage
  mirrors coherent.
- Remove old highlight/material/appearance compatibility shims once final BSG
  selection and render-state APIs are in use.

Exit criteria:
- Public scene-graph state is expressed only through BSG APIs and BSG-owned data
  structures.

Suggested Remaining Work Slices
-------------------------------
1. Payload/vlist ownership slice:
    - Move vlist storage into BSG payload sidecars.
    - Convert residual mged/libtclcad/librt/libanalyze direct users.
    - Validate mged draw tests, BSG draw tests, and qged swrast.
2. Source metadata slice:
    - Add typed BSG source/app context APIs that replace direct `dp` and `s_path`.
    - Convert bot/brep/nmg/edit/QgModel/draw-update users by subsystem.
    - Validate affected libged command tests and qged model/view tests.
3. Material/appearance/bounds mirror deletion slice:
    - Remove residual color, style, bbox, size, display-object, and draw-revision
      mirrors from ordinary callers.
    - Validate libdm render paths and export/report commands.
4. Lifecycle independence slice:
    - Replace `bv_obj_*` internals with BSG allocation/free.
    - Delete free-list ownership from libbv scene-object code.
    - Validate all BSG lifecycle tests plus libged draw-root tests.
5. Final deletion slice:
    - Remove `struct bv_scene_obj` and compatibility casts.
    - Rename or remove obsolete libbv APIs.
    - Run full Qt-enabled draw-stack validation.

Decision Rules
--------------
- Prefer BSG-native ownership over compatibility preservation.
- Do not add new APIs that expose `bv_scene_obj` layout.
- Convert one storage cluster at a time, but delete compatibility storage as soon
  as its last caller moves.
- If a libbv scene-object helper is only forwarding to BSG, move callers to BSG
  and delete the helper.
- If a libbv feature is really a renderer/view utility rather than scene storage,
  keep or relocate it without retaining `bv_scene_obj` coupling.
