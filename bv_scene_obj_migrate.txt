BV_SCENE_OBJ TO LIBBSG COMPLETION PLAN
======================================

Purpose
-------
This file tracks the remaining work needed to eliminate `struct bv_scene_obj` as
BRL-CAD's scene-graph data model and replace it with first-class, idiomatic
libbsg scene graph code and containers.

This is not a minimalist field move.  The target is a fundamental data-model
cutover:

- libbsg owns scene nodes, scene containers, traversal, typed payloads,
  per-node state, renderer attachments, lifecycle, and scene-level policies.
- libbv remains a view/math/vlist utility library and may provide temporary
  compatibility adapters, but it does not own scene graph storage or public
  scene semantics.
- Consumer code uses BSG concepts directly instead of depending on the
  historical `bv_scene_obj` layout, first-member casts, or libbv object tables.
- When a compatibility path becomes a thin wrapper over BSG, callers move to BSG
  and the wrapper is deleted rather than preserved indefinitely.

Scope Snapshot
--------------
Snapshot date: 2026-05-21.

A literal scan of non-generated `.c`, `.cpp`, `.h`, and `.hpp` files under
`brlcad/include` and `brlcad/src` finds 1474 `bv_scene_obj` mentions across 149
files.  This is close enough to the reported ~1550-use estimate to confirm that
the remaining work is broad architectural replacement, not a single mechanical
rename.

Largest current hotspots by literal mention count:

| `src/libbv/util.cpp` | 191 | legacy allocation/reset/object-table/backend utility hub |
| `src/libged/bsg_ged_draw.c` | 130 | draw-tree production, legacy draw objects, GED data bridging |
| `src/libbsg/node.c` | 73 | BSG accessors still backed by legacy storage/casts |
| `include/bv/util.h` | 57 | public libbv scene-object API surface |

| `src/libged/dbi_state.cpp` | 45 | draw database/object state synchronization |

| `include/bv/defines.h` | 35 | legacy storage definition itself |
| `src/libbsg/draw_set.c` | 33 | BSG draw-set code still touching compatibility storage |

The raw count includes forward declarations, comments, tests, compatibility
code, and legitimate old API boundaries.  Treat it as a scope signal, not as a
one-to-one list of required edits.  Each phase below must classify references as
one of:

1. delete immediately;
2. replace with an existing BSG concept;
3. replace after a missing BSG container/API is introduced;
4. keep only inside a short-lived, explicitly named compatibility adapter;
5. retain as non-scene libbv utility code after proving it no longer depends on
   `bv_scene_obj` storage.

Target End State
----------------
The final tree should have these properties.

- `bsg_node` is allocated, stored, parented, traversed, mutated, and destroyed by
  libbsg without embedding in or casting from `struct bv_scene_obj`.
- libbsg exposes scene-level containers, not only individual node accessors:
  - `bsg_scene` or equivalent root/scene owner;
  - scene object sets for database objects, view-only objects, local objects,
    overlays, selections, and render queues;
  - typed node containers and traversal/action APIs rather than caller-owned
    `bu_ptbl` tables of legacy objects.
- Node identity/source state is modeled as BSG source metadata:
  - stable node ID;
  - optional database directory/path identity;
  - optional instance/part identity;
  - optional caller-owned application context that is not confused with DB
    identity.
- Geometry is represented by typed BSG payloads:
  - vlist payloads;
  - polygon/label/axes/arrow overlay payloads;
  - LoD/adaptive-wireframe payloads;
  - evaluated shaded/render payloads;
  - future image/framebuffer payloads only after explicit design.
- Transforms, bounds, aggregate bounds caches, and drawn-frame stamps are BSG
  state, not fields on a libbv object.
- Material and appearance are separate BSG concepts.  Settings snapshots are
  private import/export compatibility data, not the authoritative draw model.
- Selection/highlight/illumination is a scene-level BSG selection model with
  compatibility mapping for old GED/MGED behavior.
- Renderer/backend attachments are BSG render resources keyed by backend tag,
  payload revision, and node revision rather than raw `s_backend` fields.
- Update/free callbacks are BSG payload lifecycle hooks with typed signatures.
- libdm, libged, mged, libtclcad/Archer, qged/libqtcad, librt, and libanalyze use
  BSG APIs and scene containers.
- `include/bv/defines.h` no longer defines scene-node storage.
- `include/bsg/*` does not include `bv/defines.h` for scene-node definitions.
- `rg "bv_scene_obj" brlcad/include brlcad/src` returns no active scene-graph
  implementation references.  Only historical release notes or removed-migration
  comments may remain.

Current Baseline
----------------
Completed groundwork already in the branch:

- `struct bsg_node` is a BSG-owned public type in `include/bsg/node_type.h`.
- `include/bsg/defines.h` no longer typedefs `bsg_node` to
  `struct bv_scene_obj`.
- `struct bv_scene_obj` embeds `struct bsg_node bsg` as its first member for the
  temporary compatibility layout.
- Non-compat public libbsg APIs generally use `bsg_node *`.
- Explicit conversion helpers live in `include/bsg/compat.h` and
  `src/libbsg/compat.c`.
- BSG accessors exist for many old fields: kind, name, parent/children,
  visibility, force draw, legacy illumination, transform, material, appearance,
  payload, vlist, bounds, drawn revision, user/GED data, backend, view, and
  callbacks.
- `bsg_node_create`, `bsg_node_create_child`, `bsg_node_clear_children`, and
  `bsg_node_destroy` exist and libbsg lifecycle tests exercise BSG-owned paths.

Remaining structural blockers:

1. `struct bv_scene_obj` is still the outer allocation for many nodes.
2. libbsg internals still include `bv/defines.h` and cast BSG nodes to
   `struct bv_scene_obj *` for missing storage.
3. libbv public APIs still expose `struct bv_scene_obj *` for allocation,
   lookup, view-object helpers, polygon helpers, vlist helpers, snapping, and
   object tables.
4. GED/MGED/libtclcad/qged/libqtcad/librt/libanalyze callers still pass old
   handles through many command and callback boundaries.
5. Tests still assert compatibility behavior using raw old handles in several
   draw-stack tests.
6. The remaining `bv_scene_obj` fields mix several different concepts in one
   struct, so they must be split into idiomatic BSG concepts before the struct
   can be deleted.

Replacement Work Plan
---------------------

Phase 0 - Establish the Live Inventory and Guardrails
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Objective: make remaining work measurable and prevent new dependencies while the
model is being replaced.

Work:
- Generate and check in a refreshed inventory that separates:
  - public API signatures naming `struct bv_scene_obj`;
  - direct field accesses;
  - first-member casts and `bsg_compat_*` use;
  - tests/comments/deprecation notes;
  - false positives from unrelated fields with the same names.
- Group every active reference by owning subsystem and target BSG concept:
  lifecycle, scene set, identity, payload, vlist, transform, bounds, material,
  appearance, selection, view context, renderer attachment, callback, or
  compatibility adapter.
- Add a lightweight developer check or documented command that fails on new
  active `bv_scene_obj` references outside the approved compatibility list.
- Mark remaining legacy APIs and direct-access fields as deprecated with a clear
  deletion phase, not as permanent supported APIs.

Exit criteria:
- The inventory explains every active reference category.
- New work has an obvious rule: add BSG APIs/containers, not new
  `bv_scene_obj` dependencies.

Phase 1 - Define the BSG Data Model Before Moving Storage
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Objective: replace the one-struct legacy object with explicit BSG-owned
containers and state types.

Work:
- Introduce the scene owner/container abstraction, tentatively `bsg_scene`, that
  owns roots, object sets, lifecycle, traversal invalidation, and scene-wide
  policies.
- Define BSG scene sets for database objects, view-only objects, local objects,
  overlays, selected nodes, and renderer-visible nodes.  These replace legacy
  `gv_objs`/`gv_view_objs`/object-table semantics rather than merely wrapping
  them.
- Define typed node state sidecars or inline-owned members for:
  - source metadata and DB identity;
  - transform and local/world bounds;
  - aggregate bounds cache and dirty propagation;
  - material and appearance;
  - payload and payload lifecycle;
  - view/edit context;
  - renderer attachments;
  - selection/highlight state;
  - draw/update revision counters.
- Decide which current concepts belong on a node, on a scene, on a payload, on a
  view, or on a renderer attachment.  Do not carry fields forward just because
  they existed on `bv_scene_obj`.
- Document ownership and invalidation rules for every new container before
  moving callers.

Exit criteria:
- libbsg has named containers for the major roles now hidden in
  `bv_scene_obj`, not only field-level accessors.
- Every legacy field has a target BSG concept or a deletion decision.

Phase 2 - Move Allocation, Ownership, and Scene Sets to libbsg
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Objective: make libbsg, not libbv, own node and scene lifetimes.

Work:
- Make `bsg_node_create` allocate standalone BSG node storage that is not a
  `struct bv_scene_obj` wrapper.
- Make `bsg_scene` own roots and node sets.  Parent/child mutation and object-set
  membership must update dirty flags and traversal caches in one place.
- Replace libbv object free-list ownership with BSG allocation pools or simple
  BU allocation, whichever best fits the final model.
- Convert `bv_obj_create`, `bv_obj_get`, `bv_obj_get_unregistered`,
  `bv_obj_reset`, and `bv_obj_put` into temporary adapters over BSG lifecycle or
  delete them as callers migrate.
- Move root/group/object table creation in GED draw setup to BSG scene
  construction.
- Remove assumptions that a node can discover all owner tables from fields such
  as `free_scene_obj`, `otbl`, and `vlfree`.

Exit criteria:
- BSG nodes and BSG scenes can be allocated, populated, traversed, and destroyed
  without allocating `struct bv_scene_obj`.
- libbsg lifecycle code no longer includes `bv/defines.h` for storage access.

Phase 3 - Replace Legacy Storage by Concept Cluster
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Objective: move data out of `bv_scene_obj` by semantic cluster, with no dual
sources of truth left behind.

3A. Source metadata and identity
- Replace `dp`, `s_path`, `s_u_data`, and ambiguous app-data uses with explicit
  BSG source metadata and typed caller-context slots.
- Separate database directory/path identity from arbitrary tool-private data.
- Convert GED draw, bot/brep/nmg/edit paths, QgModel, raytrace paths, selection,
  reports, and export commands.
- Delete legacy source fields or keep only import/export adapters until callers
  are gone.

3B. Payload, vlist, and generator callbacks
- Move `s_vlist`, `s_vlen`, `s_i_data`, `draw_data`, `s_update_callback`, and
  `s_free_callback` into typed BSG payloads.
- Create payload kinds for DB wireframes, evaluated shaded data, polygons,
  labels, axes, arrows, LoD/adaptive wireframes, and generic overlay geometry.
- Make payload lifecycle own allocation, vlist free-list interaction, update
  callbacks, stale marking, and teardown.
- Convert libbv polygon/vlist helpers into BSG payload builders or BU-level vlist
  utilities when they are not scene-specific.

3C. Transform, bounds, and render revisions
- Move `s_mat`, `s_size`, `s_csize`, `s_center`, `bmin`, `bmax`, `have_bbox`,
  `s_bbox_cached`, `s_displayobj`, `s_changed`, `current`, and `s_drawn_rev` to
  BSG transform/bounds/render-state containers.
- Replace ad hoc bbox recomputation with BSG actions that update dirty aggregate
  bounds from payload and child state.
- Ensure LoD, culling, snap, display-list invalidation, and reports all use the
  same BSG bounds API.

3D. Material, appearance, and draw policy
- Move `s_color`, `s_color_rev`, `s_soldash`, `s_arrow`, `s_os`, `s_local_os`,
  `s_inherit_settings`, and `s_old` into BSG material, appearance, draw-policy,
  and compatibility snapshot code.
- Make `bsg_settings` private or delete it once material/appearance APIs cover
  all callers.
- Eliminate remaining old-settings compatibility fields after render, export,
  report, and command paths read BSG material/appearance directly.

3E. Selection and highlighting
- Replace `bsg_iflag` compatibility and old illumination flows with a scene-level
  BSG selection model.
- Model selected nodes, highlighted nodes, sub-primitive selections, callbacks,
  and old GED/MGED illumination compatibility explicitly.
- Convert `gv_selected`, GED selection commands, MGED highlight paths, qged
  selection filters, and tests to the BSG selection container.

3F. View/edit context
- Replace `s_v` view-context semantics with explicit BSG view-scope or edit
  context objects.
- Keep render policy on the view/renderer, not on scene nodes.
- Convert polygon editing, QGED/libqtcad filters, MGED edit flows, and Tcl view
  object commands.

3G. Renderer/backend attachments
- Replace `s_backend` and `struct bv_obj_backend` with BSG renderer attachments
  owned by the scene/node/payload layer and keyed by backend tag plus revisions.
- Preserve backend cleanup and invalidation behavior, but route it through BSG
  lifecycle and payload dirty state.
- Convert libdm GL/swrast/qtgl paths and any future backend hooks.

Exit criteria:
- For each cluster, old fields are deleted or written only by a temporary adapter
  whose deletion is scheduled in Phase 7.
- No ordinary libdm/libged/qged/mged/libqtcad/libtclcad/librt/libanalyze code
  directly reads or writes legacy storage.

Phase 4 - Replace libbv Scene-Object APIs with BSG APIs
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Objective: remove libbv as the public scene-object surface.

Work:
- For every public libbv API naming `struct bv_scene_obj *`, choose one outcome:
  - move to libbsg with BSG types;
  - replace by a higher-level BSG scene/set/action API;
  - keep as a non-scene view/math/vlist utility with no scene-node handle;
  - delete.
- Replace `bv_view_obj_*` with BSG scene-set operations for overlays, polygons,
  labels, axes, lines, arrows, and local objects.
- Replace `bv_scene_obj_bound` and similar helpers with BSG bounds actions.
- Replace `bv_obj_stale`, backend invalidation helpers, and object reset helpers
  with BSG payload/revision/attachment invalidation.
- Move any reusable raw vlist helpers to BU/libbv utility APIs that do not know
  about scene nodes.
- Remove `struct bv_scene_obj` declarations from public libbv headers once all
  callers use BSG types.

Exit criteria:
- libbv no longer exports allocation, reset, lookup, object-table, traversal, or
  payload APIs for scene nodes.
- Public view/draw code reaches scene data through libbsg.

Phase 5 - Convert Consumers to the New BSG Containers
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Objective: make every BRL-CAD consumer operate on BSG concepts rather than old
handles.

Work by subsystem:

- libdm
  - Render via BSG traversal/actions and typed payloads.
  - Use BSG material/appearance/selection/bounds/render attachments only.
  - Remove fallback reads from old fields after BSG storage is authoritative.

- libged
  - Make GED draw state own a BSG scene, not old object tables.
  - Convert draw/erase/redraw, reports, plots, PNG/PS, selection, view-object,
    edit, raytrace, bot/brep/nmg, and database-state paths to BSG scene and
    node APIs.
  - Change public GED draw APIs that currently expose `bv_scene_obj` to BSG
    scene/node/set types.

- MGED
  - Convert highlight, edit, plotting, raytrace, titles, usepen, dozoom, and
    refresh paths to BSG scene APIs.
  - Remove direct dependencies on old GED data fields stored in scene objects.

- libtclcad / Archer
  - Convert Tcl view-object commands, arrows, axes, labels, polygons, mouse
    callbacks, and draw commands to BSG payload/material/appearance APIs.
  - Keep Tcl command compatibility at the command layer, not in scene storage.

- qged / libqtcad
  - Convert select/measure/poly/edit filters to BSG node, payload, selection,
    and scene-set APIs.
  - Ensure Qt-side models do not cache `bv_scene_obj *` as their semantic handle.

- librt / libanalyze
  - Replace any plotting/sketch/sample/NIRT scene-object callbacks with typed BSG
    payload builders or renderer-neutral output APIs.

- tests
  - Convert tests from old field assertions to BSG semantic assertions.
  - Keep a small compatibility test only while the adapter exists; delete it with
    the adapter.

Exit criteria:
- Consumer APIs and local variables use `bsg_node *`, `bsg_scene *`, scene-set
  handles, typed payload handles, or subsystem-specific semantic handles.
- Old `bv_scene_obj *` handles do not cross subsystem boundaries except through a
  temporary compatibility adapter scheduled for deletion.

Phase 6 - Remove the First-Member Compatibility Layout
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Objective: end pointer equivalence between `bsg_node *` and `bv_scene_obj *`.

Work:
- Remove `struct bsg_node bsg` from `struct bv_scene_obj` or delete the outer
  struct entirely if Phase 4 completed first.
- Delete casts that assume first-member layout.
- Delete or rewrite `bsg_compat_from_bv_scene_obj` and
  `bsg_compat_to_bv_scene_obj`; if a compatibility window is still required,
  implement it as an explicit map/adaptor object, not as pointer aliasing.
- Update all tests that intentionally checked pointer equivalence.
- Make libbsg internal headers independent of `bv/defines.h`.

Exit criteria:
- A BSG node pointer cannot be cast to a libbv scene object pointer.
- The build proves BSG storage stands alone.

Phase 7 - Delete `struct bv_scene_obj` and Migration Scaffolding
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Objective: remove the old data model from the tree.

Work:
- Delete the `struct bv_scene_obj` definition from `include/bv/defines.h`.
- Delete obsolete fields, compatibility snapshots, old settings mirrors,
  object-table owners, and free-list scene-object storage.
- Delete deprecated public APIs from libbv, GED, and tests.
- Delete `include/bsg/compat.h`, `src/libbsg/compat.c`, and compatibility tests
  once no production caller remains.
- Remove deprecation comments that only existed to guide the migration.
- Refresh documentation to describe BSG scene graph concepts as the normal draw
  stack model.

Exit criteria:
- `rg "struct bv_scene_obj|bv_scene_obj" brlcad/include brlcad/src` finds no
  active implementation references.
- `include/bv/defines.h` contains view/math/display utility data only, not scene
  graph node storage.

Phase 8 - Hardening, Parity, and Cleanup
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Objective: prove the new model is complete and stable.

Work:
- Run full Qt-enabled draw-stack builds and tests.
- Compare key behavior before/after the cutover:
  - DB draw/erase/redraw;
  - view objects and overlays;
  - mged/qged selection and highlighting;
  - shaded and wireframe rendering;
  - adaptive wireframe/LoD behavior;
  - hidden-line/transparency/color overrides;
  - axes/labels/arrows/polygons;
  - plots, reports, PNG/PS export, and NIRT visuals;
  - backend cache cleanup and invalidation;
  - multi-view editing and redraw behavior.
- Remove stale migration documentation or collapse it into release notes once the
  deletion is complete.

Exit criteria:
- No known behavior regressions remain in the draw stack.
- The BSG API is documented as the supported scene graph model.

Suggested Implementation Slices
-------------------------------
These are small enough to assign as separate follow-up tasks while still moving
toward the full data-model replacement.

1. Inventory/guardrail slice
   - Refresh the machine-generated reference inventory.
   - Add the approved compatibility whitelist.
   - Mark new `bv_scene_obj` references outside the whitelist as failures in the
     developer check.

2. BSG scene container slice
   - Add the scene owner and scene-set APIs.
   - Migrate draw roots and object-table membership to the new containers while
     keeping adapters for old callers.

3. Source identity slice
   - Move `dp`, `s_path`, and GED/app data into BSG source metadata/context.
   - Convert GED draw, QgModel, ray/display, and reports.

4. Payload/vlist slice
   - Make BSG payloads own vlist and custom data lifecycles.
   - Convert polygons, labels, arrows, axes, LoD, mged plot, Tcl adornments, and
     export/report consumers.

5. Bounds/transform slice
   - Move transform and bounds storage to BSG.
   - Replace old bbox helpers with BSG bounds actions and aggregate invalidation.

6. Material/appearance/settings slice
   - Delete old settings mirrors from ordinary consumers.
   - Make settings snapshots private or remove them.

7. Selection slice
   - Implement the BSG selection container and migrate old illumination/highlight
     flows.

8. Renderer attachment slice
   - Replace `s_backend` with BSG renderer resources.
   - Convert GL/swrast/qtgl cache allocation, invalidation, and cleanup.

9. libbv API deletion slice
   - Replace or delete every public libbv API that names `bv_scene_obj`.
   - Move reusable non-scene helpers to clean utility APIs.

10. Consumer boundary slice
    - Convert remaining GED/MGED/libtclcad/qged/libqtcad/librt/libanalyze
      signatures and tests to BSG handles.

11. First-member cast deletion slice
    - Remove pointer aliasing and compatibility conversions.
    - Build with standalone BSG node allocation only.

12. Final deletion slice
    - Delete the struct definition, compatibility files, deprecated APIs, and
      remaining migration-only tests/comments.

Decision Rules
--------------
- Prefer BSG-native containers over wrappers around `bv_scene_obj` fields.
- Do not add public APIs that expose `bv_scene_obj` layout or old ownership.
- Do not preserve a compatibility API after all callers can use BSG directly.
- Do not maintain long-lived dual sources of truth.  Each migration slice must
  name the authoritative owner and delete or isolate the mirror.
- Keep libbv utilities only when they are truly view/math/vlist utilities and no
  longer depend on scene-node storage.
- If an old field combines multiple responsibilities, split it into BSG concepts
  instead of reproducing the same ambiguity in a new struct.
