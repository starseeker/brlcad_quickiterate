BSG Modernization Plan and Work Log
===================================

Purpose
-------
Track API-maturation work needed to move libbsg from a legacy-shaped
scene/view container to a conceptually primary scene-graph API.


Baseline and Direction
----------------------
Use `bview2bsg` as the implementation baseline. It already:
- Removed libbv as a separate dependency by moving former libbv functionality
  under libbsg.
- Migrated major callers to `bsg/` headers and `bsg_*` names.
- Established a BSG draw-tree path for GED/MGED-style drawing.
- Added early scene-graph foundations:
  - node kinds (`GROUP`, `SHAPE`, `TRANSFORM`, `LOD`, `VIEW_SCOPE`)
  - sensors/fields (early form)
  - payload type bits
  - visitor traversal
  - draw-tree/overlay helpers
  - per-view scene-root plumbing

Key issue still to solve:
- libbsg is mechanically standalone, but conceptually still resembles a renamed
  legacy view/draw "god struct". Public API maturity is incomplete.


Branch Survey Summary
---------------------
- `qged`
  - Early transitional branch.
  - Useful as historical context; not a direct port target.

- `bview`
  - Important conceptual prototype.
  - Introduced `bv_node`, `bv_scene`, `bview_new`, and useful Inventor analog mapping.

- `bview2`
  - Intermediate step toward modernization.
  - Largely superseded by `bview2bsg`.

- `qged_obol`
  - Demonstrated end-to-end Obol rendering and camera/pick integration.
  - Valuable for lessons; bypassed too much of BRL-CAD's native drawing model.

- `qged_radical`
  - Most useful Obol experiment.
  - Key captures: CAD assembly identity model, path-to-instance mapping,
    matrix conversion rules, pick-detail mapping, hardware/swrast split.

- `radicalcmp`
  - Comparison notes reinforcing "mature BSG first, then Obol adapter".

- `drawstack`
  - Highly relevant draw-stack semantics work.
  - Shifted from legacy display-list mental model to BSG draw-tree semantics.

- `mdraw`
  - Production-oriented draw-stack modernization.
  - Useful for parity and behavior checks.

- `bsg2`
  - Most important conceptual mine for future work.
  - Contains missing maturity concepts (node/identity/material/appearance/
    payload/action/render/selection/camera/light/settings and tests).
  - Should be harvested conceptually, not merged wholesale.


Concepts Missing or Under-Realized in `bview2bsg`
--------------------------------------------------
High-value gaps:
- Generic node API (`bsg_node_*` lifecycle/structure/accessors)
- Stable identity model (node/part/instance/source IDs and paths)
- Material vs appearance split
- Typed payload model (vlist/wire/mesh/CSG/BRep/overlay/image/text/etc.)
- Action framework (bbox/search/collect/render/pick/export)
- First-class selection model (not `s_iflag`)
- Renderer-neutral camera snapshots and explicit light model
- Renderer contract where backends consume render actions, not raw node fields
- Sensor/field maturity (scene-owned sensors, revisions, dirty propagation)
- Public API cleanup removing legacy naming/assumptions


Current Repository Check (confirmed)
------------------------------------
- `include/bsg/defines.h` still exposes `struct bsg_node` directly with many
  legacy `BV_*` names and view/draw fields.
- `include/bsg/payload.h` currently provides payload flags/accessors, not typed
  payload objects.
- Existing public BSG headers include group/shape/transform/LOD/view-scope/
  sensor/field/visit support, but not:
  - `node.h`, `identity.h`, `material.h`, `appearance.h`, `action.h`,
    `render.h`, `selection.h`, `camera.h`, `light.h`, `settings.h`
- `brlcad/doc/notes/drawing_stack_modernization.txt` indicates draw-stack
  migration is largely complete and API maturation is the next priority.

User Modernization Gate — libbsg Consumers Before Obol
-------------------------------------------------------
Before adding Obol as a backend or removing compatibility APIs, modernize the
BRL-CAD drawing-code users of libbsg so they express their intent in BSG /
OpenInventor-style terms instead of renamed libbv/display-list terms.  The goal
is to make libged, MGED, qged/libqtcad, libtclcad, and libdm consume a clean
scene-graph API; this should expose which libbsg compatibility fields and helper
paths are genuinely obsolete.

Current user audit highlights:
- High raw-field-access users remain in `src/libged/draw.cpp`,
  `src/libged/bsg_ged_draw.c`, `src/libged/dbi_state.cpp`,
  `src/libged/draw/draw.c`, `src/libdm/view.c`, `src/libqtcad/QgMeasureFilter.cpp`,
  `src/mged/edsol.c`, and `src/mged/dodraw.c`.
- Common direct fields still encode scene concepts imperatively:
  `children`, `parent`, `s_u_data`, `s_i_data`, `s_vlist`, `s_color`, `s_os`,
  `s_v`, `dp`, `vlfree`, and `s_iflag`.
- Remaining user-facing compatibility seams include `ged_bv_data`,
  `bsg_view_obj_foreach_*`, `bsg_view_obj_set_illum`, `bsg_set_fsos`,
  `BV_*` object-kind names, `_bv_*` internals in libbsg, and the qtcad
  `set_draw_custom` callback path.
- MGED has already moved away from the old `display_list` store, but its edit,
  illuminate, replot, and raytrace helper code still talks in solid-list and
  raw-node terms (`ged_bv_data`, `LAST_SOLID`, `s_iflag`, `s_u_data`).
- qged/libqtcad view filters and plugins create useful BSG overlay objects, but
  refresh, selection highlighting, measurement/polygon overlays, and custom
  draw callbacks are not yet expressed as BSG render/selection/payload actions.


Phase 8A — Stabilize User-Facing BSG Accessors (COMPLETE)
---------------------------------------------------------
Purpose:
- Give libged/MGED/qged/libqtcad users complete vocabulary for node payload,
  identity, metadata, traversal, selection, and appearance operations before
  migrating the users.

Work items:
1) Fill accessor gaps needed by drawing-code users:
   - typed user/application data accessors replacing raw `s_u_data`;
   - typed internal payload-data accessors replacing raw `s_i_data`;
   - child traversal helpers replacing direct `children` / `parent` ptbl access;
   - vlist payload accessors replacing direct `s_vlist` / `vlfree` edits;
   - draw-source accessors for `dp`, `s_path`, `s_mat`, and full-path identity;
   - compatibility accessors for frame/drawn state until render actions own it.
2) Promote `ged_bv_data` into an explicitly named GED draw-shape data contract
   (for example `ged_draw_data` / `ged_shape_data`) with documented ownership,
   destructor, full-path, directory, and selection/edit responsibilities.
3) Add BSG draw-tree traversal/action helpers that expose semantic operations:
   find drawn groups by full path, visit drawn shapes, collect visible shapes,
   export vlists, replot/update a source path, and remove stale source nodes.
4) Add a public illumination/highlight facade over `bsg_selection` and node
   sensors so callers do not read or write `s_iflag` directly.
5) Add render-request extension points needed by users before Obol: overlay-last
   traversal, pre-render payload dispatch, view-filter hooks, and backend-neutral
   custom annotation rendering.

Exit criteria:
- [ ] libbsg exposes the accessors/actions needed to remove raw `bsg_node` field
      access from consumers.
- [ ] GED draw-shape data ownership is named and documented independently of
      the old libbv naming.
- [ ] Selection/illumination callers can use BSG selection APIs instead of
      `s_iflag`.
- [ ] qged/libqtcad filters have a render-action replacement for ad hoc custom
      draw callbacks.


Phase 8B — Modernize libged Draw Producers and Consumers (COMPLETE)
-------------------------------------------------------------------
Purpose:
- Make libged's drawing commands describe database drawing, overlays, selection,
  material, and export/report operations in BSG scene/action terms.

Work items:
1) Migrate `src/libged/bsg_ged_draw.c`, `src/libged/draw.cpp`, and
   `src/libged/draw/draw.c` from raw node mutation to Phase 8A accessors.

6) Make LoD and payload update paths use `bsg_payload_dispatch`,
   `bsg_render_request`, and typed LoD accessors rather than direct `s_i_data`,

- [ ] libged drawing code uses BSG node/material/appearance/payload/action APIs

- [ ] No libged command relies on direct `bsg_node` child table, color, vlist,

- [ ] Custom draw callbacks are deprecated and have a tested render-action
      replacement.
- [ ] Selection and edit overlays are represented as BSG scene/view-scope data,
      not renderer-specific callbacks.
- [ ] `ged_test_qged_swrast` and qtcad drawing tests cover the migrated paths.


Phase 8E — Modernize libdm Rendering Consumption (COMPLETE)
----------------------------------------------------------
Purpose:
- Make display managers consumers of BSG render requests rather than owners of
  scene traversal policy, preparing for Obol as a backend adapter.

Work items:
1) Move `dm_draw_objs` toward consuming `bsg_render_request` results: BSG owns
   traversal, visibility, overlay ordering, payload dispatch, and revision
   checks; libdm owns backend drawing of prepared payloads.
2) Replace direct libdm reads of mutable node fields (`s_color`, `s_os`,
   `s_vlist`, `s_backend`, `s_drawn_rev`, LoD snapshot fields) with material,
   appearance, payload, backend, and render-state accessors.
3) Formalize the backend cache contract currently represented by `s_backend` and
   ensure GL, swrast, qtgl, and future Obol backends use the same lifecycle
   hooks for create/invalidate/free.
4) Keep renderer-specific vlist/string primitives behind backend interfaces so
   qged, MGED, offscreen tests, and Obol do not depend on GL-era assumptions.
5) Add parity checks for native BSG rendering before any Obol adapter is enabled.

Exit criteria:
- [ ] libdm does not own scene traversal policy; it consumes BSG render requests
      and backend payloads.
- [ ] Backend cache lifecycle is explicit and tested.
- [ ] Native dm-qtgl/dm-swrast behavior remains unchanged before Obol is added.


Phase 8F — Remove or Isolate Compatibility Seams Exposed by User Migration (COMPLETE)
------------------------------------------------------------------------------------
Purpose:
- After users have migrated, identify libbsg pieces that were only preserved for
  old libbv/display-list users and either remove them or isolate them behind
  compatibility headers.

Work items:
1) Rename or split libbsg implementation files whose names encode the old layer
   (`bv_util.cpp`, `bv_lod.cpp`, `bv_vlist.c`) once user-facing includes and
   CMake dependencies are clean.
2) Replace public `BV_*` object-kind names in new code with `BSG_*` aliases;
   keep old names only in compatibility headers until Phase 10 removal.
3) Retire `bsg_set_fsos` from user code; free-node reuse should be internal to
   scene/view-set management.
4) Decide whether `bsg_scene_group` remains a meaningful concept or can collapse
   into named group nodes plus draw-intent metadata.
5) Audit `struct bsg_node` after caller migration and move fields that no longer
   need public exposure into `bsg_node_internal`.
6) Update documentation and tests to describe the stable OpenInventor-style API:
   nodes, groups, shapes, transforms, view scopes, payloads, material,
   appearance, actions, selection, camera, light, render request, and backend
   adapter.

Exit criteria:
- [ ] New drawing-code users no longer include libbv-style compatibility names.
- [ ] Public raw-node storage is reduced to what is intentionally stable.
- [ ] Obsolete compatibility paths are either removed or explicitly scheduled for
      Phase 10 removal.

Bottom Line
-----------
Use `bview2bsg` as code baseline and `bsg2` as conceptual roadmap. Prioritize
making libbsg a clean OpenInventor-like BRL-CAD scene API first; then layer
Obol as an adapter/backend on top of that mature API.
