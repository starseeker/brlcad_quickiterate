BSG Modernization Plan and Work Log
===================================

Purpose
-------
Track the API-maturation work needed to move libbsg from a legacy-shaped
scene/view container to a conceptually primary scene-graph API.


Current repository check (confirmed)
------------------------------------
- `include/bsg/defines.h` still exposes `struct bsg_node` directly with many
  legacy `BV_*` names and view/draw fields.
- `include/bsg/payload.h` currently provides payload type flags/accessors, not
  typed payload objects.
- Existing BSG public headers include group/shape/transform/LOD/view-scope/
  sensor/field/visit support, but not `node.h`, `identity.h`, `material.h`,
  `appearance.h`, `action.h`, `render.h`, `selection.h`, `camera.h`,
  `light.h`, or `settings.h`.
- `brlcad/doc/notes/drawing_stack_modernization.txt` shows draw-stack
  migration is largely complete; next work should focus on conceptual API
  maturation.


Modernization phases
--------------------
[x] Phase 0: Baseline audit
[ ] Phase 1: Introduce generic node API (`include/bsg/node.h`, `src/libbsg/node.c`)
[ ] Phase 2: Add identity and revision model (`include/bsg/identity.h`)
[ ] Phase 3: Split material and appearance (`include/bsg/material.h`, `include/bsg/appearance.h`)
[ ] Phase 4: Replace implicit geometry with typed payloads (`include/bsg/payload.h`)
[ ] Phase 5: Add BSG action framework (`include/bsg/action.h`)
[ ] Phase 6: Add first-class selection (`include/bsg/selection.h`)
[ ] Phase 7: Add camera and light snapshots (`include/bsg/camera.h`, `include/bsg/light.h`)
[ ] Phase 8: Move rendering behind BSG render action (`include/bsg/render.h`)
[ ] Phase 9: Add Obol as adapter/backend only
[ ] Phase 10: Final cleanup and deprecation removal

Phase 1 entry criteria (next)
-----------------------------
1) Add `brlcad/include/bsg/node.h`.
2) Add `brlcad/src/libbsg/node.c`.
3) Provide generic node lifecycle/kind/name/parent-child/visibility/transform/
   bounds/user-data/revision accessors without changing underlying
   `struct bsg_node` storage.
4) Migrate existing `node_group`, `node_shape`, `node_transform`, `lod`,
   and `view_scope` helpers to call the generic node API internally.
5) Add/extend focused `libbsg` tests for the new node API before broader
   caller migration.
